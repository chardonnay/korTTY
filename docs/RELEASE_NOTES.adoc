= Release Notes

== Unreleased

=== Terminal AI Agent

* *Inline activity feed*: Terminal-targeted AI Agent runs now show a Cloud-Code-style activity panel in the active terminal tab with message/action/status indicators, task timing, reported token usage, collapsible details, and auto-scrolling.
* *Panel controls*: The terminal agent panel now supports previous/next run navigation, rerun, close, collapse/expand, resize, font-size controls, an *Expand all* option, remembered panel size/font settings, and a red cancel button.
* *Activity export*: Completed terminal-agent runs can be exported for the current run or the full panel history as Markdown, plain text, YAML, XML, JSON, PDF, or Asciidoctor, including AI profile, model/LLM, run timestamps, runtimes, token usage, summaries, and detail text.
* *Terminal input lock*: While a terminal agent run is active, regular terminal input is blocked for that tab. *Esc*, *Ctrl+C*, and the panel cancel button abort the run.
* *Current-directory aware runs*: Terminal shortcut commands now capture the active remote directory with `pwd -P` and pass it to the agent, so relative commands and generated files run in the directory where the user started the task.
* *Sudo prompt handling*: When sudo access is required, the agent panel can ask for a masked sudo password and reuse it for the current session. Unsupported interactive sudo modes are rejected instead of hanging the terminal.
* *Terminal final output*: Final terminal-agent answers are written into the terminal transcript, while the activity panel remains available for detailed execution state.

=== AI Settings and Theme Support

* *Agent command matching*: *Settings → AI* can now match the configured terminal agent command name case-insensitively.
* *Default-profile terminal runs*: *Settings → AI* can disable the terminal-agent setup dialog before each shortcut run; in that mode KorTTY uses the configured default AI profile.
* *Theme colors*: Themes can define Terminal AI agent panel colors separately from the normal terminal palette, and existing themes derive sensible defaults.

=== Terminal Agent Fixes

* Fixed terminal shortcut handling so `agent`, `agent-ask`, and `agent-plan` are intercepted by KorTTY instead of reaching the remote shell as unknown commands.
* Fixed duplicate prompt artifacts and startup alias leakage in shell history after reconnecting to an SSH session.
* Fixed incomplete or status-bar-only terminal-agent output by routing the final answer back into the terminal area.
* Fixed activity-panel usability issues around auto-scroll, closing, resizing, collapsed-state status, and visible busy indication.

== v2.0.0

*Release date:* March 2026

=== Highlights

* *OpenAI-compatible AI assistant in the terminal*: Selected terminal text can now be sent directly to *AI → Summarize*, *AI → Solve Problem*, or *AI → Ask* without leaving the session view.
* *Profile-based AI setup*: *Settings → AI* now supports multiple named profiles with separate endpoint, optional model, optional encrypted API key, selection limit, tokenizer strategy, token budget, default profile selection, and code-text language defaults.
* *AI result tabs as working surfaces*: AI responses open in temporary tabs with follow-up prompts, profile/language switching, retry/cancel, saving/renaming, OS sharing, export to PDF/Markdown/plain text, markdown-table copy helpers, snippet export from generated code blocks, and persistent AI font size.
* *Saved AI chats and AI Manager*: Conversations can now be saved as named chats and reopened, renamed, refreshed, or deleted from *Tools → AI Manager*, which also provides a dedicated profile management tab.
* *AI Agent and Planning*: Terminal-focused agent and planning workflows can be started from *Tools* or from the terminal context menu, with dedicated transcript tabs and configurable execution targets.
* *AI-assisted snippet editing*: The snippet editor now supports AI-generated metadata, snippet-language suggestions, selection-based spelling correction and translation, technical descriptions, and alternative code solutions.

=== AI Workflow, Safety, and Quotas

* *Preview before sending*: The confirmation dialog shows the selected text before transmission, lets you edit it, supports search/replace, and displays the estimated request token usage.
* *Quota visibility*: Per-profile token limits, warning thresholds, and reset cycles are shown in Settings and projected in the confirmation dialog before a request is sent.
* *Automatic usage accounting*: Prompt and response token counts are persisted after successful AI calls so usage warnings stay accurate across sessions.
* *Safer output handling*: Visible `<think> ... </think>` blocks are stripped from rendered responses, and AI result tabs are not restored as part of saved project/session state.
* *Profile fallback for saved chats*: If the original AI profile of a saved chat no longer exists, KorTTY prompts for a replacement profile before follow-up requests continue.
* *Per-chat language control*: AI chat responses default to the GUI language and can be changed per chat for future follow-up requests.
* *Terminal shortcut trio*: Configurable local commands such as `agent`, `agent-ask`, and `agent-plan` are intercepted at the shell prompt when the prompt hook is enabled.

=== AI Agent and Planning

* *Agent execution target*: Agent tasks can target the active terminal window or open in a dedicated chat tab.
* *Planning flow*: AI Planning collects clarifying answers, proposes options, and can start the accepted plan.
* *Operational prompts*: Agent workflows can surface command approvals and sudo password requests when required by the generated plan.

=== Snippet Manager and Editor

* *AI metadata generation*: The snippet editor can derive snippet name, description, and language from the current code content.
* *Editor-side AI text tools*: Selected comments and user-facing text can be corrected or translated without rewriting the surrounding logic.
* *Technical descriptions*: A selected code region or a whole snippet can be summarized in a dedicated dialog and inserted back as comments.
* *Alternative solutions dialog*: Selected code can be replaced by one of several AI-generated alternative implementations, with configurable result count, reload, zoom, and remembered dialog geometry.
* *Persistent editor controls*: Snippet editor line numbers, word wrap, and AI-driven change toggling are now part of the day-to-day editing workflow.

=== Terminal and UX

* *Configurable close confirmation for active terminals*: A new global Terminal setting controls whether closing a window with active terminal sessions requires confirmation. The default remains safe: ask before closing.
* *Status bar improvements*: Terminal status information now surfaces host/IP and the active protocol more clearly.
* *Mosh background fix*: Mosh tabs no longer show a false "interrupted" state simply because the tab is not focused.
* *Menu bar visibility preference*: The in-window menu bar can now be shown or hidden via *View* or *Settings → Window*, and restored with *Cmd/Ctrl+Shift+L* if hidden.

=== Documentation and Release Tooling

* *v2.0.0 documentation refresh*: README, User Guide, and Release Notes were updated for the AI workflows, packaging examples, and current version numbers.
* *PlantUML documentation diagrams*: The docs now use PlantUML sources for rendered diagram PNGs, including the dedicated AI API integration diagram, and the release pipeline renders them automatically.
* *Version alignment*: The application metadata, Gradle build, README, and documentation now consistently report *2.0.0*.
* *Node-24-ready release workflow actions*: The GitHub release workflow now uses current action majors for checkout, Node setup, and artifact upload so it stays compatible with the GitHub Actions Node 24 transition.

== v1.9.0

*Release date:* March 2026

=== Highlights

* *Token-free SithTermFX builds*: KorTTY now builds against *SithTermFX 1.1.0* from source, both locally and in CI. Building the project no longer depends on GitHub Packages credentials.
* *Bundled mosh4j runtime*: Release packages now ship with the required *mosh4j* JARs, so Mosh support works without a first-run download.
* *Verified multi-platform release pipeline*: The GitHub Actions release workflow was updated and validated for macOS Apple Silicon, Windows x86_64, Windows ARM64, Linux x86_64, Linux aarch64, Arch Linux, and generic Java distributions.

=== Build and Packaging

* *Local build requirements clarified*: The project now documents the required local toolchain more clearly, including Git and Maven for the embedded SithTermFX build step.
* *Signed release artifacts*: Linux and Java release artifacts continue to ship with detached signatures and the public signing key.
* *Release workflow improvements*: Manual release builds started via `workflow_dispatch` can now upload artifacts to an existing tagged GitHub Release.

=== Versioning

* *Application version updated*: The application, Gradle build, README, and docs now consistently report *1.9.0*.

== v1.8.1

*Release date:* March 2026

=== Themes and UI

* *More built-in theme profiles*: Added a broader set of built-in color profiles, including IntelliJ-inspired themes.
* *Live theme preview in Settings*: Selecting a theme under *Settings → Themes* now shows an immediate preview.
* *Immediate apply on save*: Saved global theme changes are applied without restart to the main window and to terminals that use global/default settings.
* *Theme font behavior option*: Themes apply colors by default; font family/size are only applied when explicitly enabled in theme options.
* *Version consistency*: The application version shown in the About dialog and runtime metadata is now aligned with `v1.8.1`.

=== SFTP Manager

* *Archive exclude patterns*: Local and remote archive dialogs now support exclude patterns (one pattern per line) for files/directories.
* *Windows path/glob fix*: `matchesExclude()` path handling was hardened so exclude matching works correctly across platforms.

=== Translation, Packaging, and Startup

* *Target language list in packaged binaries*: Release binaries now include `jdk.localedata` in runtime images so *Settings → Translation → Target language* keeps broad language coverage.
* *Locale list fallback logic*: Target language population now uses ISO language codes plus available JVM locales for resilient behavior in reduced runtime images.
* *macOS packaged app startup fix*: The packaged runtime now keeps the required Java modules (including `java.xml`) so the shipped macOS app starts correctly.

=== Release Build Matrix and Signing

* *macOS signing*: GitHub Actions signs both the macOS `.app` bundle and the `.dmg` installer with Apple Developer ID.
* *Windows ARM64 artifacts*: GitHub Actions publishes Windows ARM64 artifacts as `korTTY-Windows-<version>-arm64.msi` and `korTTY-Windows-<version>-arm64.zip` (ZIP contains single `korTTY.exe`).
* *Linux artifact signing*: Linux `tar.gz`, `zip`, `deb`, `rpm`, and Arch `pkg.tar.zst` artifacts are GPG-signed in CI and published with detached `.sig` files plus the public key.
* *Signed Java distributions*: Release builds also publish GPG-signed Java artifacts (`.jar`, `.zip`, `.tar`) for the generic JVM distribution.
* *CI Java toolchain note*: The `windows-11-arm` release job uses Java 21 for compatibility; other release jobs continue with Java 25.
