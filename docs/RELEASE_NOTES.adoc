= Release Notes

== Unreleased

=== Snippet Editor AI, Diagrams, and Profiles

* *Cursor-aware AI completion*: The snippet editor can request a completion at the current caret location. Suggestions are shown as ghost text and are inserted only when the user clicks them.
* *Session-local auto completion*: Auto AI completion can be enabled per editor session. It is off by default and requests suggestions after the user pauses at a caret location.
* *AI review and rewrite flows*: Error review, improvement themes, custom instructions, alternative solutions, and security fixes use structured AI responses and before/after previews before replacing code.
* *Selected-code scope*: Alternative solutions and improvement actions operate on the selected code region. When no selection is available for alternative solutions, the request uses the whole snippet.
* *Security check with selected fixes*: Security review produces selectable findings; only selected findings are sent back for fix generation and preview.
* *Snippet AI privacy boundary*: Snippet AI uses the default AI profile, token accounting, cancellation, and enabled Chat/Functions/Both AI Skills, but does not expose internet tools.
* *Technical description dialog*: Descriptions can use current-language comment syntax with configurable line width, preserve a space after the comment marker, and split sentences after a full stop onto the next line.
* *Local PlantUML diagrams*: Snippet logical-structure diagrams are stored with the snippet, marked stale by content hash, regenerated with saved instructions, rendered locally only, and exportable/copyable as image output.
* *Editor profiles*: The snippet editor has ten built-in IntelliJ-inspired color/cursor profiles plus user-defined profiles saved in global settings.
* *Review windows*: AI review/diff/alternative dialogs use larger readable code text, support zoom via buttons and Ctrl/Cmd +/- shortcuts, and expose copy-to-clipboard where applicable.

=== Snippet Export and Code Formatting

* *Plain text script export*: Snippets can be exported as one script file per snippet, using the name and extension from the Snippet Manager *Name* column.
* *ZIP script export*: Selected or all snippets can be exported as a ZIP archive with one script file per snippet. The script file extension can be kept from each snippet name or forced for every file in the ZIP.
* *ZIP encryption options*: Script ZIP exports support no encryption, AES password-protected ZIP, or GPG encryption using a stored KorTTY GPG key.
* *Shared formatter service*: Snippet Editor and File Editor formatting now use the same `CodeFormatterService` with built-in, bundled, optional external fallback, and unavailable provider states.
* *Bundled formatter manifest*: Formatter versions and sources are pinned in `src/main/resources/formatters/formatter-manifest.properties`; packaged builds can include shfmt, Prettier, sql-formatter, Perl::Tidy, and google-java-format support.

=== JobScheduler Background Automation

* *New Tools menu entry*: *Tools > JobScheduler...* opens the scheduler directly after Snippet Manager and before the AI tools.
* *Background execution*: Jobs run while the KorTTY process is open and do not require a terminal tab to stay open.
* *Saved SSH TCP targets*: Jobs can target saved servers, groups, or both through the Connection Manager selection flow. Mosh targets are blocked as unsupported and journaled.
* *Schedule model*: Jobs support selected weekdays, validated fixed times, optional active date ranges, start/end time windows, and intervals inside the active window. Schedule times use the local system time zone.
* *Persistent state*: Jobs, schedules, actions, pinned host keys, encrypted sudo secrets, journal entries, and the JobScheduler dialog geometry are persisted in `~/.kortty/job-scheduler.xml` and `global-settings.xml`.

=== JobScheduler Actions and Security

* *Command, snippet, and AI-agent jobs*: `COMMAND` jobs run non-interactive remote commands. `SNIPPET_SCRIPT` jobs run selected SnippetManager scripts with additional per-job parameters. `AI_AGENT` jobs use the shared AI-agent safety logic and require explicit job-level auto-approval before unattended command execution.
* *SFTP jobs*: Scheduler actions cover upload, download, sync, delete, rename, mkdir, chmod, chown, remote copy, and remote archive creation.
* *Archive jobs*: Scheduler archives support ZIP, password-protected ZIP, TAR, and TAR.BZ2, with optional download after successful creation.
* *Sudo handling*: Server-specific sudo passwords are used before group sudo passwords. Stored sudo secrets are encrypted with the master password.
* *SFTP sudo staging*: SFTP paths that need elevated rights can use temporary staging plus sudo-assisted `mv`, `cp`, `tar`, `chmod`, and `chown`, with cleanup failures journaled.
* *Host-key safety*: Host-key pinning is required by default for unattended SSH/SFTP/Rsync execution. A job can explicitly disable host-key verification, and that unsafe mode remains scoped to that job.
* *Journal modes*: `LIMITED_REDACTED` stores bounded stdout/stderr excerpts with redaction. `FULL` stores full output/transcripts while still redacting KorTTY-managed secrets before persistence.
* *Locked master-password behavior*: Jobs that need encrypted SSH, sudo, API, or archive secrets are blocked and journaled when the master password is locked.

=== JobScheduler Rsync Integration

* *New `RSYNC_SYNC` action*: Schedule upload or download directory synchronization between the local filesystem and saved SSH TCP connections.
* *Multiple sources*: One job can synchronize multiple source directories under the configured target root.
* *Safe defaults*: Rsync uses `-a --itemize-changes`; `--delete` is optional and disabled by default.
* *Group downloads*: Downloads from multiple targets write into separate per-target subdirectories below the local target root to avoid overwrites.
* *External tools*: KorTTY uses `rsync` from `PATH` or the optional *Settings > SFTP > JobScheduler Rsync* binary path. The local `ssh` command must be available in `PATH`.
* *Pinned known_hosts*: Rsync jobs create a temporary owner-only `known_hosts` file from the pinned host key. Existing pins without OpenSSH public-key material must be confirmed again before Rsync can run.
* *Askpass support*: Password and key-passphrase authentication use temporary owner-only `SSH_ASKPASS` helper files. Passwords, passphrases, helper paths, and secret-file paths are redacted before journaling.
* *Rsync sudo scope*: `Use sudo` for Rsync maps to passwordless remote `sudo -n rsync`; stored sudo passwords are not used by the current Rsync integration.

=== JobScheduler UI and Shutdown UX

* *Job editor*: Working directory, local paths, remote paths, archive paths, Rsync sources, and Rsync target roots have browse helpers where applicable.
* *Remote selectors*: Owner and group selectors can query the target and show available remote values.
* *Validated time controls*: Window start, window end, and fixed times use validated time dropdowns instead of free-text entry.
* *Weekday bulk toggle*: The weekdays row has a control to select or clear all weekdays.
* *Menu-bar status*: When enabled and at least one scheduler entry exists, the menu bar shows running job state or the next run countdown after *Help*. Opening it lists up to five queued jobs with start time and live countdown.
* *Cancellation*: Running jobs can be cancelled from the JobScheduler status menu or right-click status menu; cancellation requests are journaled.
* *Journal controls*: Journal columns are sortable, selected journal entries can be deleted, and journal timestamps are displayed in the local KorTTY/system time zone.
* *Journal retention*: Entries older than 14 days are deleted automatically by default unless the user changes the retention value; `0` keeps entries indefinitely.
* *Journal detail pane*: The protocol/detail output area can be resized vertically, KorTTY remembers the divider position, and selected detail text can be copied from the right-click menu.
* *Quit drain*: When KorTTY is asked to quit while scheduler jobs are running, it warns the user. If confirmed, KorTTY blocks new starts, journals the shutdown wait, waits for running jobs to finish or cancel, and exits afterward.

=== AI Internet Access

* *Per-profile internet mode*: AI profiles can now keep internet access disabled or opt into one of the supported modes: `KorTTY Tavily Tool`, `LM Studio Tavily MCP`, `Bright Data Web MCP`, `Brave Search MCP`, `SearXNG MCP`, or `LM Studio Toolpack`.
* *Direct Tavily tool support*: The KorTTY Tavily mode uses OpenAI-compatible chat-completions tool calls and executes `web_search` through Tavily with hard connect/request timeouts.
* *LM Studio MCP modes*: LM Studio MCP integrations use the native `/api/v1/chat` payload with integrations instead of assuming MCP tools on `/v1/chat/completions`.
* *Structured web failures*: Web timeouts, HTTP errors, authentication failures, empty results, and tool-round limits are returned as structured tool errors. Models are instructed to report those failures and not invent web facts.
* *Agent web gating*: Terminal-agent JSON planning exposes web tools only for tasks that clearly need current or external information. Local file/script review tasks continue through SSH command inspection.

=== AI Skills

* *AI Skills settings tab*: *Global Settings > AI Skills* can create, edit, enable/disable, delete, import, export, and sort local skills.
* *Skill targets*: Each skill can target AI Chat/functions, AI Agent, or both.
* *Automatic skill matching*: Active skills can be filtered automatically by request, description, tags, and headings. Users can disable automatic matching to send all active target-compatible skills.
* *Markdown import/export*: Skills export as Markdown with KorTTY frontmatter. Plain Markdown and Claude/Codex-style `SKILL.md` files can be imported disabled by default for review.
* *Agent visibility*: Terminal-agent activity logs show which AI Skills were used for a run.

=== Terminal AI Agent Fixes

* *Current directory reliability*: Agent runs now carry the active terminal directory through prompt parsing, shell-hook `$PWD`, probe fallback, repair prompts, and command execution.
* *Shortcut and paste handling*: Pasted or shortcut-inserted text in `agent ...` commands is read from the visible terminal line when it is more complete than the key-event buffer.
* *Prompt wrapping*: Wrapped terminal prompt lines are searched from the visible screen so the agent can recover both the task text and current directory.
* *Web/local separation*: Local file review prompts no longer get derailed into web-search tool rounds when an internet-enabled profile is active.

=== Terminal Effect Plugins

* *New plugin menu*: *Plugins > Terminal Effects* opens terminal-effect plugin management between *Tools* and *View* in the main menu bar.
* *Plugin management dialog*: Loaded terminal-effect plugins are shown with active state, name, and description. Users can enable, disable, reload, import `.jar` plugins, and export plugins that have a source JAR.
* *ServiceLoader SPI*: Terminal effects use `de.kortty.plugin.terminaleffects.TerminalEffectPlugin` and `TerminalEffectSession` for appearance changes, JavaFX overlays, and optional SithTermFX `TtyConnector` wrapping.
* *Per-connection selection*: Quick Connect and Connection Manager can store the selected terminal-effect plugin and animation speed on a connection.
* *Animation speed controls*: Terminal-effect speed supports a `1x` to `10x` slider plus a numeric field up to `99x`.
* *Exportable MOTHER plugin*: MOTHER has been moved into a bundled plugin JAR (`kortty-terminal-effect-mother.jar`) and can be exported from the plugin manager.
* *MOTHER output animation*: MOTHER paces visible terminal output, keeps terminal control sequences immediate, adds CRT overlay styling, and briefly flashes the current output line before fading it back to normal brightness.

=== Documentation

* README, User Guide, and Release Notes now describe JobScheduler background automation, Rsync jobs, scheduler safety behavior, AI internet modes, AI Skills, Terminal AI Agent usage, terminal-effect plugins, snippet-editor AI workflows, local formatter behavior, snippet export formats, failure handling, and manual validation paths in more detail.
* Added `docs/TERMINAL_EFFECT_PLUGINS.adoc` with the terminal-effect plugin SPI, ServiceLoader packaging, MOTHER reference build, import/export behavior, lifecycle rules, connector-wrapper guidance, overlay guidance, security considerations, and validation checklist.
* Updated and re-rendered the architecture, module overview, AI API integration, snippet editor workflow, connection flow, session lifecycle, and terminal-effect plugin lifecycle diagrams.

== v2.1.0

=== Terminal AI Agent

* *Split-local activity panels*: Terminal-targeted AI Agent runs now use the activity panel attached to the terminal split where the run was started. Different splits can run their own agent tasks in parallel.
* *Inline activity feed*: Terminal-targeted AI Agent runs show message/action markers, task timing, reported token usage, collapsible details, and auto-scrolling.
* *Panel controls*: The terminal agent panel supports previous/next run navigation, rerun, close, collapse/expand, resize, font-size controls, a cancel button, an *Expand all* option, a *Keep collapsed* option, and remembered panel size/font settings.
* *Persistent panel options*: *Expand all* and *Keep collapsed* are saved globally across restarts. *Remember size* continues to control saved panel height and activity font size.
* *Semantic activity markers*: Activity rows use `↑`, `↓`, `?`, `!`, `x`, and `i` markers. Red styling is reserved for error and failed states.
* *Prompt layout*: Long user prompts are shown in a two-line scrollable field so token usage, panel controls, and close/collapse actions remain visible.
* *Activity row actions*: Each activity row can be copied to the clipboard or opened in the Snippet Editor. Snippet handoff removes leading activity quote markers (`>`) from copied row text.
* *Activity export*: Completed terminal-agent runs can be exported for the current run or the full panel history as Markdown, plain text, YAML, XML, JSON, PDF, or Asciidoctor, including AI profile, model/LLM, reasoning status, run timestamps, runtimes, token usage, summaries, and detail text. Leading activity quote markers (`>`) are removed automatically, and export progress is reported in the panel status instead of a success dialog.
* *Terminal input lock*: While a terminal agent run is active, regular terminal input is blocked for that split. *Esc*, *Ctrl+C*, and the panel cancel button abort that run.
* *Current-directory aware runs*: Terminal shortcut commands now use KorTTY's tracked active remote directory, so relative commands and generated files run in the directory where the user started the task.
* *Sudo prompt handling*: When sudo access is required, the agent panel can ask for a masked sudo password, submit it with *Enter* or the button, allow up to three wrong-password retries, and reuse it for the current session. Unsupported interactive sudo modes are rejected instead of hanging the terminal.
* *Terminal final output*: Final terminal-agent answers are written into the terminal transcript, while the activity panel remains available for detailed execution state.

=== AI Planning

* *`agent -plan` shortcut*: In addition to `agent-plan <task>`, KorTTY now supports `agent -plan <task>` with the configured agent command name and profile options.
* *Interactive planner tab*: Planning mode asks clarifying questions, accepts option clicks or custom answers, can refine the plan, and creates a final plan report before execution is enabled.
* *Planning implementation gate*: The agent switches from planning to execution only after the user accepts the final plan with *Implement*.
* *Sudo preflight after acceptance*: If the current SSH session needs sudo with a password, planning performs the sudo password check immediately after plan acceptance and before execution starts.
* *Planning font size*: The planning tab supports *A-*, *A+*, and Ctrl/Cmd plus `+` / `-`; the selected planning font size is persisted across restarts.

=== Snippet Manager

* *One-liner script arguments*: *Send to Terminal with Parameters* prompts for missing `${...}` snippet variables and optional script arguments, with one argument per line.
* *Safe argument passing*: Bash/shell, Python, Perl, and Ruby one-liners pass arguments individually with shell quoting instead of appending raw shell text.
* *Unsupported language guard*: Snippets in languages without a safe one-liner argument path keep the existing no-argument behavior, but show an information message and send nothing when script arguments are entered.
* *Cleaner terminal output*: Embedded/base64 one-liners show the `KorTTY snippet: ...` label without echoing the full generated command into the terminal transcript.

=== SSH Connection Reliability

* *Keep-alive implementation*: SSH Keep-Alive now sends `SSH_MSG_IGNORE` heartbeats at the configured interval and enables TCP socket keepalive while the option is active.

=== AI Settings and Theme Support

* *Agent command matching*: *Settings → AI* can now match the configured terminal agent command name case-insensitively.
* *Default-profile terminal runs*: *Settings → AI* can disable the terminal-agent setup dialog before each shortcut run; in that mode KorTTY uses the configured default AI profile.
* *Reasoning effort per profile*: AI profiles can optionally enable a supported reasoning effort. KorTTY exposes the available choices from the configured API/model combination and includes the selected reasoning state in terminal-agent exports.
* *Editable themes*: *Settings → Themes* can edit existing themes, save changes, create new themes, and keep dedicated Terminal AI agent panel colors with the theme.
* *Theme colors*: Themes can define Terminal AI agent panel colors separately from the normal terminal palette, and existing themes derive sensible defaults.

=== Startup and Security UX

* *Master password dialog layout*: The startup master-password dialog is wider, uses a light gray background, and shows the KorTTY logo/version beside the password fields instead of behind them.

=== Terminal Agent Fixes

* Fixed terminal shortcut handling so `agent`, `agent-ask`, `agent-plan`, and `agent -plan` are intercepted by KorTTY instead of reaching the remote shell as unknown commands.
* Fixed terminal-agent bootstrap text appearing in the terminal after SSH login.
* Fixed duplicate prompt artifacts after connecting or reconnecting to an SSH session.
* Fixed incomplete or status-bar-only terminal-agent output by routing the final answer back into the terminal area.
* Fixed activity-panel usability issues around auto-scroll, closing, resizing, collapsed-state status, and visible busy indication.
* Fixed planning-tab contrast, font scaling, button placement, final-plan enablement, and rejected too-many-commands errors when starting an accepted plan.

== v2.0.0

*Release date:* March 2026

=== Highlights

* *OpenAI-compatible AI assistant in the terminal*: Selected terminal text can now be sent directly to *AI → Summarize*, *AI → Solve Problem*, or *AI → Ask* without leaving the session view.
* *Profile-based AI setup*: *Settings → AI* now supports multiple named profiles with separate endpoint, optional model, optional encrypted API key, selection limit, tokenizer strategy, token budget, default profile selection, and code-text language defaults.
* *AI result tabs as working surfaces*: AI responses open in temporary tabs with follow-up prompts, profile/language switching, retry/cancel, saving/renaming, OS sharing, export to PDF/Markdown/plain text, markdown-table copy helpers, snippet export from generated code blocks, and persistent AI font size.
* *Saved AI chats and AI Manager*: Conversations can now be saved as named chats and reopened, renamed, refreshed, or deleted from *Tools → AI Manager*, which also provides a dedicated profile management tab.
* *AI Agent and Planning*: Terminal-focused agent and planning workflows can be started from *Tools* or from the terminal context menu, with dedicated transcript tabs and configurable execution targets.
* *AI-assisted snippet editing*: The snippet editor now supports AI-generated metadata, snippet-language suggestions, selection-based spelling correction and translation, technical descriptions, and alternative code solutions.

=== AI Workflow, Safety, and Quotas

* *Preview before sending*: The confirmation dialog shows the selected text before transmission, lets you edit it, supports search/replace, and displays the estimated request token usage.
* *Quota visibility*: Per-profile token limits, warning thresholds, and reset cycles are shown in Settings and projected in the confirmation dialog before a request is sent.
* *Automatic usage accounting*: Prompt and response token counts are persisted after successful AI calls so usage warnings stay accurate across sessions.
* *Safer output handling*: Visible `<think> ... </think>` blocks are stripped from rendered responses, and AI result tabs are not restored as part of saved project/session state.
* *Profile fallback for saved chats*: If the original AI profile of a saved chat no longer exists, KorTTY prompts for a replacement profile before follow-up requests continue.
* *Per-chat language control*: AI chat responses default to the GUI language and can be changed per chat for future follow-up requests.
* *Terminal shortcut trio*: Configurable local commands such as `agent`, `agent-ask`, and `agent-plan` are intercepted at the shell prompt when the prompt hook is enabled.

=== AI Agent and Planning

* *Agent execution target*: Agent tasks can target the active terminal window or open in a dedicated chat tab.
* *Planning flow*: AI Planning collects clarifying answers, proposes options, and can start the accepted plan.
* *Operational prompts*: Agent workflows can surface command approvals and sudo password requests when required by the generated plan.

=== Snippet Manager and Editor

* *AI metadata generation*: The snippet editor can derive snippet name, description, and language from the current code content.
* *Editor-side AI text tools*: Selected comments and user-facing text can be corrected or translated without rewriting the surrounding logic.
* *Technical descriptions*: A selected code region or a whole snippet can be summarized in a dedicated dialog and inserted back as comments.
* *Alternative solutions dialog*: Selected code can be replaced by one of several AI-generated alternative implementations, with configurable result count, reload, zoom, and remembered dialog geometry.
* *Persistent editor controls*: Snippet editor line numbers, word wrap, and AI-driven change toggling are now part of the day-to-day editing workflow.

=== Terminal and UX

* *Configurable close confirmation for active terminals*: A new global Terminal setting controls whether closing a window with active terminal sessions requires confirmation. The default remains safe: ask before closing.
* *Status bar improvements*: Terminal status information now surfaces host/IP and the active protocol more clearly.
* *Mosh background fix*: Mosh tabs no longer show a false "interrupted" state simply because the tab is not focused.
* *Menu bar visibility preference*: The in-window menu bar can now be shown or hidden via *View* or *Settings → Window*, and restored with *Cmd/Ctrl+Shift+L* if hidden.

=== Documentation and Release Tooling

* *v2.0.0 documentation refresh*: README, User Guide, and Release Notes were updated for the AI workflows, packaging examples, and current version numbers.
* *PlantUML documentation diagrams*: The docs now use PlantUML sources for rendered diagram PNGs, including the dedicated AI API integration diagram, and the release pipeline renders them automatically.
* *Version alignment*: The application metadata, Gradle build, README, and documentation now consistently report *2.0.0*.
* *Node-24-ready release workflow actions*: The GitHub release workflow now uses current action majors for checkout, Node setup, and artifact upload so it stays compatible with the GitHub Actions Node 24 transition.

== v1.8.1

*Release date:* March 2026

=== Themes and UI

* *More built-in theme profiles*: Added a broader set of built-in color profiles, including IntelliJ-inspired themes.
* *Live theme preview in Settings*: Selecting a theme under *Settings → Themes* now shows an immediate preview.
* *Immediate apply on save*: Saved global theme changes are applied without restart to the main window and to terminals that use global/default settings.
* *Theme font behavior option*: Themes apply colors by default; font family/size are only applied when explicitly enabled in theme options.
* *Version consistency*: The application version shown in the About dialog and runtime metadata is now aligned with `v1.8.1`.

=== SFTP Manager

* *Archive exclude patterns*: Local and remote archive dialogs now support exclude patterns (one pattern per line) for files/directories.
* *Windows path/glob fix*: `matchesExclude()` path handling was hardened so exclude matching works correctly across platforms.

=== Translation, Packaging, and Startup

* *Target language list in packaged binaries*: Release binaries now include `jdk.localedata` in runtime images so *Settings → Translation → Target language* keeps broad language coverage.
* *Locale list fallback logic*: Target language population now uses ISO language codes plus available JVM locales for resilient behavior in reduced runtime images.
* *macOS packaged app startup fix*: The packaged runtime now keeps the required Java modules (including `java.xml`) so the shipped macOS app starts correctly.

=== Release Build Matrix and Signing

* *macOS signing*: GitHub Actions signs both the macOS `.app` bundle and the `.dmg` installer with Apple Developer ID.
* *Windows ARM64 artifacts*: GitHub Actions publishes Windows ARM64 artifacts as `korTTY-Windows-<version>-arm64.msi` and `korTTY-Windows-<version>-arm64.zip` (ZIP contains single `korTTY.exe`).
* *Linux artifact signing*: Linux `tar.gz`, `zip`, `deb`, `rpm`, and Arch `pkg.tar.zst` artifacts are GPG-signed in CI and published with detached `.sig` files plus the public key.
* *Signed Java distributions*: Release builds also publish GPG-signed Java artifacts (`.jar`, `.zip`, `.tar`) for the generic JVM distribution.
* *CI Java toolchain note*: The `windows-11-arm` release job uses Java 21 for compatibility; other release jobs continue with Java 25.
