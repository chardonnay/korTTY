Release notes¶

What changed in the current release. The version this guide was built for is shown in the footer.

v2.18.0¶

Terminal¶

  • Coding agents — korTTY recognises Claude Code, Codex and Gemini CLI in local shell tabs and classifies each pane as working, blocked on a question, done or idle, and now shows it everywhere: a glyph in the tab title, chips, accent bars, rollups and pane rows in the dashboard (which expands to a waiting agent and offers Send Enter / Esc / Interrupt in the context menu), a dockable Coding Agents panel (View → Coding Agents, Ctrl+Alt+G) listing every agent of every window with one-click answers (y, n, Enter, Esc, ↑, ↓, Ctrl+C), Explain, Rename and a prompt box, a status-bar strip, Ctrl+Alt+N to jump to the next waiting agent, a badge with the number of waiting agents on the app icon (Dock, Windows taskbar, KDE/Ubuntu launcher; window title elsewhere) and a desktop notification when an agent needs a decision or finishes while you are not looking at its pane. Detection reads the terminal screen locally and can be switched off in Settings → Terminal → Coding agents, where the badge and the notifications have their own toggles; the rules are JSON files you can override under ~/.kortty/coding-agents/. See Coding agents.
  • Control API and kortty-cli — korTTY can now open a local socket so a script or a coding agent on the same computer can list your windows, read any pane, type into it, wait for output, split a local shell, and drive a detected coding agent. It is off by default and is switched on under Settings → Terminal → Control API, where a status line reports what the listener is actually doing. Nothing is reachable over the network and no other user of the computer can connect: the endpoint lives in an owner-only ~/.kortty/control/ directory and needs a token that is regenerated on every start. Every action is logged with byte counts only, never terminal text, and the first time a program types into a pane you get one desktop notification, so a takeover is never silent. An administrator can deny the feature outright with the control-api policy key. The kortty-cli client ships beside the application in every native package and handles discovery, authentication and exit codes for you. See Control API and Control CLI.
  • Command timestamps stay on their command lines — once the scrollback had reached its limit, the marks in the command timestamp sidebar drifted one row further from their command with every new line of output, and a new prompt on the bottom row got no mark of its own. Marks now move with their lines, disappear when their line leaves the scrollback, and are removed by Clear Buffer. The dates in the sidebar and its hover popup follow the UI language instead of a fixed German order, and Duplicate and No Group in the tab context menu are translated instead of always German. See Terminal settings.
  • Anonymous usage statistics now cover coding agents and the Control API — if you allowed anonymous statistics, korTTY also reports which agent kinds are detected, how often agent notifications fire, which Control API methods are used and whether the coding-agent and Control API settings are on. Only kinds, states, method names and counts are sent — never terminal text, prompts or pane names. See Anonymous data.
  • Tabs that close on their own are fully released — when a split pane was left as the last pane and its shell exited, or Ctrl+D closed a local cmd or PowerShell tab, the tab closed without the cleanup its close button runs: korTTY still counted that pane as connected, so with Configuration > Prevent System Sleep checked the computer was kept awake, and a shell closed with Ctrl+D kept running in the background. Such tabs now close exactly like a tab closed with its close button.
  • Navigation keys reach programs the way they expect them — korTTY used to send the arrow keys, Tab, Home/End, Page Up/Down, Insert/Delete and the F-keys as fixed sequences without their modifiers, so Ctrl+Left and Shift+Tab arrived as plain Left and Tab and Shift+F1 as F1. They are now encoded the xterm way and follow the program's cursor-key mode, so word movement (Ctrl+Left / Ctrl+Right, Option+Left / Option+Right on macOS) and back-tab work in the shell, mc and vim. Shift+Page Up / Shift+Page Down now scroll korTTY's scrollback, Ctrl+Tab switches tabs while the terminal has the focus, editing the find bar's search text no longer types into the shell, and broadcast mode mirrors these keys to every pane, encoded for each. See Keyboard shortcuts.
  • Ctrl+L and Ctrl+F reach the shell on Windows and Linux — the terminal's own Clear Buffer and Find took these keys, so Ctrl+L wiped the scrollback instead of redrawing the screen in bash, psql or a REPL, and Ctrl+F never moved the cursor forward or paged forward in less. Both keys now go to the shell; Clear Buffer and Find stay in the terminal's right-click menu and Find in Edit → Find…, while Cmd+K and Cmd+F on macOS are unchanged. On Linux a selection copied automatically also becomes the X11 primary selection, so a middle-click pastes it in other applications. See Keyboard shortcuts.
  • The ANSI colors and the selection color on the Colors tab now take effect — the 16 color pickers in Settings → Colors were never saved, and the terminal ignored the Selection color too. Both now apply to every open terminal as soon as you save, and terminal recordings use the same colors as the screen. Settings you never changed keep the built-in palette and inverse-video selection, so nothing looks different until you customize a color. Bold as bright color still affects recordings only. See Colors.

Connections and security¶

  • Review and replace a changed host key — when a server was rebuilt, the changed-key alert of a terminal tab or the SFTP manager now offers Review and Replace…: it shows the trusted and the new SHA-256 fingerprint side by side and replaces the key only after you tick that you verified the new fingerprint with the server administrator. Close and Cancel stay the default buttons, background connections never offer the replacement, and the enforce-host-key-check policy forbids it. The new Configuration → Security → Known Hosts… lists, searches and removes trusted keys. See SSH host-key verification.
  • Split panes follow the server access policy — Split Right (new connection) and Split Down (new connection) connected to the server you picked without checking your organization's server allow or deny list, so a split pane could reach a server or jump server that Quick Connect and saved connections refuse. A blocked server or jump server is now refused right after you pick it, with the same policy message as Quick Connect and before korTTY asks for a password or saves the connection. Same-server splits check the policy too, so a tab whose saved connection was edited to point at a blocked server or jump server cannot open a pane there. See Server access control.

SSH and security¶

  • SSH tunnels now really open — tunnels configured on a connection were saved, imported and shared, but never opened. korTTY now opens the enabled ones once per terminal tab after login, closes them before a reconnect and opens them again afterwards, moves them to another pane of the same server when you close the pane they run on, and shows Tunnels: 2/3 active with the first error in the tab's status bar (hover for every tunnel). Because tunnels that never did anything would otherwise start listening silently after the update, korTTY asks once per connection before it opens them, and again when the tunnels or the server change. A remote tunnel listens on the SSH server's loopback address unless you name another one, shared (Teamwork) connections never open remote tunnels and may only listen on localhost, and administrators can forbid tunnels with the new allow-port-forwarding policy key. Remote tunnels that earlier versions imported from PuTTY Connection Manager carry the bind address 0.0.0.0; the confirmation, the tunnel list and the status bar mark them as reachable from other computers, so set their Remote bind address to localhost if the forwarded port should stay private to the server. See SSH Tunnels.
  • The tunnel editor says what listens where, and Enable SSH tunnels works — the tunnel dialog now labels its fields after their role for each type (Local bind address, Remote bind address, Local host as a remote tunnel's target), lists the listener first and warns when other computers can reach it; the tunnel list shows remote tunnels listener first instead of reversed and no longer shows German text for SOCKS proxies. Enable SSH tunnels, which nothing ever read, now switches every tunnel of the connection on or off, and saving the connection applies tunnel changes to open tabs right away, so switching tunnels off closes them. Cancel now discards tunnels added, edited or removed in the connection editor, which were kept before. PuTTY Connection Manager imports bind remote tunnels to localhost. See SSH Tunnels.
  • SSH tunnels now really open — tunnels configured on a connection were saved, imported and shared, but never opened. korTTY now opens the enabled ones once per terminal tab after login, closes them before a reconnect and opens them again afterwards, moves them to another pane of the same server when you close the pane they run on, and shows Tunnels: 2/3 active with the first error in the tab's status bar (hover for every tunnel). Because tunnels that never did anything would otherwise start listening silently after the update, korTTY asks once per connection before it opens them, and again when the tunnels or the server change. A remote tunnel listens on the SSH server's loopback address unless you name another one, shared (Teamwork) connections never open remote tunnels and may only listen on localhost, and administrators can forbid tunnels with the new allow-port-forwarding policy key. Remote tunnels imported from PuTTY Connection Manager carry the bind address 0.0.0.0; the confirmation and the status bar mark them as reachable from other computers, so set their Remote host to localhost if the forwarded port should stay private to the server. See SSH Tunnels.
  • The terminal encoding now takes effect — Settings → Terminal → Encoding was never read, so every SSH session was decoded as UTF-8 and servers that write ISO-8859-1, ISO-8859-15 or Windows-1252 showed broken umlauts. The setting now applies to SSH connections, and each connection can choose its own Character encoding on the Connection tab of the connection editor. Local shells stay UTF-8 unless their connection sets an encoding, and Mosh is always UTF-8. A value you picked in an earlier version, when it had no effect, is not applied on its own: SSH sessions stay UTF-8 until you save the settings after opening the Terminal page, where a note points this out. Text that the Control API types into a pane follows the pane's encoding as well. See Character encoding.
  • Temporary SSH keys are no longer left in the temp folder — every connect, split and SFTP session with a temporary SSH key wrote the private key to a file in the system temp folder that was never deleted, so the key stayed on disk long after it had expired, and the debug log recorded the beginning and end of the key text. Temporary keys are now read in memory only and never logged, and key files that earlier versions left behind are deleted at the next start when they belong to you. See Security.
  • Scheduled jobs delete their temporary key file — a JobScheduler job with a temporary SSH key still needs the key as a file for Rsync's external ssh; that file is now created owner-only from the start and deleted when the job ends or its connection fails, instead of staying in the temp folder.
  • JMX monitoring shows the connections that are really open — the de.kortty:type=SSHClient MBean always reported 0 active connections and no names, because it read a session list that nothing ever filled. ActiveConnectionCount, ActiveConnectionNames and ConnectionStatistics now list every live SSH and Mosh terminal connection (each split pane counts, local shells do not), and BufferedTextSize, which was never measured, stays at 0 for existing JMX clients. See Logging and diagnostics.
  • Scheduled jobs keep temporary keys off the disk too — a JobScheduler job with a temporary SSH key now authenticates in memory like a terminal tab. Only an Rsync job still needs the key as a file for its external ssh; that file is created owner-only from the start and deleted when the job ends or its connection fails, instead of staying in the temp folder.

Local AI¶

  • Go back to an older llama.cpp or MLX runtime — when a new runtime release causes problems, Other version… in the Runtimes table of AI → AI Manager → Local Models lists every version the signed stable channel still offers for this computer and installs the one you choose through the same verification as an update. A version other than the newest stays pinned, so update checks keep it until you pick the newest version again or choose Unpin; a pinned version the channel later withdraws is dropped automatically. See Runtimes.
  • Both runtimes stay visible in the Runtimes table — the table had a fixed height that fit two rows only at the default font, so with a larger UI font scale or an AtlantaFX design only llama.cpp was visible and MLX needed scrolling. The table now sizes itself to its rows and follows font-scale and design changes while the AI Manager is open.
  • Being offline is no longer reported as a failed runtime update — the startup check for the llama.cpp and MLX runtimes ran into an error with a stack trace whenever the computer had no network yet. An unreachable channel now ends in an Offline status and a single log line, installed runtimes stay usable, and an installation you start yourself still says why it did not happen.
  • MLX runtime updates are published like llama.cpp ones — the MLX index is now read from the same immutable, versioned releases as the llama.cpp index instead of a release whose files were replaced on every update; builds fall back to the previous location until the first combined release exists.

AI chat¶

  • Attach the selected file to an AI request — when the text you right-click in the terminal is a single file name, AI → Summarize / Solve Problem / Ask and Ask Agent… offer to send that file's content along with the request, so the model can work with the file rather than only its name. The file is resolved against the pane's current directory (over SFTP in SSH tabs, from disk in local-shell tabs) and is attached only after korTTY has checked that it exists, is readable, is UTF-8 text and fits the profile's selection limit; a checkbox in the confirmation dialog lets you send the text alone. The attachment is shown above the chat, stays in context for follow-up prompts and is kept with a saved chat. A Flowchart button beside it renders a Mermaid flowchart of the attached script in the chat. See Attaching a selected file to the chat.
  • Secrets in terminal selections are masked before they reach the AI — Summarize, Solve Problem, Ask and Ask Agent… used to send the selected text and an attached file exactly as they were, including a password or token that happened to be on screen. korTTY now replaces the connection's password, your organization's journal replacement rules and well-known formats (private-key blocks, AWS, GitHub, GitLab and Slack tokens, sk- API keys, bearer tokens, JWTs, passwords in URLs, *_PASSWORD= assignments) with ***, and the preview or the status bar says how many it masked. Only integrated models are exempt; an endpoint on localhost is masked too unless you mark it as a Trusted local endpoint in the profile, because it may forward to a cloud API. Masking is pattern-based and cannot catch every secret. See Masking secrets before sending.

AI agent and profiles¶

  • The AI agent asks before it runs in a switched session — after su, sudo -i or a nested ssh in a terminal, the agent's commands would still run over the tab's original connection, as the user the tab was opened with, not as the user the prompt shows. AI Agent and AI Planning now warn first and name the user@host (or "on this computer" in a local-shell tab) the commands will really run as; Cancel is the default. The check also covers rerunning a command with the activity panel's reload button and the execution of an accepted plan. See Safety and failure handling.
  • No internet mode for native Anthropic profiles — korTTY sends no web tools to the native Anthropic Messages API, so a mode such as KorTTY Tavily Tool had no effect there. For such profiles the Internet access dropdown is now locked to Disabled with a hint explaining why. See AI internet access.

AI usage and costs¶

  • See what AI costs — an AI profile can now carry a price per one million input and output tokens (AI → AI Manager → Profiles, Price per 1M tokens). With a price, korTTY shows the money spent next to the quota bar ("≈ 3.42 € in this period"), on session journals and in the AI Swarm header; local models are marked as having no token costs. See Token quota management.
  • Session journals show their AI tokens — every AI call made for a journal (summaries, title, screenshot analysis, questions) is added to the journal: the journal page header shows the total and the journal manager has an AI tokens column with a breakdown in its tooltip. See AI token usage and cost.
  • All AI calls count towards the profile quota — session journal calls, every AI Swarm agent and the swarm's combined answer, and scheduled AI jobs were not added to the profile's token quota before; they now are, so the quota bar reflects what was really spent. The AI Swarm header also shows the total tokens of the whole run.
  • Scheduled AI agent jobs no longer hide a number in their output — the job's token count was treated like a secret, so every occurrence of that number in the job's output and journal was replaced by ***. It is now booked against the profile quota instead.

JobScheduler¶

  • Session journal per run — a job can now record a full session journal for every run: one journal per target server with every command, its output, the job's summary and the outcome, which can be summarized by the AI, searched, exported and asked questions like an interactive journal. Per job you choose when the AI summarizes (every kept run, only failed runs, or never), whether successful runs are kept at all, when the journals are deleted automatically (after N days, on a date, or never), a maximum number of runs and disk space, whether a run identical to the previous one is discarded in favour of a reference, and which AI profile summarizes — a local profile keeps it free. Switching the journal or its AI summaries on first shows a warning with an estimate of the tokens and cost per run, day and month. The run history shows each run's journals with tokens and cost and opens them in the viewer; scheduled AI Swarm jobs record one journal per server as well. Administrators can forbid automation journals or cap their retention, disk space and number of runs. See Session journal per run.
  • Screenshots of jobs from an invisible virtual terminal — COMMAND and snippet jobs with a session journal can run in a pseudo terminal that korTTY renders without any window: screenshots at an interval, when the screen changes and at the end land in the run's journal, and a runtime limit stops monitors such as top with Ctrl+C. Progress bars and AI coding tools in non-interactive mode become visible without disturbing the terminals you are working in. See Virtual terminal and screenshots.

AI Swarm and journal manager¶

  • Session journal per swarm run — the Session journal checkbox in the AI Swarm toolbar records one journal per server for every run: the agent's commands and output, its answer and the combined report, with the same settings as a job (⚙) and the same cost warning. The dashboard reports what was kept and what the journal summaries cost, and Open shows the journals. See Session journal per run.
  • Journals grouped by job and swarm, with badges — the journal manager now groups automation journals by their job or swarm and by run, with the totals of each group, a filter for interactive, JobScheduler, AI Swarm, failed or pinned journals, and badges for the source, outcome, AI mode, identical runs, pin and the time left until automatic deletion. See Managing journals.
  • Temporary SSH keys are no longer sent to the AI with a multi-server workflow — Generate multi-server workflow sent the complete private key of a temporary SSH key to the AI provider. The request now only states that the server uses a temporary key. The path of a key file is still sent, so the script can use it. See Generate multi-server workflow.

Security¶

  • Unlock the vault after startup — with Require master password on startup turned off, korTTY started with the vault locked and offered no way to enter the master password later. Configuration → Security → Unlock Vault… now opens the vault mid-session, and the "vault locked" messages for saving keys and passwords, AI Swarm, guide questions and workflow scripts have an Unlock Vault… button that continues the action once the vault is open. Temporary SSH keys that a locked start could not decrypt are restored on unlock instead of being lost on the next save. See Unlocking the vault later.

Connections¶

  • Password targets behind a password jump server now connect — the terminal handed the master password only to targets that log in with an SSH key, and the SFTP tab not even to a temporary key, so a password or keyboard-interactive target failed on the jump server's stored password with "vault is locked" although the vault was open — and korTTY kept repeating that failed attempt through the whole retry count. The jump password now works whatever the target's authentication. Failures that another attempt cannot fix — a jump password that is missing, locked in the vault or cannot be decrypted, an incomplete jump setup, a rejected jump-server host key, an SSH key file that is missing or cannot be read — are reported once and no longer retried or reconnected automatically, and with a locked vault korTTY no longer contacts the jump server at all. See When the jump server cannot be used.

SFTP file manager¶

  • Robust uploads, a responsive server list and Reconnect — uploading a folder that already existed on the server failed at once; it now merges into the remote folder, and uploads are streamed, so files larger than the available memory or 2 GB no longer fail. Remote folders load in the background behind a Loading… indicator, and a folder that cannot be opened keeps the one you were in. A remote copy onto the item itself or into one of its own subfolders is now refused — copying a file to the folder it was in used to empty it. When the connection drops, the status bar shows Disconnected from host with Reconnect instead of Upload, Download and Refresh silently doing nothing. Size now sorts by the real byte count, the permissions fields accept only three octal digits, the menu entry is documented as Connections → SFTP-Client..., and the German UI says Server instead of Fernbedienung. See SFTP file manager.
  • SFTP tabs come back with a project, at their folders — a saved project referred to its SFTP Manager tabs by connection name while opening it looked them up by id, so with Auto-Reconnect no SFTP tab was ever restored, and the saved folders were ignored as well. Tabs are now saved by connection id and reopen at the local and remote folders they showed; a project saved earlier still restores a tab whose connection name is unique. A remote folder that is gone opens the login directory with a note in the status bar. Remote image tabs are saved with the connection they were opened from instead of the first SFTP tab's, so with several SFTP tabs open they no longer reopen from the wrong server. Restored remote image tabs now also connect with a key from the SSH key manager or through a jump server with a stored password, and close their own connection when you close them. See SFTP Manager tabs.
  • Rename, New Folder, drag and drop and wildcard search in the SFTP Manager — the guide described all four, but the SFTP Manager tab had none of them, and its search treated * as a plain character. Both panels now rename with F2 or the context menu, create folders from a toolbar button or the context menu, and delete with Del after confirmation; a rename never replaces an existing entry. Drag local rows or files from the desktop onto the remote panel to upload them and remote rows onto the local panel to download them, also straight into a folder row; up to 20 files with 16 MB together can be dragged from the server to the desktop. The search understands *, ?, [abc] and {py,sh} and keeps .. visible. See File operations and Search.

Performance¶

  • Dialogs open noticeably faster — the WebKit engine is loaded in the background after start instead of on the first dialog that needs it, the AI Manager and the settings dialog build their tabs on first visit, a stored connection's secrets are no longer re-derived on every open, and the snippet editor keeps a ready editor in reserve. Measured on a development build, the first AI Manager open dropped from about 1.4 s to under 0.1 s and the settings dialog from about 350 ms to 45 ms. The spare editor can be switched off with Keep a pre-warmed editor ready. See Snippet Editor settings.

Guide and snippets¶

  • The built-in guide has a new look and a working offline search — the guide now uses the Dracula theme, because the previous theme reaches end of life in November 2026. Search works without a network connection and suggests results as you type, and German pages now declare German as their language, so screen readers and hyphenation use the right one.
  • Clearer coding-agents diagram and a wider guide search field — the diagram on the coding-agents page shows one short note per box and no longer routes a line through other boxes, and the search field in the guide header is wide enough for its German placeholder.
  • Flow diagrams keep loops a model drew in the wrong shape — when a model drew a loop's condition as a plain action with two exits, the repair cut the exit after the loop and the whole diagram was replaced by the local fallback. Such a loop head is now turned into the loop decision.
  • Flow diagrams from Nemotron and gpt-oss are no longer thrown away — a model that writes all branches of a decision in one chain through Stop (… --> stop_1 -->|no| failure), as Nvidia Nemotron does, now gets that chain read as the decision's next outcome instead of the diagram being rejected, and repeated lines no longer make a complete diagram look hollowed out. Rounded nodes such as setup("Setup" ) are read as actions. When a diagram is still rejected — for example because a local model such as gpt-oss derailed into garbled output — korTTY asks once more, naming the reason, before it uses the local fallback.
  • Snippet Manager: more columns, resizable and remembered — the snippet table shows Lines and Last modified, every column (including Used, which was too narrow to read, and Tags) can be resized, and korTTY remembers the widths. Export now proposes plain text script files first. See Snippets.
  • Import single text files as snippets — Import accepts plain text files such as data_test.pl, several at once; each becomes a snippet named after the file, with the language taken from the file extension. Binary files are skipped. See Importing text files.
  • Import and export snippet variables — the Variable Manager exports all or the selected variables as JSON, XML or YAML and imports them again, asking whether existing values are overwritten. Its windows are larger, and the add/edit dialog explains both fields. See Variable Manager.

Snippet Manager and code analysis¶

  • One workspace for all snippets — the Snippet Manager shows the library and the snippets you edit side by side: browse in a read-only preview tab, edit in one tab per snippet, find a snippet with quick open (Ctrl+P), hide the library with Ctrl+B, and save or close tabs with Ctrl+S / Ctrl+W. The open tabs and the window's size and position come back the next time. See The Snippet Manager workspace.
  • Unsaved snippets are never lost — every way of closing, including closing a main-window tab, opening a project and quitting, asks about unsaved snippet edits, and an editor's unsaved form is kept as a draft that can be restored after a crash.
  • The Full code analysis lives in the editor and is stored — the analysis is a side panel inside the snippet editor, stored with the snippet the moment it arrives and shown again without a new AI request. A history keeps several analyses per snippet (Stored analyses per snippet in the Snippet Editor settings), with pinning, discarding, Verify after applying, Review later, and an apply run that can be continued even after a restart. The library's new Analysis column and filter show which snippets have open findings, a stale analysis or a pending review. See Full code analysis.
  • AI changes are reviewed inside the editor — improvements, security fixes, AI formatting and the analysis's apply result replace the editor area with a side-by-side review instead of a blocking dialog, so terminals and other editors stay usable.
  • Stop and retry any snippet AI request — every AI action in the snippet editor shows its running time with ■ Stop (also Esc) and offers ↻ Retry after a stop or failure; a stopped request really ends on the provider side.
  • Before/after analysis reports — export the stored analysis as PDF, HTML, Markdown or JSON before or after applying, save the analysed or final script as plain text, and export the reports of several snippets at once as one file or a ZIP.
  • More reliable flow diagrams, and a zoom window — a diagram the model got wrong is requested once more — repaired with the exact error where it can be — a fallback diagram says why it was used, and a click on the analysis diagram opens it in its own zoomable window.
  • Analyses are part of the backup — the configuration backup includes the stored snippet analyses, and an unreadable snippet file is moved aside instead of being overwritten.
  • Snippet folders — organise the library in nested folders shown in a tree above the table, drag snippets and folders to move them, and export a whole folder as a ZIP or a directory that keeps its structure. See Folders.
  • Executable flag — each snippet is exported and copied as an executable (755) or a plain (644) file; scripts with a known extension or a shebang are executable automatically, and the flag can be changed in the Exec column or the editor. See Executable flag.
  • Copy snippets and folders into the terminal directory — copy selected snippets or a whole folder tree as files into the current directory of an SSH session (over SFTP) or a local shell, with the right file modes and an overwrite/skip choice for existing files. See Copying files to the terminal directory.
  • Analyse a folder as one project, and modularize — the Full code analysis can examine a folder of scripts together and report problems between files, and the new Propose modularization option lets the AI split a script into modules that become files in a folder. Results that change several files are reviewed in a window with one tab per file and a directory tree that can be shown or hidden. See Analysing a folder as one project and Modularization.
  • Shell expansions stay as written, and typed values are stored only on request — only the built-in placeholders and the variables declared in the Variable Manager are replaced, so ${HOME}, ${1:-default} or ${#array[@]} reach the shell unchanged instead of being sent empty or asked for, $${name} writes a literal ${name}, and ${cursor} places the caret when a snippet is inserted into an editor. Send to Terminal asks for a declared variable without a value instead of sending it empty, Send to Terminal with Parameters lists every declared variable pre-filled, and a value you type is kept only when you tick Remember. Scheduled and swarm script runs still refuse an undeclared ${name}, and a # inside a word such as $# no longer cuts a shell line short when a script is sent as a one-liner. See Placeholder variables.

Credentials¶

  • Passwords from an external command work on Windows and no longer freeze korTTY — a credential that fetches its password from a command such as op, bw or enpass-cli now runs it in PowerShell on Windows (it always failed there) and on the host in the Flatpak package. The 10-second limit now really holds: a tool that waits for input, an unlock or Touch ID is stopped together with the processes it started and reported, where it could hang korTTY forever before, and the connection editor fetches the password in the background while the field shows Retrieving password.... See Passwords from an external command.

Backup and restore¶

  • GPG backups can be restored — a GPG backup was saved under the ZIP name kortty-backup.zip, so importing it asked for a ZIP password and failed, and even a renamed .gpg file could not be restored. GPG backups are now saved as kortty-backup.zip.gpg and import without a ZIP password; korTTY reads the format from the file content, so GPG backups made by earlier versions under the .zip name restore too. See Importing a backup.
  • A failed backup no longer pushes out the last good one — the new backup is written completely before the current one is rotated into old-backups/, rotated GPG backups keep their .zip.gpg ending, two backups in the same second no longer overwrite each other, and Maximum Backups counts ZIP and GPG backups together. See Backup retention and cleanup.
  • More of your configuration is backed up — custom terminal themes, credential environments, saved AI Swarm chats and MLX model registrations are now part of the backup, and after an import korTTY reloads them together with SSH keys, snippet variables and AI chats instead of overwriting the restored files with what it had loaded before. A backup with another master password makes korTTY quit after the import, so you unlock the restored data with that password on the next start.
  • The backup dialogs show their numbers — the confirmation after creating or importing a backup showed {0} instead of the file name, size and number of files.

Teamwork and terminal recording¶

  • No more options that did nothing — the Video Manager no longer offers a Default format: recordings were always written as korTTY replay files, and WebM or MKV videos come only from Export. A setting saved with the old WebM value still loads. The Read-only checkbox is gone from the teamwork source dialog as well, because korTTY never writes back to a teamwork source; a value stored earlier is kept. The Teamwork page now describes the one-way sync as it works. See Terminal recording.

Local data files¶

  • A crash or a damaged file no longer costs you your connections — connections, credentials, SSH and GPG keys, environments, themes, scheduled jobs and master.key are now replaced atomically and flushed to the disk instead of being rewritten in place, and on macOS and Linux ~/.kortty and the files holding secrets are made owner-only. A file korTTY cannot parse at startup is moved aside as <name>.corrupt-<timestamp> and listed in a notice instead of being overwritten with an empty list, and a file it cannot read at all is left untouched for the session. See Stored security data.
