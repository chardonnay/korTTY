    Release notes¶

    What changed in the current release. The version this guide was built for is shown in the footer.

    v2.16.0¶

    Appearance¶

    • Hints and profile rows in the AI dialogs are readable on the dark designs again — the AI Manager's profile list painted every unremarkable profile in a hard-coded near-black, and the small hint and status lines asked Modena for a colour that no AtlantaFX design defines, so JavaFX dropped the declaration and the label fell back to pure black — 1.52:1 against a dark surface. A profile row now keeps the surface's own cell colour, the token-warning levels pick a shade that clears 4.5:1 on the active background, and hints dim with opacity instead of naming a colour, so they follow whatever the design provides.
    • Scroll bars in the guide now match its dark page — the window that shows the manual loads only the ask panel's stylesheet, which carried no scroll-bar rules, so both the page's scroll bar and the ask panel's fell back to Modena's light grey beside the dark page. Track, thumb and arrows are now drawn in the same palette as the page, with the accent colour on hover.
    • The "Cursor blinks" setting stays off — the choice lived inside the terminal's cursorStyle string, which colour profiles, themes and per-connection settings also own, and every one of them ships a blinking style: a single profile copy could turn blinking back on, and the next start showed the box ticked again. It is now stored as a setting of its own that wins over whatever style those carry, so it survives restarts and profile switches. Existing settings files keep their current choice — it is read out of the stored style once and then kept in the new field. See Colors settings.

    Snippets¶

    • Cursor-style code completion in the snippet editor — Shift+Tab at the end of a line opens a completion list. Ctrl+Space opens one anywhere. The candidates are harvested from the snippet itself: the arrays, hashes, variables, functions and language idioms that fit the spot. Every array that a for-loop could iterate over is one of them. When an AI profile is configured, up to five ✦ AI candidates join the open list as they arrive. Auto AI Complete now shows its suggestion as ghost text after a typing pause. Tab accepts it and Esc discards it. Alt+] and Alt+[ step through the alternatives. The data notice appears once per application start instead of once per editor. The old floating suggestion box with its Insert button is gone. An AI completion request sends the code around the cursor and the snippet's symbol names. It no longer sends the whole snippet twice. It skips knowledge stores, runs beside the other AI actions instead of blocking them, and is abandoned after 30 seconds. For JavaScript, TypeScript, JSON, CSS and HTML, Monaco's own language suggestions share the list. The combination that opens the list is configurable under Configuration → Global Settings → Snippet Editor. The new AI Completion Shortcut field records whatever you press: one key, or one key with up to three modifiers. When you pick something else, Shift+Tab removes one level of indentation again. See AI Code completions. See also Snippet Editor settings.
    • Full code analysis can now be applied to long scripts — each apply stage used to return the complete rewritten script as a JSON array of every line. For a 4,000-line script that is around 60,000 output tokens: at the model's completion cap, twelve minutes per stage, and a single lost quotation mark in that much JSON lost all of it — with MiniMax-M3 every stage failed after 18 minutes. Above 400 lines a stage now receives the line-numbered snippet and returns only the changed regions, which korTTY applies locally before running exactly the same verification as before; untrustworthy ranges are refused, the log names what was applied, and the stage's output cap drops to 32,768 tokens. Short snippets keep the proven whole-file answer. See Full code analysis.
    • A long-script analysis run costs far fewer tokens and requests — every apply stage sends the whole line-numbered script, so on a 4,009-line script each stage was around 63,000 prompt tokens. Edit-mode stages now take six analysis items instead of three, which took twelve items from four stages to two — 126,391 prompt tokens instead of roughly 252,000, measured live with MiniMax-M3. The script also comes first in the request now, so consecutive stages share the system prompt, the contract and the script up to the first line the previous stage changed: MiniMax reports the saving as cached tokens, LM Studio and llama.cpp reuse their KV cache. Whole-script retries are gone as well — a broken edit answer is read locally wherever the snippet itself proves the reading, and a dependency suggestion the model did not echo no longer opens a repair round.
    • korTTY now reads the answers models actually return — a run used to lose finished work to the shape of a reply rather than its content. From live runs against MiniMax-M3, gpt-oss-120b and local reasoning models: a diagram whose quotes, line breaks or label pipes the model mis-escaped is repaired instead of discarded, one that declares a node twice or overshoots the stated node limit is kept, the colour definitions a model adds on its own are dropped rather than held against it, and a diagram the repairs would hollow out is refused with both its node and its edge count named. On the apply side, an answer that is truncated, abbreviated, ran into the output-token limit or collapses the script now gets one second attempt saying what was wrong, instead of ending the run. MiniMax is told to switch its own reasoning off for diagram requests, which it ignored reasoning_effort for. Every answer korTTY could not use is archived complete under ai-answers/ in the log directory, with the log line naming the file and the place the JSON broke, so a failed stage can be diagnosed from a report without debug logging.
    • Flow diagrams of long scripts are less generic and generate much faster — the diagram request never told the model the node limit that the validator enforced, so for a script of several thousand lines the model transcribed the whole script into hundreds of nodes, spent minutes doing it, and was rejected. The limit is now part of the request and grows with the script — 12 action/decision nodes for snippets up to 200 lines, up to 24 at 1,000 lines or more — and the built-in flowchart skill asks for the main phases of a long script rather than every branch. A script longer than 400 lines is also sent as a condensed structural outline — its definitions and top-level flow, with elided runs marked and the original line numbers kept — instead of every single line, which cuts the request size several-fold and lets the model describe phases instead of statements. See Mermaid diagrams.
    • Flow diagrams now accept the Mermaid that models actually write — tested live against MiniMax-M3, korTTY's diagram grammar rejected one answer in three for shorthand the contract never allowed but every model uses: nodes declared inline in an edge, chained edges, -- yes --> labels, the :::class shorthand, unquoted labels, other node shapes, and the model's own slips (a label pipe typed as a bracket, a shape closed early, a decision drawn as a diamond with one exit, a mistyped id left dangling, File::Glob in a label tripping the URL screen). The grammar now reads all of these and rewrites an accepted diagram into its strict dialect before rendering or saving, the validator tolerates a modest overshoot of the stated node limit instead of discarding a summarized diagram, the contract shows the edge-label syntax instead of describing it, and only what cannot be drawn faithfully — parallel branches from one action — is still rejected, with the reason named. A start_1 the model declared but never connected is wired to the flow's real entry, statements written with a stray class prefix are still read, and a repaired diagram that kept fewer than half of the drawn nodes is refused rather than shown as a stub.
    • A rejected AI flow diagram now says so — when korTTY discarded an AI-generated flowchart, the Full code analysis window silently showed the generic local fallback diagram instead, so a long script always seemed to produce a trivial five-node chart. The fallback now carries a notice naming the rejection reason, the same reason appears in the editor's status line and in the log together with the diagram's node and edge counts, and a diagram whose nodes lack a valid source mapping is kept (those nodes merely lose their hover reference) instead of being replaced by the fallback. Acceptance is logged only after the last gate, so a diagram the strict-dialect repairs then hollow out no longer appears as accepted and rejected one millisecond apart, and the rejected answer itself is kept under ai-answers/ for diagnosis.
    • Sequence, state, class and ER diagrams now scale with the window — Mermaid puts an inline max-width on the root SVG of every family whose useMaxWidth option is on, which is all of them except the flowchart korTTY configures explicitly, and that cap outranked the viewer's own sizing: those four stayed at their natural size however large the window grew, while the zoom label climbed to 311%. The inline size declarations are now stripped before the width and height are written from the viewBox, so how large a diagram is drawn is the container's business alone — for the families korTTY may render later as well.
    • A zoom slider for the diagram — the diagram toolbar's − / + / Fit buttons now have a slider between them that sets the scale directly. Its track runs in powers of two, so the fitted size sits in the middle and one step to either side halves or doubles it, instead of a linear track that would leave the fitted size at a fifth of the way. The buttons and the slider drive one value, so each follows the other, and Fit returns both to the middle. Because every zoom step redraws the whole diagram, a dragged slider redraws a few times a second and once more on the value it is released on, so a 4,000-line script's flowchart follows the drag smoothly. The zoom controls stay together as one group when the toolbar wraps.
    • The docked change preview keeps its size and place — the preview docked beside a Full code analysis opened at 1040×700 instead of its docked size, drifted to the screen edge when all three windows had to be tiled, and could show a blank band with its content covering only half the window. A freshly docked window now ignores the platform's late size reports for a second and re-asserts its placement, opens at its docked size, and checks that its content still covers it whenever the window, the scene or the content changes size.

    AI assistant¶

    • AI chat answers now display formatted Markdown — headings, emphasis, lists, quotations, and inline code appear as a readable preview alongside the existing tables and code blocks. Long text wraps without a fixed-height inner scrollbar. The conversation follows new messages and delayed layout changes, pauses when you scroll up, and resumes when you return to the bottom.
