    Release notes¶

    What changed in the current release. The version this guide was built for is shown in the footer.

    v2.10.0¶

    Terminal logging¶

    • Connection logging was rebuilt to actually be reliable — terminal logging previously wrote every connection to one fixed path (so two connections open at once interleaved into the same file), had no compression, and rotated by deleting the file at the size limit. Files are now named <date>-<time>-<server>_<number>, a fresh one starts every day (optional) and whenever the size limit is hit, nothing is ever overwritten or deleted by rotation, and each closed file is gzip-compressed. Old archives are swept by the date encoded in their name once the retention period (default 30 days, 0 keeps everything) expires, and only korTTY's own log files are ever touched, so it is safe to point the setting at a folder used for other things too.
    • The terminal log is now redacted — captured lines pass through the same redaction as the session journal before anything is written: the connection's own stored password and any replacement rules an organization's policy defines. Log files, and a log folder korTTY created itself, are set to owner-only permissions where the filesystem supports it.
    • Quick Connect gained a Terminal log section — configuring logging in the Connection Manager and then connecting from Quick Connect with a different authentication method previously dropped the setting silently; Quick Connect now carries its own folder, format and compression controls and applies them to the session it opens.
    • Fixed: XML and JSON logs had two document roots and never parsed, rotation wrote the closing footer twice, up to 10,000 queued lines from just before a disconnect could be silently dropped, and output was split on line endings in a way that destroyed indentation and turned every progress-bar frame into its own log entry. All four are fixed.

    Session journal: filtered export, named markers, page appearance and screenshot editing¶

    • Exports can now be narrowed down — Exporting only part of a journal accepts any number of time windows (an entry only needs to fall into one of them), a topic filter as literal text, a regular expression, or handed to the AI to select by meaning, and a marker filter (all entries, only marked ones, or specific markers). Times are parsed leniently (8, 0800, 8.30 all work) and widened by an adjustable tolerance (± 5 minutes by default), so an approximate window still catches the entry that actually straddles it. A filtered HTML bundle is rebuilt rather than copied — trimmed capture log, only the referenced screenshots — so a shared export cannot leak the rest of the session; every filtered PDF, Markdown file and bundle carries a banner naming the range so nobody mistakes it for the complete journal.
    • Markers are no longer a fixed four-value list — beyond the built-ins (None, Info, Important, Error) you can now define custom markers, give each one a name and colour, and map it to one of the built-ins for older journals and for the error/important counts. Optional rules apply a marker automatically as entries are captured, matching a literal term or a regular expression against the entry's title, summary, note and excerpts, with precedence your own choice > a rule > the AI's suggestion — a rule never overwrites a marker you set by hand.
    • The journal page has adjustable appearance — a colour scheme (six fixed palettes, the page's automatic light/dark pair, or a scheme derived live from your terminal's own colours), a text font and a monospace font, chosen from a toolbar popover and remembered for every journal korTTY renders afterwards.
    • Screenshots can be annotated — pen, box, an "Unreadable" tool that coarsens a region into blocks, and text labels, plus a note field, reachable by right-clicking a screenshot. Marks are stored as data and stay re-editable; the untouched capture is kept locally as .orig.png and is never included in an export. This obscures a value in the rendered page, it does not redact it — use Search & replace or a policy redaction rule to remove something from a journal for good.
    • Selecting a time range got easier — inside korTTY the viewer's timeline can be switched into range-selection mode: click a first and a last entry to highlight the span between them and hand it straight to the export dialog, or collect several windows before exporting. The same selection is available from the edit-mode entry table via right-click.
    • You can edit a journal title directly on its page, and a header button jumps from one marked entry to the next.

    Snippet editor¶

    • Fixed incomplete Full code analysis replacements — every Apply selected stage asks for one full rewritten script, explicitly requires every unchanged section to be copied, and refuses omission markers such as rest unchanged before another stage or the review window can use the result.
    • Fixed the snippet Text language scope — every AI action that returns code now requires all existing and new comments, every displayed message, every log message, and every help message in that returned scope to use the selected language. A Full code analysis replacement applies the rule to the entire script while its report and diagram labels continue to follow the interface language.
    • Reduced Full code analysis prompt and skill bloat — analysis and diagram requests now send one line-numbered script copy instead of repeating the same source as raw and numbered text. An explicit snippet-skill selection is used as an allowlist instead of being combined with another automatic relevance pass, and ordinary automatic matching keeps only its strongest candidates.
    • Optimized and hardened Mermaid diagram generation — diagram-only requests no longer carry configurable coding Skills, knowledge-store excerpts, a linear example that could anchor the model, or repeated copies of the Mermaid contract. A compact immutable Mermaid action skill is now always included instead: it asks for grouped runtime behavior, localized yes/no branches and loop exits, connected start-to-stop paths and exact source ranges. Fresh AI results with disconnected nodes, backward terminal paths, incomplete decisions, more than 12 action/decision nodes or incomplete source mappings are rejected and use the local fallback without an AI retry, while safe stored diagrams remain backward-compatible; built-in interface languages also get a local edge-label check. When the none Reasoning value is available and the profile has a fixed model selection, korTTY automatically uses it for the diagram request without changing the saved profile. An Auto profile is not overridden from previously discovered capabilities because its loaded model can change; an explicitly configured none value still applies. OpenAI-compatible HTTP, LM Studio native, and embedded llama.cpp/MLX transports cap the response at 8,192 tokens, while Anthropic retains its separate provider cap. For embedded llama.cpp/MLX, korTTY does not repeat a response that is empty or contains only the model's reasoning; replacing or closing a pending diagram also cancels the superseded client request.
    • Added output limits for code replacements — A finite output limit now applies to Full code analysis, security-fix, hardening and assistant replacements over OpenAI-compatible HTTP, LM Studio native, and embedded llama.cpp/MLX. It scales from 32,768 to 65,536 tokens with the source size; Anthropic retains its separate provider cap. When korTTY applies selected Full code analysis improvements or security fixes, it automatically requests none Reasoning only if that value is available and the profile has a fixed model selection. An Auto profile keeps its configured or provider-default Reasoning behavior unless none was explicitly configured. This prevents binary on/off reasoning models from spending the complete replacement budget before emitting the script. A provider-reported or malformed truncated response — including a reasoning-only answer with empty visible content — is recorded and rejected with the localized output-limit status and cannot change the editor or trigger an AI retry. Very large full-script replacements can therefore be refused rather than partially applied.
    • LM Studio reasoning-option detection was fixed — Refresh reasoning options now prefers the model's exact native allowed_options metadata. A binary off/on model no longer shows the Minimal, Low, Medium, High, or Extra high levels as supported merely because LM Studio silently converts an unsupported value to on; an explicit none request switches this feature off, while omitting the parameter uses the published provider default.
    • Fixed the Input hardening file-size guard — generated scripts now use MAX_FILE_SIZE, check file metadata before reading any content, reject oversized files without reading them, and treat 0 as an unlimited size. The size field now accepts 0 accordingly.
    • Audited every Hardening and Input hardening option — leaving a classic option unselected no longer lets the same behaviour return through unconditional language-specific defaults, and each input sub-option now names only its own checks, helpers and exit-code cases. Global hardening selected in Improve robustness or Custom improvement now rewrites the complete snippet so prologue and epilogue rules can actually be applied.
    • Stopped partial hardening in Full code analysis — Apply selected assigns every selected classic and input-hardening rule a stable mandatory identifier, batches analysis items and dependencies into apply stages of at most three, processes the two hardening categories separately in batches of at most three mandatory requirements, and verifies the cumulative completed-identifier list without demanding one verbose change record per rule. Missing requirements reject the whole staged result, while explicit selected flags and guard literals such as --dry-run, --yes, --help, --verbose, MAX_FILE_SIZE, FORCE, --force, and SECURITY: must be present in the final script.
    • Made staged Apply selected requests survive a dropped connection — a stage whose response stream is cut off mid-answer by the connection is now retried once automatically and reported as an interrupted connection, instead of aborting the whole apply and misreporting it as the output-token limit. Long-running chat requests (Full code analysis, security fixes, hardening, the assistant) now stream over OpenAI-compatible HTTP so a slow generation keeps bytes flowing and survives gateway idle timeouts; a MiniMax profile with reasoning turned off now also disables MiniMax's own "thinking" budget instead of silently spending it anyway.
    • Fixed empty Full code analysis apply results from malformed local-model JSON — each stage now returns the complete script as a structured array with one source line per entry instead of one escape-sensitive JSON string. OpenAI-compatible requests enforce that shape and a conservative minimum line count through a strict JSON response schema, dropping the schema only when the endpoint explicitly rejects structured output. The compatibility parser still preserves source escapes such as \s where possible.
    • Made Full code analysis apply progress visible and atomic — the analysis report now stays open while a narrow AI-processing companion window docks beside it. Separate progress bars for improvements and code hardening, elapsed time and provider-reported cumulative token usage sit above a complete checklist. Improvement and dependency rows show their colour-coded category icon directly after the item ID rather than reserving a narrow right-hand column for category and severity text; hardening requirements rely on the Code hardening section heading. Checklist descriptions are capped at three lines with an ellipsis while the complete text remains visible in the adjacent analysis report. The active batch is visible, every completed item receives a green checkmark and a failed or retried step remains identifiable. Each stage builds on the previous full script, but intermediate results remain hidden and are never applied on their own. A stage gets at most one visible repair attempt after either a short non-truncated fragment or a complete response that omits a mandatory identifier or required literal. Requirement repair starts from the complete returned script and names the unresolved identifiers; a second failure reports those identifiers and discards the sequence. Exactly one final review preview opens only after cumulative validation succeeds.
    • An interrupted Apply selected can now be resumed or partially applied — when the staged run stops after at least one completed stage (an AI or connection failure, or the editor's cancel button), an Apply interrupted prompt offers three ways out: continue the remaining stages from the point of interruption while keeping the completed work, review the completed stages' combined rewrite in the usual before/after preview and apply it from there, or discard everything as before. Closing the analysis window or the snippet editor mid-run still discards silently, and a run that aborts before its first completed stage keeps the previous behavior.
    • Made unavailable input guards explicit — Input hardening is now disabled, and yields no effective saved configuration, for YAML/YML/Ansible targets in workflow, swarm, improvement and Full code analysis dialogs instead of accepting a selection that would later be ignored.
    • Fixed an Auto AI Complete popup during Full code analysis — starting the analysis now discards a pending completion timer and closes any visible ghost suggestion instead of allowing a stale completion popup to appear over the analysis flow.
    • Hardened the initial Full code analysis response — OpenAI-compatible HTTP now constrains the report to a strict JSON schema with the fields summary, dependencies and improvements. korTTY retries once without the schema only when the endpoint explicitly rejects structured output. Malformed model output is rejected without a retry loop.
    • Moved the Full code analysis selection checkbox — Select all improvements is now the first control at the far left of the analysis toolbar instead of being pushed to its right-hand control group, with extra spacing before the following Profile: indicator so the two groups remain visually distinct.

    Connections¶

    • Connections can now be tagged — every saved connection takes one optional free-text tag (prod, staging, a customer name…), set on the connection editor's Connection tab or in bulk via the Connection Manager's new Assign Tag / Remove Tag context-menu entries, which work on a multi-selection and on whole folders including their subfolders. Tagged servers show a 🏷 badge in the manager tree and in Quick Connect's saved-connections list, and the connection searches — Connection Manager (local and Teamwork tabs) and Quick Connect — all match tags too.
    • Export by tag — the connection export dialog can now export all connections carrying chosen tags instead of the pre-selected list: pick one or more tags, the dialog's connection count follows the actual selection, and the export button stays disabled while nothing matches.
