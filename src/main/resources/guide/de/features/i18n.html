Sprachen und dynamische Übersetzung¶

KorTTY unterstützt acht integrierte Sprachen und kann über Übersetzungs-APIs Übersetzungen für jede weitere Sprache generieren, sodass Sie die Schnittstelle in Ihrer bevorzugten Sprache verwenden können.

Eingebaute Sprachen¶

KorTTY enthält vollständige Übersetzungen für die folgenden Sprachen:

  • Englisch (Standard)
  • Deutsch
  • Italienisch
  • Spanisch
  • Portugiesisch
  • Französisch
  • Kroatisch
  • Niederländisch

Die Anwendung erkennt beim ersten Start automatisch Ihre Systemsprache und lädt die passende Übersetzung, falls verfügbar. Wenn Ihre Systemsprache nicht in der integrierten Liste enthalten ist, wird Englisch als Ersatz verwendet.

Sprache ändern¶

So wechseln Sie zu einer anderen integrierten Sprache:

  1. Öffnen Sie Einstellungen → Sprache
  2. Wählen Sie im Dropdown-Menü die gewünschte Sprache aus
  3. Starten Sie die Anwendung neu, damit die Änderung wirksam wird

So verwenden Sie automatisch Ihre Systemsprache:

  • Wählen Sie Automatische Erkennung (Systemsprache) in Einstellungen → Sprache
  • Die Anwendung erkennt beim Start Ihr Systemgebietsschema

Dynamische Übersetzung (zusätzliche Sprachen)¶

Sie können Sprachdateien für jede Sprache generieren, die von einer Übersetzungs-API unterstützt wird. Dadurch kann KorTTY seine Benutzeroberfläche in Sprachen anzeigen, die über die acht integrierten Optionen hinausgehen.

Übersetzungsanbieter¶

KorTTY unterstützt die folgenden Übersetzungsdienste:

Anbieter API-Schlüssel erforderlich verwendete API Hinweise
Google Translate Ja Cloud Translation v2 (Basic) Standard, allgemein verfügbar; ein einfacher API-Schlüssel reicht aus
DeepL Ja DeepL API v2 Hochwertige Übersetzungen; Kostenlose und Pro-Endpunkte werden automatisch ausgewählt
LibreTranslate Optional LibreTranslate /translate Optional für öffentliche Instanzen; Selbst gehostete Option verfügbar
Microsoft Translator Ja Azure AI Translator v3.0 Übersetzungen auf Unternehmensniveau
Yandex Ja Yandex Cloud Translate v2 Benötigt einen Dienstkonto-API-Schlüssel von Yandex Cloud, nicht den veralteten v1.5-Schlüssel

Yandex-Schlüssel, die von einer früheren korTTY-Version gespeichert wurden

Yandex stellt die Ausgabe von Schlüsseln für die alte Translate API v1.5 ein und schaltet die kostenlosen Schlüssel ab bereits ausgestellt, sodass kein verfügbarer v1.5-Schlüssel mehr authentifiziert werden kann. korTTY spricht jetzt mit dem Stattdessen Yandex Cloud Translate v2-Endpunkt und ein v1.5-Schlüssel, der in einer früheren korTTY-Version gespeichert ist wird nicht funktionieren: Erstellen Sie ein Dienstkonto in der Yandex Cloud-Konsole und geben Sie es ein ai.translate.user-Rolle, geben Sie einen API-Schlüssel dafür aus und fügen Sie diesen Schlüssel ein Einstellungen → Übersetzung. Wenn Sie auch das Feld API-URL mit der alten ausgefüllt haben translate.yandex.net/api/v1.5/...-Adresse, löschen Sie sie – korTTY ignoriert diese Adresse und protokolliert a Warnung, bis Sie es tun.

Erzeugen einer Übersetzung¶

So erstellen Sie Übersetzungen für eine neue Sprache:

  1. Öffnen Einstellungen → Übersetzung
  2. Wählen Sie im Dropdown-Menü eine Übersetzungs-API aus
  3. Geben Sie bei Bedarf Ihren API-Schlüssel ein (der Schlüssel wird verschlüsselt mit Ihrem Master-Passwort gespeichert)
  4. Legen Sie optional eine benutzerdefinierte API-URL fest (um beispielsweise auf eine selbst gehostete LibreTranslate-Instanz zu verweisen)
  5. Klicken Sie auf API-Verbindung testen, um zu überprüfen, ob die Einrichtung funktioniert
  6. Wählen Sie im Sprach-Dropdown die Zielsprache aus
  7. Klicken Sie auf Sprachdatei generieren

Die generierte Sprachdatei wird unter ~/.kortty/i18n/messages_XX.properties gespeichert, wobei XX der aus zwei Buchstaben bestehende Sprachcode ist. Starten Sie die Anwendung nach der Generierung neu, um die neue Sprache unter Einstellungen → Sprache verfügbar zu machen.

Nach App-Upgrades¶

Wenn KorTTY auf eine neue Version aktualisiert wird, werden zuvor generierte Sprachdateien automatisch als veraltet erkannt, wenn sie mit einer älteren App-Version erstellt wurden. Unter Einstellungen → Übersetzung wird ein Hinweis angezeigt, der angibt, welche Sprachen aktualisiert werden müssen.

So aktualisieren Sie alle veralteten Sprachdateien nach einem Upgrade:

  1. Öffnen Einstellungen → Übersetzung
  2. Klicken Sie auf Veraltet neu generieren
  3. Alle generierten Sprachen werden neu übersetzt, um neue oder geänderte Schlüssel aus der neuen Version einzuschließen

Die Neugenerierung ist nicht dringend: Bis Sie dies tun, greift jede nach der Generierung Ihrer Datei hinzugefügte Zeichenfolge auf die gepackte Übersetzung für diese Sprache zurück oder auf Englisch, wenn die Sprache keine gepackte Datei liefert. Sie sehen eine übersetzte oder englische Bezeichnung, niemals einen rohen Schlüsselnamen.

Speicher und Persistenz¶

  • Erzeugte Sprachdateien werden in gespeichert ~/.kortty/i18n/
  • Jede Datei ist eine Standard-Java-Eigenschaftendatei (messages_XX.properties).
  • Dateien bleiben bei Anwendungsneustarts und -aktualisierungen bestehen
  • Sprachdateien sind in verschlüsselten Backups enthalten, die über Bearbeiten → Backup erstellen erstellt wurden.

Wie es funktioniert¶

Das Internationalisierungssystem von KorTTY basiert auf einer Ressourcenbündelarchitektur:

  • Basissprache: Englische Zeichenfolgen werden in i18n/messages.properties definiert, das mit der Anwendung gebündelt ist
  • Integrierte Sprachen: Vorübersetzte Eigenschaftendateien werden mit der Anwendung gepackt
  • Dynamische Sprachen: Generierte Eigenschaftendateien werden beim Start von ~/.kortty/i18n/ geladen
  • Platzhaltererhaltung: Übersetzungs-APIs bewahren parametrisierte Platzhalter wie {0}, {1} und ${variable} während der Übersetzung
  • Lookup-Fallback: Zuerst wird eine Datei in ~/.kortty/i18n/ konsultiert, dann die gepackte Datei für dieselbe Sprache und dann das englische Basispaket – sodass ein Schlüssel, der in der generierten Datei fehlt, trotzdem aufgelöst wird

Die LanguageManager-Klasse erkennt verfügbare Gebietsschemas sowohl aus integrierten Übersetzungen als auch aus dynamisch generierten Dateien, sodass Sie beide Typen nahtlos kombinieren können.

Plattform-Gebietsschemaerkennung¶

KorTTY verwendet die Gebietsschemaeinstellungen Ihres Betriebssystems als Standard, wenn die automatische Erkennung aktiviert ist. Die Spracherkennung funktioniert plattformübergreifend:

  • macOS: Liest die Systemsprache aus den Systemeinstellungen
  • Windows: Verwendet Windows-Spracheinstellungen
  • Linux: Berücksichtigt die Umgebungsvariable LANG und die Systemgebietsschemaeinstellungen

Wenn die Primärsprache Ihres Systems nicht in der integrierten oder generierten Liste enthalten ist, wird automatisch Englisch ausgewählt.

Tipps für die Übersetzungsqualität¶

Übersetzungsergebnisse optimieren

  • Kürzere Blöcke: Übersetzungs-APIs funktionieren am besten mit Zeichenfolgen mittlerer Größe. KorTTY stapelt Übersetzungen in Gruppen von 25 Zeichenfolgen
  • Platzhaltersicherheit: Platzhalter ({0}, ${var}) werden während der Übersetzung automatisch geschützt und nie geändert
  • Test nach der Generierung: Überprüfen Sie nach dem Generieren einer neuen Sprache die Schnittstelle auf umständliche Formulierungen und erwägen Sie eine Anpassung der API-Anbieter, wenn die Qualität nicht ausreicht

LibreTranslate Self-Hosting

Wenn Sie eine selbstgehostete LibreTranslate-Instanz ausführen, können Sie KorTTY darauf verweisen, indem Sie die benutzerdefinierte API-URL in den Übersetzungseinstellungen eingeben. Dadurch werden API-Schlüsselabhängigkeiten vermieden und Ihre Daten bleiben lokal.

Fehlerbehebung¶

API-Verbindungsprobleme

Wenn API-Verbindung testen fehlschlägt, überprüfen Sie Folgendes: - Ihr API-Schlüssel ist korrekt und gültig - Der Dienst des API-Anbieters weist keine Ausfälle auf - Ihr Netzwerk kann den API-Endpunkt erreichen - Stellen Sie bei benutzerdefinierten URLs sicher, dass der Endpunkt erreichbar ist und ausgeführt wird

Fehlende Sprachen nach dem Upgrade

Wenn eine generierte Sprachdatei nach dem Upgrade von KorTTY verschwindet: - Überprüfen Sie, ob die Datei unter noch vorhanden ist ~/.kortty/i18n/messages_XX.properties - Stellen Sie sicher, dass die in der Datei aufgezeichnete App-Version mit der aktuellen App-Version übereinstimmt - Generieren Sie die Sprache bei Bedarf neu, indem Sie Einstellungen → Übersetzung → Veraltete Sprache neu generieren verwenden
