Versionshinweise¶

Was hat sich in der aktuellen Version geändert? Die Version, für die diese Anleitung erstellt wurde, wird in der Fußzeile angezeigt.

v2.17.0¶

Terminal¶

  • Ein falsch platzierter Bildlaufbereich schränkt den Cursor nicht mehr ein – DECSTBM legt den Bereich fest, in dem gescrollt wird, nicht den Bereich, in dem der Cursor adressiert werden kann, aber jeder Schreibvorgang hat den Cursor durch Scrollen trotzdem an die Ränder geklemmt: Text, der über dem oberen Rand adressiert wurde, wurde in den Bereich gezogen, und Text, der unter dem unteren Rand adressiert wurde, scrollte den Bereich unter dem heraus, was bereits auf dem Bildschirm war. tmux löst den ersten Fall aus, während es einen Bereich mit immer noch schmalen Rändern zeichnet, wodurch der Cursor eine Zeile über der Eingabeaufforderung angezeigt wird. Das Scrollen erfolgt jetzt nur noch bei einem expliziten Zeilenvorschub, sodass der Cursor jede Zeile im Terminal ansprechen kann, ohne bereits vorhandene Zeilen zu verschieben.

Tools¶

  • KI-Bilder im ASCII-Art-Tool stimmen jetzt mit ihrem Thema überein und kommen in Sekunden statt in Minuten an – die Registerkarte „KI-Bild“ forderte das Modell auf, ein ausgerichtetes Zeichenbild einzugeben, was Modelle schlecht und langsam machen: denkende Modelle gaben ihr gesamtes Budget für Überlegungen aus, die Antwort hatte keine Ausgabeobergrenze, eine abgeschnittene Antwort sah aus wie eine leere, und jede Anfrage kostete zunächst eine Suche im Wissensspeicher. Das Modell gibt nun eine kleine Vektorzeichnung zurück, die korTTY selbst rastert und in ASCII konvertiert, die Reasoning wird ausgeschaltet und die Antwort für diese Aktion begrenzt, und Wissensspeicher werden übersprungen. Eine abgeschnittene Zeichnung wird angezeigt, soweit sie angekommen ist, und eine unbrauchbare Antwort erhält eine zweite Anfrage mit der Benennung des Fehlers und dann eine Direkteingabe-Fallback. Die Registerkarte erhielt eine Schaltfläche Abbrechen, ein Dropdown-Menü Größe von 40 × 20 bis 100 × 50 Zeichen und Schritt-für-Schritt-Statustexte. Abgelehnte Antworten werden zur Diagnose unter ai-answers/ gespeichert. Siehe ASCII art.
  • ASCII-Grafik aus einem vorhandenen Bild – die neue Registerkarte Bilddatei des ASCII-Art-Tools wandelt ein Foto, ein Logo oder ein Symbol auf Ihrem Computer mit demselben Konverter in Zeichen um, den auch die KI-Bilder verwenden: Öffnen Sie ein PNG, JPEG, GIF oder BMP oder legen Sie es auf der Registerkarte ab, wählen Sie die Größe aus, passen Sie Helligkeit und Kontrast an und kehren Sie ein helles Motiv auf einem dunklen Hintergrund um. Der Tonwertbereich wird automatisch gedehnt, sodass Mitteltonfotos nicht zu einem einzigen Graublock werden. Siehe Registerkarte „Bilddatei“.
  • ASCII-Grafik direkt in Code kopieren – die neue Zeile Kopieren als im ASCII-Grafik-Tool stellt jeder Zeile die Kommentarmarkierung Ihrer Sprache voran oder umschließt das Bild in einen Blockkommentar oder ein JSON-String-Array. Außerdem kann jede Zeile in eine fertige Druckanweisung für Bash, Perl, Python, Ruby, PHP, JavaScript, Java, C, C#, Go, Rust, Kotlin, Swift, Lua, PowerShell oder Batch umgewandelt werden, mit den für die Sprache erforderlichen Anführungszeichen und Escapezeichen. Eine Abstand-Einstellung richtet das Bild aus. Siehe In die Zwischenablage kopieren.
  • Das ASCII-Art-Tool, der Guide-Viewer und die Journalfenster werden wieder in der Größe geöffnet, die Sie ihnen gegeben haben – diese Fenster speicherten ihre Geometrie, zeichneten jedoch nie den UI-Schriftmaßstab auf, in dem die Größe gemessen wurde. Sobald also ein anderes Fenster einen anderen Maßstab aufgezeichnet hatte, galt die gespeicherte Größe bei jedem Öffnen als veraltet und nur die Position wurde zurückgegeben. Wenn Sie sie jetzt schließen, wird dieser Datensatz aktualisiert, sodass beim nächsten Öffnen sowohl Position als auch Größe wiederhergestellt werden. Siehe ASCII art.

Frühere Versionen

Hier wird nur die aktuelle Version aufgeführt, daher bleibt der Anleitung in jeder Sprache, in die er übersetzt wurde, kurz. Jede Version ist auf der GitHub-Release-Seite ; Die kuratierten Notizen für frühere Versionen werden im Repository in app-docs/release-notes-archive.md und app-docs/RELEASE_NOTES.adoc aufbewahrt.
