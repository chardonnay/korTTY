# Release notes

What changed in the current release. The version this guide was built for is shown in the footer.

## v2.7.0

### Enterprise policy

- **Administrators can now manage korTTY through a policy file** — a `kortty-policy.toml` in the installation directory (admin-writable only) can restrict servers users may connect to (allow/deny lists with host globs, ports, single IPs, CIDR networks and IP ranges, enforced for terminals, SFTP, QuickConnect, jump hosts and scheduled jobs), disable or restrict features (AI Agent/Chat/Swarm/Planning, Teamwork, plugins, update checks, telemetry, terminal recording), force the master password and host-key verification, confine korTTY to an internal clipboard so text copied in other applications cannot be pasted into korTTY (while copy &amp; paste within korTTY keeps working), control logging (directory, format as text or JSON lines, retention, gzip compression and rotation caps), and preconfigure read-only AI profiles (with encrypted API keys via `korTTY --encrypt-policy-value`), local AI models, script headers and teamwork sources. Rules target individual users, policy-defined groups or OS/AD groups with user &gt; group &gt; everyone precedence; locked settings appear grayed out with a "Managed by your organization" hint, and an invalid policy file puts korTTY into a fail-safe lockdown instead of silently enforcing nothing. See [Enterprise policy](../reference/enterprise-policy.md).

### File browser

- **The menu-bar File Browser was rebuilt as a proper file manager** — the docked sidebar (**View → File Browser**) gained a navigation toolbar (back / forward / up / home / refresh, new folder / file), an editable path bar that can root the tree at any directory including above your home folder, a filter field, type-aware icons with a symbolic-link badge, and a footer that counts the folders, files and selection in the current directory. See [File browser](../features/file-browser.md).
- **Faster and safer to use** — directories load in the background so a large or network-mounted folder no longer freezes the window, refreshing keeps expanded folders open, and you can sort by name, size or date. Inline rename (++f2++), *Copy Path*, keyboard navigation, and dragging files into the panel to copy or move them were added.
- **Delete asks first — Trash or permanent** — deleting an entry now prompts to either move it to the system Trash (reversible) or delete it permanently, instead of silently removing it forever. Copy, move, archive and delete all run in the background so a large folder no longer freezes the window.
- **The panel remembers itself** — its side, width, *show hidden files* state and last directory are restored on the next launch.
- **The SFTP file manager matches the new look** — its toolbar and file-type icons now use the same icon set and styling as the file browser (no change to how it works).

### Jump server (bastion host)

- **Jump server hopping is now implemented** — a connection with an enabled jump server is routed through the bastion: korTTY authenticates to the jump host with its own credentials, opens a tunnel, and opens the real SSH session to the target through it. Previously the Jump Server tab collected host, username and password but discarded them on save and connected straight to the target — a connection could look bastion-routed while going direct. The tab now persists every field (password encrypted with the master password) and adds an authentication selector for password or an unencrypted SSH key file.
- **The bastion is verified, and credentials are kept separate** — the jump host's key goes through the same trust-on-first-use prompt and pinning as any other host, the target is still verified under its own name through the tunnel, and neither host is ever offered the other's password or key. The write-only *Auto-Command* field was removed; a real tunnel supersedes the "type ssh on the bastion" pattern it stood for.
- **SFTP now routes through the jump server too** — file transfer connections hop through the bastion the same way terminal sessions do.
- **Mosh with a jump server is refused up front** — a Mosh session runs over UDP, which the bastion's SSH tunnel cannot forward; previously the SSH bootstrap succeeded and the session then stalled with no data. Connecting now fails immediately with a clear message, and the Jump Server tab warns as soon as the combination is configured. SFTP for such connections still routes through the bastion.

### SSH host-key verification

- **Opt out of host-key verification, per connection, per group, or globally** — for lab or throwaway hosts, korTTY can accept an unknown host key without the first-use prompt. It is an **accept-new** relaxation, not blind trust: a key that differs from one already pinned for that host is still hard-blocked, so a man-in-the-middle on a host you have connected to before is still caught. The three scopes resolve in precedence order — a per-connection override (Connection Manager editor and Quick Connect: *Use default* / *Verify* / *Don't verify*) wins over a per-group toggle (right-click a group → *Disable host key verification*), which wins over the global **Settings → Terminal → Disable host key verification for all connections**. Off by default. A jump server's own host key is always verified strictly, regardless of the target's setting.

### Master password

- **Optional passwordless auto-login for test environments** — a new **Configuration → Global Settings → Security → Disable master password prompt on startup** option makes korTTY remember the master password (stored only obfuscated, with owner-only permissions, in `~/.kortty/master.autounlock`) and unlock the vault automatically at startup, so encrypted data such as AI profiles and SSH passwords stays usable with no prompt. On a brand-new profile it even sets up a default password so the app can start with zero input. It is insecure by design — the file permissions are the only protection — and meant for throwaway/test setups such as a VM: korTTY asks you to confirm before enabling it, keeps a warning visible while it is on, and an enterprise policy that forces the master password overrides it. Off by default.

### Guide translation

- **The offline guide can now be translated by a local AI profile** — **Configuration → Global Settings → Translation → Guide translation** translates the bundled offline guide (the same site this documentation is part of), including its in-page search, into the target language chosen above, using an AI profile rather than the translation-provider API. Translation runs in the background: it keeps going after Settings is closed, shows a progress bar, percentage and time-remaining estimate at the right end of the menu bar, can be cancelled and resumed without losing progress, and korTTY asks before quitting while it is running. After an update that changed the guide, korTTY offers once to bring an existing translation up to date, re-translating only what actually changed. See [Translation](../reference/settings/translation.md#guide-translation).
- **Estimate duration before committing to a full translation** — a new **Estimate duration** button measures the chosen AI profile against a real sample of the guide and projects how long translating everything remaining would take, without waiting out the full run.
- **A warning appears before translating with a reasoning model** — such models spend most of their output "thinking" rather than translating, which can turn a translation that takes about an hour into one that takes six or more; korTTY detects this from the model's name and warns before starting or estimating, while still allowing you to proceed.

### Interface translation

- **Any AI profile can now translate the interface strings** — the **Local AI text profile** provider gained its own **AI profile** dropdown, matching the one the guide translation already had. A profile picked there is used whatever its connection mode, so a cloud model (Anthropic, an OpenAI-compatible endpoint) or a local CLI profile can generate a language pack, not only an embedded llama.cpp/MLX model. Leaving it on **Default (local text profile)** keeps the previous behaviour: the Text-role profile, and only when it runs a local model — the provider exists for people who do not want their interface strings leaving the machine. When that role holds a cloud or CLI profile, korTTY now names the profile and points at the dropdown instead of reporting a bare "failed to generate language file". See [Translation](../reference/settings/translation.md#local-translation).
- **A malformed batch no longer throws away the whole language pack** — previously one bad reply from the model aborted language-file generation completely and nothing was written at all, even though most strings had translated. The batch is now retried and split in half, and only a string the model never returns in usable form keeps its English text.

### ASCII art

- **AI-drawn ASCII pictures** — the ASCII art tool (**Tools > ASCII Art...**) gained an **AI Picture** tab: type a subject such as "house" and a model draws it as an ASCII picture, constrained to printable ASCII within 60 columns and 30 lines so it stays readable. **New variation** redraws the same subject with a different treatment — viewing angle, level of detail, line style, scene context or proportions — asking for something different again on each retry, and a transient profile picker lets a single run use a different AI profile without changing your default.
- **Zoomable preview** — both tabs share one zoom level, adjustable with the **+** / **−** / **⟲** buttons, ++ctrl+plus++ / ++ctrl+minus++ / ++ctrl+0++, or ++ctrl++ and the scroll wheel over the preview. The level ranges from 50 % to 333 % and is remembered between sessions along with the window position and size.
- **Two tabs instead of one form** — the FIGlet banner generator moved into its own **Text Banner** tab, so a banner and a picture keep their own result while you switch, and **Copy to Clipboard** copies whichever tab is open.
- **Fixed: the Lean font was missing from packaged builds** — the style was declared in lowercase while the bundled file is `Lean.flf`, so JAR resource lookup dropped it from the style list on case-sensitive filesystems.

### Dashboard

- **Redesigned dashboard panel** — the side panel (++ctrl+shift+d++) got a full visual and interaction overhaul: a clear panel boundary with its own background, a header with the panel title plus collapse/expand-all and refresh icon buttons, node-type icons for main window, environment, group and connection rows, and bold section rows with dimmed active/total counts. Rows respond to hover and selection (accent stripe), tooltips show `user@host` and the connection state, and ++enter++ or double-click focuses the session.
- **Three-state status dots and protocol badges** — each connection row shows a filled green dot while connected, a filled red dot when the connection dropped unexpectedly (including Mosh network interruptions), and a hollow outline after a session ended normally; the old text-glyph status is gone. A small `ssh` / `mosh` / `local` badge identifies the transport.
- **Environment grouping** — ungrouped connections cluster under the environment of their stored credential (Production, Development, Test, Staging or custom), so multi-stage work stays visually separated.
- **Content-sized, animated panel** — the dashboard sizes its width to the longest entry (bounded), animates open and closed instead of popping in, shows a placeholder when no session is open, and reports "connected of total" in a footer. Its colors follow the active App Design, including per-design status-dot palettes.
- **Context menu and group fixes** — the connection context menu adds **Focus** and icons for every action. Tabs opened via "open whole group" now correctly appear under their group, and changing a connection's group in the Connection Manager updates open tabs immediately.

### Tool windows as tabs

- **Management tools can open as tabs in the main window** — a new **Open tool windows as tabs** option in [Window settings](../reference/settings/window.md) makes Snippets, the JobScheduler, the AI Manager, Saved Chats, Credential/GPG/SSH key management, the Video Manager, Teamwork settings and the Terminal Effects manager open as tabs beside your terminal sessions instead of separate windows. The tab always opens in the main window whose menu you used, so with several windows open each collects its own tools — for example the AI Manager as a tab in one window and the JobScheduler in another. Reopening a tool focuses its existing tab, while the snippet editor and the AI code analysis open a new tab per snippet/run so several can sit side by side; tool tabs can be reordered and dragged between windows like any other tab. Off by default — nothing changes unless you enable it.

### Power management

- **Activity-based power management** — macOS App Nap is suppressed while a Scheduler job, AI request, or terminal input/output is active (with a 60-second terminal-activity tail). Background windows park periodic status updates and design animations, and the Scheduler owns no polling timer when no enabled future run exists. On macOS, system-sleep prevention is delegated to a separate `caffeinate` helper so the korTTY process remains eligible for App Nap. On macOS and Windows, **Configuration > Prevent System Sleep** keeps the computer awake only while a terminal is connected, a future or running Scheduler job exists, or an AI request is active; with none of these activities, system sleep remains available even while the persistent setting is checked. Display sleep is unaffected, and Linux shows the option as not yet supported.

### Snippet editor

- **Code language and Text language are now two labelled fields** — the snippet editor's **Language** field was renamed to **Code language**, and the AI text-language picker moved up from below the toolbar to sit directly beneath it as **Text language**. Both describe the snippet itself: one the programming language and syntax highlighting, the other the natural language korTTY writes into the code (comments, user-facing strings, spelling).
- **TypeScript is selectable** — TypeScript joins the code-language list, with its own `.ts` extension, Monaco highlighting and Prettier formatting (the formatter already supported it, but no snippet could be marked as TypeScript).
- **Add your own code languages** — a **+** button beside the code-language list takes any language name that is missing and stores it permanently, so it is offered in every future snippet editor. Self-added languages drive the AI prompts and the file extension; highlighting falls back to plain text when korTTY ships no grammar for them.
- **AI suggestion fills both language fields** — besides the file name and description, **AI suggestion** now also detects the natural language of the snippet's comments and printed output (`echo`, `print`, `printf`, `Write-Host`, …) and preselects it as the text language, adding it to the list when korTTY has no interface translation for it. A detected code language missing from the list is likewise added instead of being silently dropped.
- **New AI action: Optimize code comments** — available from the **AI Code** menu and from the editor's right-click menu on a selection. The AI inserts explanations of what the selected code does and why, directly above or beside the lines they belong to and in the language's own comment syntax, replaces outdated or misleading comments, and leaves every executable line untouched. Comments are written in the editor's **Text language**, and the result is shown in the usual before/after preview before it replaces the selection.
- **Automatic analysis diagrams can be switched off** — the Full Code Analysis window's diagram pane gained a **Generate automatically** checkbox. Untick it and the flow diagram's dedicated AI request no longer starts when the window opens; the pane shows a hint instead and **Regenerate** requests the diagram on demand. The choice is remembered across sessions.

### Input hardening

- **New: the AI can build input validation directly into your scripts** — every AI script flow (Full code analysis, Improve robustness, Custom improvement, and both workflow-script generators) gained an opt-in **Input hardening** panel. When enabled, the AI adds a guard block at the top of the generated or rewritten script that validates every parameter (count, character allowlists, length limits, rejection of shell metacharacters), checks input files before use (existence, text-vs-binary format, and a size limit generated as an adjustable `KORTTY_MAX_FILE_SIZE` script variable, 10 MB by default), and reports every violation as a timestamped `SECURITY:` warning on stderr and in the script's own log file. Violations stop the script with documented exit codes (64/65/66) unless a run is deliberately forced with `KORTTY_FORCE=1` — which still logs the bypass. korTTY itself performs no validation at run time: the guard is ordinary script code, so it protects every future run of the script, wherever it is started. **All**/**Clear**/**Save** manage the five sub-options, and **Save** remembers your selection and size limit as the default. See [Input hardening](../reference/input-hardening.md).

### AI Manager

- **korTTY now ships 39 built-in best-practice AI skills** — professional coding conventions (commenting, robustness, pitfalls to avoid, security) for Bash, KornShell, Zsh, Csh, POSIX sh, PowerShell, Python, C, C++, Java, C#, JavaScript, Visual Basic, SQL, R, Rust, Go, PHP, Swift, Assembly, Macro Assembler, Ruby, Perl, Lua, Groovy, TypeScript, Kotlin, Dart, HTML, XML, YAML, JSON, Puppet, Ansible, Azure DevOps Pipelines, Jenkins Declarative and Scripted Pipelines, Filebeat and Logstash are added to the skill library on first start and picked automatically by the relevance detection. The library has a search field and shows total/active/inactive counts. Built-ins can be edited, deactivated and hidden but not deleted; unmodified ones update silently with new releases, modified ones show 🔄 *Update available* with one-click *Update to latest shipped version* and *Reset to shipped version*. A personal skill tagged with the same topic (e.g. `perl`) always takes precedence — the built-in is then grayed out as *Overridden by user skill* until your skill is removed or deactivated. Switching off skill auto-detection deactivates all built-ins (after confirmation) so prompts never bloat. See [AI Skills](../reference/settings/ai-skills.md).
- **The AI Skills library moved into the AI Manager** — the skill list, Markdown editor, import/export and the two global toggles (*Enable AI Skills*, *Automatically send only matching skills*) are now the **AI Skills** section of **AI → AI Manager**, next to profiles, local models and knowledge stores; the tab of the same name in **Configuration → Global Settings** and the *AI Skills…* button in the profile toolbar are gone. Skills are stored unchanged in `~/.kortty/global-settings.xml`, and a **Save** button writes them right away while pending edits are also saved when the manager window is closed. See [AI Skills](../reference/settings/ai-skills.md).

### Integrated local AI

- **The log shows the reasoning level and the model's own errors** — every `AI request sent` / `AI request failed` line now carries `reasoningEffort=`, the level the request actually uses, so the log no longer leaves you guessing which setting was in effect. Failures append the server's own error text plus each nested `caused by:` message, a refused connection test logs its reason instead of vanishing behind a boolean, and a reasoning level the model does not offer is reported as a warning naming the configured level, the substitute used and the levels actually available — previously that downgrade happened silently.
- **MLX replies no longer starve reasoning models of their answer** — korTTY now sends an explicit generous completion budget (`max_tokens`) with every request to the embedded MLX runtime. `mlx_lm.server` silently caps requests without that field at 512 completion tokens, which reasoning models such as gpt-oss spent entirely on their chain-of-thought during complex tasks like the Full code analysis — the reply then contained no answer at all and both automatic attempts failed with "spent its whole reply on reasoning". Generation still ends at the model's stop token, so short replies are unaffected.
- **The Full code analysis window remembers its size and position** — resize or move the KI-Code-Analyse window and korTTY restores that geometry the next time you open it, including after a **Re-run**.
- **Correct analysis flowcharts on the first try** — the Full code analysis window now fetches its flow diagram with a separate, diagram-only AI request instead of asking the model to return the report and the Mermaid flowchart in one combined answer. Especially with local models the combined request often degraded the diagram to a linear chain of steps that ignored the script's real branching, and only a manual **Regenerate** click fixed it. The report now opens as soon as the text analysis is ready while the diagram pane loads its dedicated request under a spinner, so the first diagram already has Regenerate quality.
- **One update policy for both runtimes** — the Local AI **Runtime updates** setting (Off / Notify me / Install stable updates automatically) now governs the MLX runtime as well as llama.cpp. At startup and on save, korTTY checks the MLX runtime's signed stable index under the same policy: Notify me shows an update popup only when an MLX runtime is installed, and Automatic installs the newest signed MLX package once idle. A signed MLX withdrawal is now enforced after the fact too — the active pointer is cleared, sidecars stop, and the withdrawn id is denylisted so it can never be reinstalled — closing the gap where a revoked MLX runtime could keep running until the next manual install.
- **Runtime overview with removal and verified local import** — a Runtimes table in Local Models shows both embedded runtimes (llama.cpp and, on Apple Silicon, MLX) with their installed version, backend, and Ready/Not-installed/Revoked state. Per runtime, users can install or update from the signed stable channel (MLX now installs in-app from the rolling `mlx-stable` index), remove the runtime (idle-only; the revocation denylist survives), or import a local package file that is accepted only when its SHA-256 matches a non-revoked entry of the Ed25519-signed index — verified local packages run through the identical installation machinery as downloads.
- **MLX models on Apple Silicon** — on Apple Silicon Macs, the Local Models manager additionally searches, downloads, registers, and runs [MLX](https://github.com/ml-explore/mlx) models through the official `mlx_lm.server`, wrapped in korTTY's own authenticated loopback-only launcher with offline Hugging Face access, sanitized process environment, and idle self-exit. A new **Integrated MLX (Apple Silicon)** profile connection selects the installed model; the runtime ships as a separately signed package (pinned relocatable CPython plus hash-locked mlx-lm wheels) built by a new CI pipeline, with a developer script for unsigned local packages. MLX repositories download as complete verified directories — SHA-256 for LFS files and the git blob hash for small in-tree files — and reasoning models get the same inline chain-of-thought separation as GGUF models.
- **A real choice of embedding models** — the bootstrap catalog (`bootstrap-v2`) adds four embedding recommendations alongside the default Qwen3-Embedding 0.6B `Q8_0`: Qwen3-Embedding 4B `Q4_K_M` (from 16 GiB RAM), Qwen3-Embedding 8B `Q4_K_M` (from 24 GiB), the multilingual BGE-M3 `Q8_0`, and the very small, fast Nomic Embed Text v1.5 `Q8_0`. Each role slot in the setup assistant now offers every catalog model the detected memory supports — preferred default preselected — instead of exactly one fixed suggestion per role.
- **Sortable, hardware-filtered Hugging Face browser** — every column of the model search sorts ascending/descending with a header arrow (sizes and context numerically, hardware estimate from best to worst), and results are limited to repositories this computer can actually run: rows without size metadata or beyond the detected memory stay hidden while korTTY completes the listing with exact per-repository metadata in the background, and the status line reports the shown/hidden counts. On Apple Silicon a format selector switches between GGUF, MLX, and both, with a Format column identifying each row.
- **Action-bar icons** — every button in Local Models (install, setup assistant, import, configure, set as default, start, stop, remove, refresh, search, load more, download, pause/resume, cancel) now carries a matching glyph, consistent with the other AI Manager tabs.
- **Default local model marker** — one installed model can be marked as the default with **Set as default** (action bar or right-click menu); it shows a leading ★ in the Name column and is pre-selected when the manager opens, so Start/Configure/Stop target it by default. **Clear default** removes the mark. It is a manager convenience only and does not change which AI profile the agent or chat uses.
- **Tighter Local Models tables** — the installed-models table no longer stretches the short Purpose, Backend, Unload-after, and Status columns across the row; they are capped near their content width (never wider than ~30 characters) so the Name and file columns keep the space. Across every Local Models table, hovering a cell whose text is clipped by the column now shows the full value in a tooltip.
- **Robust local reasoning replies (including gpt-oss)** — the pinned llama.cpp server occasionally answers a whole reply with HTTP 500 (“does not match the expected peg-native format”, e.g. from the snippet code-analysis actions or the terminal agent); korTTY now retries a local server error, an empty reply, or a reasoning-only reply once automatically, and defensively separates any inline chain-of-thought (both `<think>` and gpt-oss harmony `<|channel|>` markers) from the answer. Chat sidecars keep the server's default reasoning parsing rather than disabling it, because harmony/channel models such as gpt-oss require that parsing to emit a final answer at all — with it disabled they got stuck after their analysis channel and returned no answer (which broke the terminal agent for gpt-oss). The terminal agent also now explicitly reads an unseen file with a `cat`/`head` command before acting, instead of reporting the content as unavailable.
- **Separated reasoning is shown, not hidden** — when a local reasoning model (both `<think>` and gpt-oss harmony models) returns its chain-of-thought inline, korTTY keeps the answer clean and offers the reasoning behind a collapsible **Reasoning** disclosure below the reply in the AI chat panel. In the terminal AI-agent window the same reasoning already appears under each *Thinking* step and can be expanded or collapsed with its pull bar.
- **Reasoning level persists for embedded profiles** — choosing a reasoning level for an Integrated llama.cpp / MLX profile is now saved reliably. Previously it could intermittently reset to Disabled because the reasoning-discovery cache was keyed by connection fields (apiUrl / CLI provider) that are unused placeholders for an embedded profile; embedded profiles are now keyed by their pinned model, so a discovered level is kept across save and reload.
- **The AI Manager keeps the reasoning level you picked** — selecting a profile in the AI Manager reset its **Reasoning** setting to *Disabled*, and closing the dialog then saved that reset over the stored value, so the level could never be kept. Filling the connection, URL and model fields while loading a profile fired their change listeners, and each of those rebuilt the reasoning options from the half-populated form and wrote the result back into the profile. Loading no longer writes back; only a real pick does.
- **Choose where the terminal agent's answer appears** — the agent run dialog adds a **Show final answer in the terminal too** option. Leave it on to keep mirroring the final answer into the terminal (unchanged behavior), or turn it off so the answer stays only in the AI agent activity panel; commands still run and any files they create stay on the server. The last choice is remembered.
- **AI request and model-lifecycle logging** — `kortty.log` now records when an AI request is submitted and when it completes or fails (`AI request sent` / `AI request done` / `AI request failed`), with the action, provider, model, approximate input size, duration and token count — metadata only, never the prompt or response text. Embedded llama.cpp and MLX models additionally log when a model is loaded, unloaded after the idle timeout (sleeping), or unloaded because its sidecar stopped. All are `INFO` lines visible at the default log level, so it is easy to see whether the AI is doing anything and which model handled a request.
- **Runtime-update notification only when installed** — the startup notification about an available llama.cpp runtime appears only when a runtime is actually installed; without one (never installed or removed), the available package is listed in Local Models without a popup.
- **Private GGUF inference without LM Studio or Ollama** — AI profiles can use an installed **Integrated llama.cpp** model. korTTY launches one authenticated loopback-only sidecar per compatible GGUF configuration, shares it through request leases, supports several different models concurrently, reports the complete loading/busy/sleep/failure lifecycle, and unloads tensors after a configurable 1–1,440 minute idle period (10 minutes by default) or never.
- **Direct local-profile selection** — choosing **Integrated llama.cpp** in an AI profile now shows a dedicated **Local GGUF model** selector. It lists installed chat models and persists the selected registry ID, so no local API URL or manually entered model name is required.
- **Hugging Face model manager and beginner assistant** — **AI > AI Manager > Local Models** searches GGUF repositories with architecture, quantization, license, selected-quantization size, context and hardware estimates; cursor pagination keeps earlier matches when **Load more** is selected. Selecting a result loads exact file metadata on demand at its immutable revision, preserves the chosen quantization while refreshing the size and hardware estimate, and excludes projector, quantization-matrix and speculative-decoding helper GGUFs from language-model downloads. After the license/size confirmation, a fixed bottom panel identifies the repository, quantization, file/shard and transferred bytes, and reports elapsed time, adaptive transfer rate and remaining time beside pause/resume/cancel controls. Immutable downloads retain resumable `.part` data on cancellation or manager close and use Range/If-Range, free-space, multipart and SHA-256 checks; imports use managed copies or external references; and new registrations start with a conservative 4,096-token runtime context. The six-step beginner flow offers independently optional Text, Coding, and embedding slots, asynchronously verifies the fixed revision/quantization/license/exact size, installs the runtime and GGUFs without freezing JavaFX, runs a real chat or embedding test for every model, and persists the role assignments only after all tests pass.
- **Text/Coding roles and model prompt presets** — separate Text/translation and Coding profile assignments fall back safely through explicit/security/connection choices to the default. Auto or forced Llama, Qwen, Mistral, Gemma, DeepSeek, Phi, GPT-OSS presets improve small/local-model format compliance without weakening strict JSON, code-payload or safety contracts. Dynamic interface translation can use the local Text profile without a translation-provider API key.
- **Separately signed recommendation and preset catalog** — a strict-schema model/prompt catalog is promoted manually from a reviewer-protected signing environment as immutable JSON plus detached Ed25519 signature. A monotonic sequence blocks signed older replays and sequence/version collisions in the application and must increase across official promotions. The nine bootstrap recommendations include concrete 40-character Hugging Face commits rather than mutable heads. The last valid cache is reverified and refreshed once in the background; a missing trust root disables network and cache trust and keeps the built-in bootstrap available offline.
- **Modeless AI Manager with persistent navigation** — the manager can remain open while the main window stays usable, and invoking it again restores and focuses the same instance instead of opening a duplicate. A bold accent underline continues to mark the open section—Profiles, Local Models, Knowledge Stores, Local AI, Saved Chats, or Swarm Chats—after focus moves into a table, search field, or action button.

### RAG knowledge stores

- **Reviewed files and folders instead of HNSW configuration** — the Knowledge Stores tab creates a local cosine HNSW store and scans individual files or recursive directories asynchronously against a fixed text allowlist before showing a confirmable preview. It counts accepted/unchanged/changed files, lists skipped entries with reasons, supports per-source Automatic/Manual synchronization, and provides cancel/disable/remove/update/test-search actions while rejecting overlapping scan/index jobs. Binary/non-UTF-8 data, protected or image-only PDFs, unsupported formats, symbolic links, hidden/build/dependency paths and overlapping sources are rejected or skipped explicitly.
- **Incremental, failure-safe hierarchical indexing** — only content-hash changes are re-chunked into approximately 800-token excerpts with 120-token overlap and embedded through the selected local model. Candidate multi-layer HNSW v2 snapshots are flushed and atomically activated; legacy v1 snapshots migrate on open, and cancellation or a fatal scan/embedding error preserves the previous graph. A source root that was actually deleted instead atomically removes its stale chunks and becomes **MISSING**. Startup reconciliation catches Automatic-source changes made while korTTY was closed, while persisted status, hash, file/chunk/problem counts and completion summaries keep the UI informative across restarts. Qdrant is available as an optional second backend.
- **Bounded untrusted retrieval with citations** — role-matched stores contribute at most six excerpts, two per source, 4,000 tokens and 25% of the model context. Excerpts are escaped inside `<retrieved_context>` with stable `[R1]` source markers after action/skill instructions and before the model preset; the full store is never sent, but explicitly assigning a cloud profile permits those retrieved excerpts to leave the computer. Agent, Planning, Swarm and scheduled autonomous flows require explicit opt-in.

### Local-AI runtime and backup lifecycle

- **Independently updated, revocation- and rollback-safe llama.cpp packages** — korTTY CI detects candidate pins while the public [llama.cpp runtime repository](https://github.com/chardonnay/kortty-llama-runtimes) rebuilds the exact reviewed commit, runs the complete CPU/Metal/Vulkan platform matrix plus authenticated chat, embeddings, JSON schema, sleep/wake, parallel-sidecar and pinned-Qdrant smokes, and signs only after protected human promotion. The public Ed25519 trust root is pinned in the application source. The Local Models manager installs or updates the preferred backend (Metal first on macOS, CPU first elsewhere with Vulkan fallback), while startup policy supports Off/Notify/Automatic Stable. Verified withdrawals persist a denylist and package quarantine marker, stop/rebind affected sidecars and remove unsafe rollback candidates; new packages activate only while idle and remain pending until the first real GGUF/API start, whose failure restores the newest healthy non-revoked version. The two newest confirmed healthy versions remain available.
- **Interactive SSH/SFTP/Mosh host-key trust** — a shared `~/.kortty/ssh-host-keys.properties` store pins each normalized host and port with an OpenSSH SHA-256 fingerprint. First use is denied until the user confirms the fingerprint; a changed key is hard-blocked without an authentication retry. The store is atomically merged across processes and included in encrypted backups, while JobScheduler's separate unattended host-key pins remain unchanged.
- **Terminal and diagnostics hardening** — the SithTermFX bottom-row hyperlink boundary is patched and regression-tested, split handshakes stay off the JavaFX thread, and test logging no longer writes negative-case stack traces into a developer's live `~/.kortty/logs` directory. Runtime-install failures now retain complete causes and stack traces in `kortty.log`.
- **Portable configuration without giant backups** — encrypted backups include local-model registrations, Text/Coding/RAG settings, and knowledge-source metadata, while excluding GGUF weights, native runtimes, temporary sidecars, original documents and regenerable HNSW snapshots. The guide adds complete local-model, RAG, security, installation, packaging and recovery documentation plus a new indexing/retrieval diagram.

### Release and packaging

- **Reliable Linux package validation** — package-size checks now understand the standard Linux jpackage `lib/app` and `lib/runtime` layout, so the application JAR and bundled JVM are validated instead of being reported as missing.
- **Reliable Windows artifact preparation** — the release workflow resolves the jpackage directory explicitly and discovers the Windows launcher within the generated app image before creating the portable archive.
- **Dependency and CI maintenance** — updated CodeQL Actions, Apache MINA SSHD and Bouncy Castle, Logback, and Apache PDFBox dependencies.

### Local terminal fixes

- **Local shells now keep the real working directory** — after `cd`, `pushd`, `popd`, or `Set-Location`, **Open in Snippet Editor** and local AI Agent runs use the interactive shell's current directory, including paths with spaces or Unicode. The directory is refreshed from the shell process on macOS/Linux or an absolute native PowerShell/cmd prompt on Windows, and unsafe or foreign path fallbacks stop with a clear error instead of opening or overwriting a same-named file in the start directory.
- **Pasted text is retained in terminal agent requests** — typed text and clipboard paste now share one connector-level input filter for SSH and local shells. Plain paste, bracketed paste, split UTF-8 input, Backspace, and Ctrl+U are tracked correctly; the complete request is saved to agent history and Enter dispatches it exactly once.

### Snippet AI fixes

- **Selection translation and spelling correction no longer fail on small local reasoning models** — the snippet editor's *Translate selection…* and *Correct spelling in selection* actions were attaching your enabled AI skills to the request. On a compact local reasoning model (for example a quantized Phi-4-mini reasoning build) the extra prompt bulk could make the model spend its whole reply on internal reasoning and return no answer (*"the local AI model produced no answer"*). These two mechanical text transforms no longer attach AI skills, keeping the prompt small so the model answers.
- **A long AI request is no longer cut off after three minutes** — a request through a provider CLI, or through LM Studio's native API with an MCP internet mode, aborted after a hardcoded 180 seconds (Anthropic profiles after 120), which was easy to hit with the snippet editor's *Full code analysis* on a large snippet. korTTY no longer imposes any timeout of its own; requests run until the model answers. If you do want a limit, set one yourself in **AI → AI Manager → Profiles**: **AI request timeout** in minutes applies to every profile, and **Timeout for this profile** overrides it for a single profile — including setting it to 0 so that one profile never times out. See [AI settings](../reference/settings/ai.md).
