# Release notes

What changed in the current release. The version this guide was built for is shown in the footer.

## v2.8.0

### Session journal

- **Terminal sessions can now document themselves** — a new [session journal](../features/session-journal.md) records server output and typed commands into a per-session capture log (JSON Lines by default, XML or YAML on request; rotated parts are compressed, never deleted) and lets an AI condense the activity into a readable timeline with a closing session summary. Enable it per connection on the new **Journal** tab of the connection editor, or retroactively for a running session — the existing scrollback is imported. Typed passwords are kept out of the journal: password prompts suppress the following input line and the connection's own stored credentials are redacted.
- **A journal bar below the terminal** shows the journal state and adds screenshots (also from the terminal's right-click menu, capturing exactly the split pane under the cursor) and free-text notes to the timeline.
- **The journal page is a self-contained HTML timeline** — connection header with statistics, day grouping, color-coded input/output excerpts, marker badges, screenshot lightbox, and a slide-in log panel with search, match counter and prev/next navigation. It renders in the built-in viewer, any browser, and inside the exported bundle, in light and dark.
- **Search the whole journal** — the magnifier in the page header (or ++ctrl+f++) opens a search bar under the connection details that highlights a term or a whole sentence across every entry title, summary, excerpt and note, with a match counter and prev/next navigation.
- **A copy button on every entry** — text entries copy in full, screenshot entries copy the image, and the log panel copies the section it shows. Right-click adds more targeted actions: the selected text, only an entry's summary, or a screenshot's path.
- **Adjustable page font size** — the **A−** / **A** / **A+** buttons scale the whole journal page, and korTTY remembers the size for every journal it renders. Screenshots, excerpt panels and the log panel size themselves to the window, so the page stays readable in a narrow tool tab as well as full screen.
- **Tools > Session Journals…** manages all journals: search (optionally through journal contents), per-journal descriptions, renaming and deleting with confirmation, marker/note editing in the viewer, and export as PDF (with downscaled embedded screenshots), Markdown or a complete HTML bundle.
- **Bulk delete and bulk export** — select several journals to remove them in one step or write them into a single zip archive that keeps each journal separate. Any archive, including a single HTML bundle, can be **encrypted with AES-256** behind a password of your choice, because journals hold full terminal transcripts.
- **Exports carry their provenance** — PDF, Markdown and the bundled journal page state by default that they were created with korTTY and link to the project repository.
- **Sensitive content can be removed after the fact** — the viewer's edit mode now also edits an entry's title and summary, deletes a whole entry (including its screenshot file), and offers **Search & replace**, which rewrites a text such as a leaked password everywhere in the journal: all entries *and* every capture-log part, compressed ones included. It takes a literal text or a regular expression (with `$1` group references), can ignore case, can spare the raw log, and **Count matches** does a dry run over the real journal first. The page's search bar gained a **Replace…** button that opens it with the current search term — inside korTTY only, since a page opened standalone in a browser cannot rewrite the journal.
- **Administrators can redact automatically** — a new `[[rule.session-journal.replace]]` policy list applies search-and-replace to every journal, with regular expressions, for things like cloud access keys or internal hostnames. The rules run before a line is written, so a matching text never reaches the log at all, and they cover AI summaries and notes too. They merge across policy tiers instead of the highest tier winning, so a narrower rule can only add patterns, never switch the organization-wide ones off. See [Enterprise policy](../reference/enterprise-policy.md#rulesession-journalreplace).

### Export appearance

- **A new Export settings page** ([Configuration → Global Settings → Export](../reference/settings/export.md)) controls how exported documents are branded, for session journals and AI chats alike: the footer is on by default and its text can be changed or switched off entirely, and an optional diagonal PDF watermark — off by default — can carry your own text in a colour you choose. A custom text is used verbatim; only the built-in texts append the repository link.
- **Fixed: the AI chat PDF watermark was drawn off the page.** It applied the page-centre offset twice and ended up clipped in a corner instead of running diagonally across the page.
- **AI summarization is configurable** — interval, evaluation window (a line limit, or `0` to fill the model context within a token budget) and an optional chunked mode that processes the whole backlog across multiple prompts (with a clear long-runtime warning). Without an available AI the journal still records raw activity entries.
- **Enterprise policy support** — administrators can deny the feature, enforce journals for every connection, fix the log format, evaluation window and storage directory, forbid renaming/deleting, prescribe a title template and enforce an AI-generated closing title via the new `[rule.session-journal]` table. See [Enterprise policy](../reference/enterprise-policy.md#rulesession-journal).

### Master password

- **Optional passwordless auto-login for test environments** — a new **Configuration → Global Settings → Security → Disable master password prompt on startup** option makes korTTY remember the master password (stored only obfuscated, with owner-only permissions, in `~/.kortty/master.autounlock`) and unlock the vault automatically at startup, so encrypted data such as AI profiles and SSH passwords stays usable with no prompt. On a brand-new profile it even sets up a default password so the app can start with zero input. It is insecure by design — the file permissions are the only protection — and meant for throwaway/test setups such as a VM: korTTY asks you to confirm before enabling it, keeps a warning visible while it is on, and an enterprise policy that forces the master password overrides it. Off by default.

### Guide translation

- **The offline guide can now be translated by a local AI profile** — **Configuration → Global Settings → Translation → Guide translation** translates the bundled offline guide (the same site this documentation is part of), including its in-page search, into the target language chosen above, using an AI profile rather than the translation-provider API. Translation runs in the background: it keeps going after Settings is closed, shows a progress bar, percentage and time-remaining estimate at the right end of the menu bar, can be cancelled and resumed without losing progress, and korTTY asks before quitting while it is running. After an update that changed the guide, korTTY offers once to bring an existing translation up to date, re-translating only what actually changed. See [Translation](../reference/settings/translation.md#guide-translation).
- **Estimate duration before committing to a full translation** — a new **Estimate duration** button measures the chosen AI profile against a real sample of the guide and projects how long translating everything remaining would take, without waiting out the full run.
- **A warning appears before translating with a reasoning model** — such models spend most of their output "thinking" rather than translating, which can turn a translation that takes about an hour into one that takes six or more; korTTY detects this from the model's name and warns before starting or estimating, while still allowing you to proceed.

### Interface translation

- **Any AI profile can now translate the interface strings** — the **Local AI text profile** provider gained its own **AI profile** dropdown, matching the one the guide translation already had. A profile picked there is used whatever its connection mode, so a cloud model (Anthropic, an OpenAI-compatible endpoint) or a local CLI profile can generate a language pack, not only an embedded llama.cpp/MLX model. Leaving it on **Default (local text profile)** keeps the previous behaviour: the Text-role profile, and only when it runs a local model — the provider exists for people who do not want their interface strings leaving the machine. When that role holds a cloud or CLI profile, korTTY now names the profile and points at the dropdown instead of reporting a bare "failed to generate language file". See [Translation](../reference/settings/translation.md#local-translation).
- **A malformed batch no longer throws away the whole language pack** — previously one bad reply from the model aborted language-file generation completely and nothing was written at all, even though most strings had translated. The batch is now retried and split in half, and only a string the model never returns in usable form keeps its English text.

### Tool windows as tabs

- **Management tools can open as tabs in the main window** — a new **Open tool windows as tabs** option in [Window settings](../reference/settings/window.md) makes Snippets, the JobScheduler, the AI Manager, Saved Chats, Credential/GPG/SSH key management, the Video Manager, Teamwork settings and the Terminal Effects manager open as tabs beside your terminal sessions instead of separate windows. The tab always opens in the main window whose menu you used, so with several windows open each collects its own tools — for example the AI Manager as a tab in one window and the JobScheduler in another. Reopening a tool focuses its existing tab, while the snippet editor and the AI code analysis open a new tab per snippet/run so several can sit side by side; tool tabs can be reordered and dragged between windows like any other tab. Off by default — nothing changes unless you enable it.

### Input hardening

- **New: the AI can build input validation directly into your scripts** — every AI script flow (Full code analysis, Improve robustness, Custom improvement, and both workflow-script generators) gained an opt-in **Input hardening** panel. When enabled, the AI adds a guard block at the top of the generated or rewritten script that validates every parameter (count, character allowlists, length limits, rejection of shell metacharacters), checks input files before use (existence, text-vs-binary format, and a size limit generated as an adjustable `KORTTY_MAX_FILE_SIZE` script variable, 10 MB by default), and reports every violation as a timestamped `SECURITY:` warning on stderr and in the script's own log file. Violations stop the script with documented exit codes (64/65/66) unless a run is deliberately forced with `KORTTY_FORCE=1` — which still logs the bypass. korTTY itself performs no validation at run time: the guard is ordinary script code, so it protects every future run of the script, wherever it is started. **All**/**Clear**/**Save** manage the five sub-options, and **Save** remembers your selection and size limit as the default. See [Input hardening](../reference/input-hardening.md).

### Snippet AI fixes

- **Selection translation and spelling correction no longer fail on small local reasoning models** — the snippet editor's *Translate selection…* and *Correct spelling in selection* actions were attaching your enabled AI skills to the request. On a compact local reasoning model (for example a quantized Phi-4-mini reasoning build) the extra prompt bulk could make the model spend its whole reply on internal reasoning and return no answer (*"the local AI model produced no answer"*). These two mechanical text transforms no longer attach AI skills, keeping the prompt small so the model answers.
- **A long AI request is no longer cut off after three minutes** — a request through a provider CLI, or through LM Studio's native API with an MCP internet mode, aborted after a hardcoded 180 seconds (Anthropic profiles after 120), which was easy to hit with the snippet editor's *Full code analysis* on a large snippet. korTTY no longer imposes any timeout of its own; requests run until the model answers. If you do want a limit, set one yourself in **AI → AI Manager → Profiles**: **AI request timeout** in minutes applies to every profile, and **Timeout for this profile** overrides it for a single profile — including setting it to 0 so that one profile never times out. See [AI settings](../reference/settings/ai.md).
