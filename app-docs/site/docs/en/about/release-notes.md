# Release notes

What changed in the current release. The version this guide was built for is shown in the footer.

## v2.9.0

### Terminal logging

- **Connection logging was rebuilt to actually be reliable** — [terminal logging](../features/terminal.md#terminal-logging) previously wrote every connection to one fixed path (so two connections open at once interleaved into the same file), had no compression, and rotated by *deleting* the file at the size limit. Files are now named `<date>-<time>-<server>_<number>`, a fresh one starts every day (optional) and whenever the size limit is hit, nothing is ever overwritten or deleted by rotation, and each closed file is gzip-compressed. Old archives are swept by the date encoded in their name once the retention period (default 30 days, `0` keeps everything) expires, and only korTTY's own log files are ever touched, so it is safe to point the setting at a folder used for other things too.
- **The terminal log is now redacted** — captured lines pass through the same redaction as the session journal before anything is written: the connection's own stored password and any replacement rules an organization's policy defines. Log files, and a log folder korTTY created itself, are set to owner-only permissions where the filesystem supports it.
- **Quick Connect gained a Terminal log section** — configuring logging in the Connection Manager and then connecting from Quick Connect with a different authentication method previously dropped the setting silently; Quick Connect now carries its own folder, format and compression controls and applies them to the session it opens.
- **Fixed: XML and JSON logs had two document roots and never parsed**, rotation wrote the closing footer twice, up to 10,000 queued lines from just before a disconnect could be silently dropped, and output was split on line endings in a way that destroyed indentation and turned every progress-bar frame into its own log entry. All four are fixed.

### Session journal: filtered export, named markers, page appearance and screenshot editing

- **Exports can now be narrowed down** — the [export dialog](../features/session-journal.md#exporting-only-part-of-a-journal) accepts any number of time windows (an entry only needs to fall into one of them), a topic filter as literal text, a regular expression, or handed to the AI to select by meaning, and a marker filter (all entries, only marked ones, or specific markers). Times are parsed leniently (`8`, `0800`, `8.30` all work) and widened by an adjustable tolerance (± 5 minutes by default), so an approximate window still catches the entry that actually straddles it. A filtered HTML bundle is rebuilt rather than copied — trimmed capture log, only the referenced screenshots — so a shared export cannot leak the rest of the session; every filtered PDF, Markdown file and bundle carries a banner naming the range so nobody mistakes it for the complete journal.
- **Markers are no longer a fixed four-value list** — beyond the built-ins (None, Info, Important, Error) you can now define your own [named, coloured markers](../features/session-journal.md#markers), each degrading to one of the built-ins for older journals and for the error/important counts. Optional rules apply a marker automatically as entries are captured, matching a literal term or a regular expression against the entry's title, summary, note and excerpts, with precedence **your own choice > a rule > the AI's suggestion** — a rule never overwrites a marker you set by hand.
- **The journal page has adjustable [appearance](../features/session-journal.md#appearance)** — a colour scheme (six fixed palettes, the page's automatic light/dark pair, or a scheme derived live from your terminal's own colours), a text font and a monospace font, chosen from a toolbar popover and remembered for every journal korTTY renders afterwards.
- **Screenshots can be [annotated](../features/session-journal.md#screenshot-notes-and-annotations)** — pen, box, an "Unreadable" tool that coarsens a region into blocks, and text labels, plus a note field, reachable by right-clicking a screenshot. Marks are stored as data and stay re-editable; the untouched capture is kept locally as `.orig.png` and is never included in an export. This obscures a value in the rendered page, it does not redact it — use Search & replace or a policy redaction rule to remove something from a journal for good.
- **Selecting a time range got easier** — inside korTTY the viewer's timeline can be switched into range-selection mode: click a first and a last entry to highlight the span between them and hand it straight to the export dialog, or collect several windows before exporting. The same selection is available from the edit-mode entry table via right-click.
- **The journal's title is editable directly from the page**, and a header button jumps between marked entries when a journal has any.
