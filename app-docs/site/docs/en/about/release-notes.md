# Release notes

What changed in the current release. The version this guide was built for is shown in the footer.

## v2.16.0

### Appearance

- **Hints and profile rows in the AI dialogs are readable on the dark designs again** — the AI Manager's profile list painted every unremarkable profile in a hard-coded near-black, and the small hint and status lines asked Modena for a colour that no AtlantaFX design defines, so JavaFX dropped the declaration and the label fell back to pure black — 1.52:1 against a dark surface. A profile row now keeps the surface's own cell colour, the token-warning levels pick a shade that clears 4.5:1 on the active background, and hints dim with opacity instead of naming a colour, so they follow whatever the design provides.
- **Scroll bars in the guide now match its dark page** — the window that shows the manual loads only the ask panel's stylesheet, which carried no scroll-bar rules, so both the page's scroll bar and the ask panel's fell back to Modena's light grey beside the dark page. Track, thumb and arrows are now drawn in the same palette as the page, with the accent colour on hover.

### Snippets

- **A rejected AI flow diagram now says so** — when korTTY discarded an AI-generated flowchart, the [Full code analysis](../features/snippets.md#ai-code-actions) window silently showed the generic local fallback diagram instead, so a long script always seemed to produce a trivial five-node chart. The fallback now carries a notice naming the rejection reason, the same reason appears in the editor's status line and in the log together with the diagram's node and edge counts, and a diagram whose nodes lack a valid source mapping is kept (those nodes merely lose their hover reference) instead of being replaced by the fallback.
- **Flow diagrams of long scripts are less generic and generate much faster** — the diagram request never told the model the node limit that the validator enforced, so for a script of several thousand lines the model transcribed the whole script into hundreds of nodes, spent minutes doing it, and was rejected. The limit is now part of the request and grows with the script — 12 action/decision nodes for snippets up to 200 lines, up to 24 at 1,000 lines or more — and the built-in flowchart skill asks for the main phases of a long script rather than every branch. A script longer than 400 lines is also sent as a condensed structural outline — its definitions and top-level flow, with elided runs marked and the original line numbers kept — instead of every single line, which cuts the request size several-fold and lets the model describe phases instead of statements. See [Mermaid diagrams](../features/snippets.md#mermaid-diagrams).
- **Full code analysis can now be applied to long scripts** — each apply stage used to return the complete rewritten script as a JSON array of every line. For a 4,000-line script that is around 60,000 output tokens: at the model's completion cap, twelve minutes per stage, and a single lost quotation mark in that much JSON lost all of it — with MiniMax-M3 every stage failed after 18 minutes. Above 400 lines a stage now receives the line-numbered snippet and returns only the changed regions, which korTTY applies locally before running exactly the same verification as before; untrustworthy ranges are refused, the log names what was applied, and the stage's output cap drops to 32,768 tokens. Short snippets keep the proven whole-file answer. See [Full code analysis](../features/snippets.md#ai-code-actions).
- **Flow diagrams now accept the Mermaid that models actually write** — tested live against MiniMax-M3, korTTY's diagram grammar rejected one answer in three for shorthand the contract never allowed but every model uses: nodes declared inline in an edge, chained edges, `-- yes -->` labels, the `:::class` shorthand, unquoted labels, other node shapes, and the model's own slips (a label pipe typed as a bracket, a shape closed early, a decision drawn as a diamond with one exit, a mistyped id left dangling, `File::Glob` in a label tripping the URL screen). The grammar now reads all of these and rewrites an accepted diagram into its strict dialect before rendering or saving, the validator tolerates a modest overshoot of the stated node limit instead of discarding a summarized diagram, the contract shows the edge-label syntax instead of describing it, and only what cannot be drawn faithfully — parallel branches from one action — is still rejected, with the reason named. A `start_1` the model declared but never connected is wired to the flow's real entry, statements written with a stray `class ` prefix are still read, and a repaired diagram that kept fewer than half of the drawn nodes is refused rather than shown as a stub.
- **A diagram is no longer rejected for the colors a model added to it** — the diagram contract tells the model to assign four semantic classes that korTTY styles itself, and a model that reads "class" often reaches for `classDef` and defines them with colors as well. The security screen then refused a complete, correct diagram for its decoration. Such `classDef`, `style` and `linkStyle` lines are now dropped from a fresh answer before validation (the log says how many), the contract says explicitly not to define the classes, and a saved diagram is still validated unchanged.
- **MiniMax no longer thinks through diagram requests** — korTTY pins the diagram request to the `none` reasoning value, but MiniMax ignores `reasoning_effort` and only its own `thinking` parameter switches reasoning off; `none` therefore arrived as no parameter at all and MiniMax-M3 reasoned by default, billing the hidden thinking as completion tokens (4,853 of them for a 130-line script) and opening the reply with an inline `<think>` block. Both **Disabled** and `none` now send `thinking: disabled` to MiniMax. The flowchart validator also accepts chained edges (`a --> b --> c`) and plain `%%` comments as the shorthand they are, quotes the offending line when it still has to reject one, skips inline reasoning before recovering a diagram from a broken answer, and logs the answer length beside the token count so hidden reasoning can be told from a verbose reply.
- **A diagram is no longer lost to a misplaced quotation mark** — korTTY's diagram grammar requires quoted node labels, and those quotes have to survive inside the JSON string a model returns. Models regularly lost that escaping on longer answers, and a complete, perfectly good diagram was discarded because the surrounding JSON no longer parsed. korTTY now constrains the diagram answer with its own JSON schema over OpenAI-compatible HTTP, and recovers the diagram from the answer's own text when the envelope is unreadable anyway — also from a compact single-line answer whose remaining fields follow the diagram on the same line — validated exactly as before, and without ever repeating the request.
- **Applying a full code analysis to a long script costs half the prompt tokens** — every apply stage sends the whole line-numbered script, so the number of stages is what a run costs, and on a 4,009-line script each stage was around 63,000 prompt tokens. Edit-mode stages now take six analysis items instead of three: the three-item limit exists so that a whole-script answer stays finishable, and an edit-mode answer holds only the changed regions. Measured live with MiniMax-M3 on that script, twelve analysis items went from four stages to two — 126,391 prompt tokens instead of roughly 252,000, all twelve edits applied — and the progress window plans with the same stage size. Hardening batches are unchanged. Two more things remove the schemaless retry that used to re-send the whole script: an edit-mode answer whose JSON does not parse is now read tolerantly and locally — the slips seen live from MiniMax-M3 are an unescaped quotation mark inside a code line, an escape JSON does not know such as `\$`, a missing `]` before an edit's closing brace, a newline inside an entry, and the summary written as a nested object; the read is all edits or none, so a half-readable answer still goes the retry route — and endpoints that accept `response_format` and ignore it, such as MiniMax, get the retry's JSON-only reminder with the first attempt. When a retry does happen, the log now names how the first answer failed (unparsable JSON, cut off, fenced, prose), and the request log shows the prompt tokens an endpoint served from its prefix cache when it reports them, and every answer korTTY could not use is kept complete under `ai-answers/` in the log directory (the twenty most recent), with the log line naming the file and the place the JSON broke, so a failed stage can be diagnosed from a report without debug logging. The edit-mode parser also read every replacement line through the identifier-list parser, which trimmed indentation, dropped blank lines and removed a repeated `fi` or `}` inside one edit; replacement lines are now taken verbatim. Two more edit-mode guards come from the same live runs: a hollow edit — a range of three or more lines "replaced" by its own first line, which would have gutted a function and was accepted as applied — is dropped, its echoed id is ignored so the repair round asks for the item, and a stage none of whose edits can be applied gets one second attempt that says what was wrong instead of failing the run at once. The analysis answer is repaired when a raw quote pair sits inside one of its prose fields — a live 24,000-character analysis was lost to `"$TEMP_UPGRADE_FILE"` inside one suggestion — and an analysis korTTY still cannot use is archived with the log line naming the file.
- **The change-preview window no longer shrinks or drifts when it docks beside a Full code analysis** — a dialog shown with `showAndWait()` sizes itself to its own preferred size, and macOS reported that size and the re-centring that goes with it only after korTTY had already docked the window; the dock read the report as the user's own resize and drag, so the preview opened at 1040×700 instead of the anchor's height and its remembered width, and on a screen where the three windows had to be tiled it was left at the screen edge. A freshly docked window now gets a one-second settling period in which such reports are ignored and the docked placement is re-asserted, and the preview opens at its docked size to begin with.
- **An over-drawn flow diagram is kept instead of thrown away** — the validator tolerated twice the node cap it states to the model, and a 49-node flowchart of a 4,000-line script, one node over the 48 tolerated, was replaced by the generic fallback after a 16-second request. The tolerance is now three times the cap; the cap itself, and the request that states it, are unchanged. In the same run, a compact edit answer in which the model had swallowed the closing quote of `res=""` cost a retry: such an entry is now read when the entry plus one quote is a line of the snippet, and raw quote pairs inside a compact entry are read again (the split of a code line at a seam has no raw quotes left in either half, so refusing paired quotes never caught it).
- **A range shortened by its last lines is applied, not dropped as hollow** — the hollow-edit guard refused every replacement that was a shorter unchanged prefix of its range, which also caught a model deleting the last two lines of a seventeen-line comment block. Every hollow edit seen live was exactly one line, and that is now the rule.
- **A closing quote fused into the last escaped quote of a code line is read** — the model wrote `body="{"` as `body=\"{\"` and went straight on to the next entry, so the JSON string never closed and the stage cost a retry; when the entry decoded up to that quote is a line of the snippet, that is where the entry ends. The earlier swallowed-quote rule compared the raw JSON text instead of the decoded line and so never matched a line with escapes; it does now.
- **A streamed answer the endpoint never closed is named as such** — two apply stages of a live run answered with JSON that stopped mid-string at a few thousand tokens, far below any cap, and were retried as "cut off". Whether the model stopped or the connection did is what decides the fix, so a stream that ends without a `finish_reason` or `[DONE]` is now logged and its raw stream kept beside the archived answers.
- **Edits that collapse the script get the second attempt instead of ending the run** — a hardening stage answered with two edits "covering" 1,199 lines and an omission marker in place of the code; korTTY rightly refused the result but aborted the run, leaving the user to resume it. Such an answer now gets the same single second attempt an unusable one gets, with the request naming the problem, and it is archived beside the other unusable answers.
- **A flow diagram is no longer lost to a label pipe typed as `>`** — MiniMax-M3 wrote `renewed_check -->|no> stop_1` in an otherwise valid 34-node flowchart, and the diagram was replaced by the generic fallback; the misclosed label is now repaired like the bracket variant `-->|no]`.
- **Three fewer requests per long-script apply** — the transport decided on the schemaless retry without the snippet, so an edit answer the stage could have read (a swallowed or fused closing quote on a line the script knows) was requested again first: it now judges with the same oracle as the stage. A known line in which the model escaped one quote and left the others raw is read. And the omission-marker check, written for whole-file answers, refused an edit-mode stage over a comment that merely said an implementation was unchanged; in edit mode it now looks at each edit instead, and only a range replaced by nothing but such a comment counts.
- **An answer the model abbreviated is named as such, and both reminders forbid abbreviating** — an apply stage came back after fifteen edits with the literal text `{"edits"...etc`, reported as "cut off" although nothing had been truncated. Such an answer is now told apart from a real truncation (only an abbreviation outside the JSON strings counts, so a code line that itself ends in an ellipsis stays a truncation), and the JSON-only instructions sent with the first attempt and with the retry both rule out `...` and `etc`.
- **An apply stage that ran into the output-token limit no longer ends the run** — a hardening stage answered with 32,768 completion tokens against the limit, and the sequence aborted; the byte-identical request the user then resumed with came back in 19 seconds with 3,239. In edit mode the answer holds the changed regions only, so the limit is a runaway answer and not the stage's size: such a stage now gets the same single second attempt every other failure gets, asking for the changed regions alone. A whole-file answer still fails there, because for a large script the limit is the real constraint.
- **A rejected flow diagram is no longer logged as accepted first** — the acceptance line was written before the last gate, so a diagram the strict-dialect repairs then hollowed out appeared twice in the log, accepted and rejected one millisecond apart. Acceptance is now logged after that gate and reports the diagram the window will actually show. A run that stops because the model would not implement a hardening requirement also names the rule beside its identifier instead of `HARDENING-10` alone.
- **A rejected flow diagram is kept whole for diagnosis** — the log carried the rejection reason and the answer's first line, which is enough to see that a diagram was discarded but not to decide whether the grammar should learn the shorthand the model wrote. Rejected diagram answers now go to `ai-answers/` in the log directory beside the unusable apply answers, with the file named in the same log line.
- **A docked window whose content does not cover it is laid out again** — the change preview was reported showing a blank band on its right, its content occupying less than half the window. JavaFX only re-lays-out a root whose size actually changed, which a programmatic resize does not always deliver, so a docked window now checks that its content covers it once the dock has settled, corrects it when it does not, and names both sizes in the log.
- **A flow diagram whose nodes are declared twice is trimmed rather than discarded** — a model drew every node once as a box in a chain and once as a decision on its own line. The parser resolves that to one node per identifier, but the size comparison behind the hollowing guard counted such a node in two buckets, so a diagram that had only lost one undeclared node looked as though the repairs had thrown two thirds of it away, and the generic fallback replaced it. Each identifier now counts once, exactly as the parser resolves it.
- **A flow diagram whose branches the repairs drop is refused, not straightened** — the hollowing guard counted nodes only, so a diagram that kept 3 of 5 nodes but just 4 of 10 edges was accepted and rendered as a straight line of boxes for a 4,000-line script. A diagram's structure is in its edges: losing more than half of them now counts as a hollowing exactly as losing more than half the nodes does, and the rejection names both figures.
- **A flow diagram whose line breaks a model escaped twice is read instead of refused** — gpt-oss-120b answered a diagram request with valid JSON, but every newline of the `mermaid` value carried two backslashes, so the value decoded to a single line of literal `\n` sequences and the complete 21-node getssl flowchart was refused for not starting with `flowchart TD`. No diagram korTTY accepts is a single line, so those sequences can only be the line breaks: they are now restored before the grammar reads the value, everywhere a diagram is validated, rendered or saved. A source that already carries real line breaks is left exactly as written, escape sequences inside labels included.
- **Apply stages of a long script now share their prompt prefix** — every edit-mode stage sends the whole line-numbered script, and the stage's own items used to sit in front of it, so a prefix cache found 128 shared tokens between consecutive stages and processed the 62,000 tokens of script again every time: on a local model that is four to five minutes per stage of a run whose answers take one. The script now comes first, followed by everything specific to the stage or the attempt — items, requirements, repair paragraphs, line count — so consecutive requests share the system prompt, the contract and the script up to the first line the previous stage changed, and a repeated attempt with unchanged input shares all of it. MiniMax reports the saving as cached tokens; LM Studio and llama.cpp reuse their KV cache. The log also gains one line per stage naming its number, phase, item ids, requirement ids, line count and mode, and a line when a stage result is kept but gets the repair attempt for work it did not verify — the run summary counted that retry, but a log showing four requests for three stages had nothing naming the fourth.
- **The change preview's blank band is corrected whenever it appears** — the preview docked beside a Full code analysis was reported again with its content covering only the left half of the window. The earlier check ran three times in the second after docking and compared the content with the scene, so a band that appeared later, or a scene that had itself stopped following the window, went unnoticed and unlogged. The check now follows every later size change of the window, the scene and the content — the dock re-places the preview whenever its neighbours change — and also recognises a scene narrower than its window, which it brings up to date by asking the platform for the size again. The docked preview also no longer applies its stored free geometry on opening, where it competed with the dock's placement in the same pulse.
- **A dependency suggestion the model did not echo no longer costs a repair round** — batched apply stages ask the model to echo every applied item id, and an id missing from the echo opened the stage's single repair attempt: the whole script sent again. A dependency entry is a reduce/replace suggestion the model may rightly leave alone, and one that changed nothing seldom echoes the id; in a 47-item run that was two full requests, eight minutes on a local model, for nothing the items needed. Now only an unechoed improvement or a requirement opens the repair round; a stage whose only unechoed ids are suggestions is accepted with them named in the log, and when another cause opens the round, its request names the suggestions as suggestions — implement where it applies, otherwise leave the code — rather than ordering them applied. A suggestion whose edit was dropped still opens the round, since the model did try to change it.
- **A zoom slider for the diagram** — the diagram toolbar's **−** / **+** / **Fit** buttons now have a slider between them that sets the scale directly. Its track runs in powers of two, so the fitted size sits in the middle and one step to either side halves or doubles it, instead of a linear track that would leave the fitted size at a fifth of the way. The buttons and the slider drive one value, so each follows the other, and **Fit** returns both to the middle. Because every zoom step redraws the whole diagram, a dragged slider redraws a few times a second and once more on the value it is released on, so a 4,000-line script's flowchart follows the drag smoothly. The zoom controls stay together as one group when the toolbar wraps.

### AI assistant

- **AI chat answers now display formatted Markdown** — headings, emphasis, lists, quotations, and inline code appear as a readable preview alongside the existing tables and code blocks. Long text wraps without a fixed-height inner scrollbar. The conversation follows new messages and delayed layout changes, pauses when you scroll up, and resumes when you return to the bottom.
