# Release notes archive

Curated release notes for earlier versions, moved out of the guide.

The guide page `app-docs/site/docs/en/about/release-notes.md` deliberately carries only the
current release: it is translated into every language the guide ships in, so a growing
changelog there costs translation time and buries the notes that matter. When a release is
cut, the outgoing version's section moves here.

This file is not part of the documentation site — it is neither published nor translated.
Releases older than the ones below are recorded in `RELEASE_NOTES.adoc` next to this file, and
every version is also listed on the [GitHub releases page](https://github.com/chardonnay/korTTY/releases).

## v2.21.0

### SFTP Manager

- **Compare and synchronize folders** — **Compare** reads both folders, the local one and the one on the server, with all subfolders, counts what is only on one side, newer or different, and colours the rows. **To the server** and **To this computer** copy what is missing or newer, keep modification times, and can delete what exists only on the target. See [Comparing and synchronizing folders](../features/sftp.md#comparing-and-synchronizing-folders).
- **File comparison with AI questions and a new file from both** — select two files, two in one panel or one in each, also a local one against one on the server, and click **Compare** to see them side by side. With the AI features on, **Ask AI** explains where they differ, what the differences do or what could be improved, for example in scripts and configuration files, and **New file** has the AI write a third file from both, which you can save on the server or on this computer or keep in the Snippet Manager. Two folders on the same side can be compared as well. See [Comparing two files](../features/sftp.md#comparing-two-files).
- **Active panel, path bar and status line** — the panel you clicked or typed in last is framed in the accent colour; each panel has its own row of buttons under its list, with **Upload** and **Download** facing each other across the divider. Each panel shows its path as clickable folders (++cmd+l++ or ++ctrl+l++ to type one) and a line under the list with the number of entries, the selection and its size. Rows are compact in every design. See [Active panel](../features/sftp.md#active-panel) and [Path bar and status line](../features/sftp.md#path-bar-and-status-line).
- **Hidden files and sort order** — an eye button beside each panel's path, or ++cmd+shift+period++ (++ctrl+shift+period++ on Windows and Linux), shows or hides dot files and folders (and Windows hidden files); each panel remembers its choice. Hidden folders come first, then hidden files, folders and files, in every column. See [Hidden files](../features/sftp.md#hidden-files) and [Sort order](../features/sftp.md#sort-order).
- **Permission checkboxes** — **Set Owner/Permissions** shows the mode as checkboxes for owner, group and others next to the octal field and keeps both in step. On the local side the user, the group and **Apply recursively to directories** now take effect. See [Permissions](../features/sftp.md#permissions).
- **User and group names, folder sizes** — servers that send owners only as numbers, such as OpenSSH, now show user and group names, looked up on the server in the background. **Calculate size** in the server's right-click menu measures folders with `du`, and the size estimate in the archive dialog now includes the selected folders. See [Owner and group names](../features/sftp.md#owner-and-group-names) and [Folder sizes](../features/sftp.md#folder-sizes).
- **Archive dialog says what it archives** — the computer, the folder, the number of folders and files and their names. The server's archive tools are looked up in the background, so a server that runs no commands no longer freezes the window. See [Creating archives](../features/sftp.md#creating-archives).

### Settings and AI Manager

- **Search in the settings** — a search line at the top of **Global Settings** finds a setting on any tab as you type. Choosing a result opens its tab, scrolls to the setting, colours it and focuses its control. See [Searching the settings](../reference/settings/index.md#finding-a-setting).
- **Manual for each tab and section** — **Manual for this page** in the settings navigation bar opens the built-in manual at the page for the current tab, and the section headers on the Logging, Resources, Security and Privacy tabs link to the section that explains them. The Logging tab now says that it concerns korTTY's own application log, not terminal session logs. See [Manual for each tab](../reference/settings/index.md#manual-for-each-tab).
- **Automatic encrypted backup** — *Settings → Backup → Automatic backup* creates a backup on a schedule (daily, weekly or monthly) into a folder you choose, always encrypted, and catches up a backup that was missed while korTTY was closed. A status line says when the last one ran and when the next is due; an organization policy can lock the setting. See [Automatic backup](../reference/settings/backup.md#automatic-backup).
- **Translation profiles** — *Settings → Translation* keeps several translation profiles, one of them the default, with a setup assistant for a new one. **Translate now** shows an estimate before it starts and can be paused and cancelled. See [Translation profiles](../reference/settings/translation.md#translation-profiles) and [Translate now](../reference/settings/translation.md#translate-now).
- **Theme preview** — the Themes tab shows the theme list in a narrow column and previews the selected theme on a sample terminal screen with a directory listing, `git status`, compiler messages, all sixteen ANSI colours and the theme's cursor. See [Theme preview](../reference/settings/appearance.md#theme-preview).
- **AI settings in the AI Manager** — the AI tab of Global Settings moved into the AI Manager's new **General** tab, which holds the options that belong to no profile: features and safety, the terminal agent, defaults and internet access. See [General tab](../reference/settings/ai.md#general-tab).
- **Profile editor in sections** — the **Profiles** tab keeps the profile name and **Use as default profile** at the top and groups the fields into **Connection**, **Model & capabilities**, **Limits & timeouts** and **Budget & usage**. Only the rows of the selected connection mode are shown, the request timeout that applies to every profile heads the Limits & timeouts section, and **Test AI Connection**, **Delete** and **Save** sit under the editor. See [AI Manager](../features/ai-assistant.md#ai-manager). **Test AI Connection** shows its result in a coloured bar under the profile name instead of only in the status line.
- **Profile setup wizard** — a sidebar shows the stages and the choices already made, a **Quick start** finds LM Studio, Ollama (on this computer, on the hosts you enter under **Other computers on the network**, and on the hosts of existing profiles) and installed command-line tools and offers one-click profiles, connection types and providers are cards, reasoning sits under **Advanced**, and the last step runs the test by itself and shows a summary with **Change** links. See [AI Profile Setup Wizard](../features/ai-assistant.md#ai-profile-setup-wizard).
- **Local AI in sections** — the **Local AI** tab splits into **Profile roles**, **Local runtime** and **Hugging Face**. See [Text, coding, translation, and embedding roles](../features/local-models.md#text-coding-translation-and-embedding-roles).

### JobScheduler

- **Job dependencies** — a job can depend on other jobs and either keep its own schedule but only run when every predecessor's last run succeeded (**Condition**), or start automatically once all predecessors have succeeded (**Chain**), optionally only counting recent successes. Cycles are refused, the job list shows a **Depends on** column, and deleting a job that others depend on warns first. **Run with successors** runs a job and everything below it in dependency order, and **Disable chain** switches a job and all its dependents off or on at once. See [Job Dependencies](../features/jobscheduler.md#job-dependencies).
- **Dependency diagram** — draws the job dependencies as a Mermaid flowchart colored by each job's last result, vertical or horizontal, in light or dark mode, with SVG/PNG export. See [Dependency Diagram](../features/jobscheduler.md#dependency-diagram).

### Fixes and maintenance

- **Reconnected tunnels get their ports back** — after a reconnect, a remote (`-R`) tunnel could fail with *Address already in use* because korTTY asked for the port again before the server had released it. korTTY now waits for the server to release a remote forward before it hands the tunnel over. See [SSH Tunnels](../features/tunnels.md).
- **Snippet AI processing beside the analysis** — the progress of applying a full code analysis sits in an **AI processing** column at the snippet editor's right edge, sized to its checklist, and can be moved into the analysis panel. See [Applying the selected improvements](../features/snippets.md#applying-the-selected-improvements).
- **JobScheduler time windows show their times** — the *Window from* and *Window until* fields no longer cut the selected time off.

## v2.20.0

### Terminal logs

- **Logfile Manager** — *Tools → Logfile Manager…* (++ctrl+shift+x++, ++cmd+shift+x++ on macOS) finds terminal logs in default, connection-specific, previously used and manually added folders. Filter by name, time range, format or compression; inspect file sizes and retention dates; export compressed copies or delete selected files after confirmation. Live logs are protected from deletion. See [Logfile Manager](../features/terminal.md#logfile-manager).
- **Log viewer** — open large or compressed logs without loading the whole file into the viewer, search, jump to a line, copy selected lines and highlight keywords, links and paths. JSON and XML logs have a formatted view with a raw-view toggle. See [Viewing a log](../features/terminal.md#logfile-manager).
- **Context and badges** — log entries can include the SSH username and the full working directory or a path relative to the first reported directory, subject to enterprise policy. The manager displays connection names and stable aliases for IP-only names, supports searchable custom badges, and offers a **Hold** badge that prevents automatic and manual deletion. See [Terminal logging](../features/terminal.md#terminal-logging) and [Logfile Manager](../features/terminal.md#logfile-manager).
- **Protected exports** — export whole logs or selected lines, optionally trim them to a time range and convert between JSON, XML and plain text. Archives can use AES-256 password encryption and additional GPG encryption. See [Exporting logs](../features/terminal.md#logfile-manager).
- **Valid XML after policy replacements** — terminal XML logs remain parseable when an enterprise replacement rule inserts characters XML cannot represent.

### Window and coding agents

- **Customizable icon toolbar** — add, remove, rearrange and preview terminal, tool and settings buttons, with a separate row for saved servers and groups. Visibility and layout are shared across windows; icon size is adjustable from 16 to 64 px. The Tools group includes the Logfile Manager, and existing layouts gain its button once while preserving their other buttons and order. The in-window menu bar starts visible. See [Customizing the icon toolbar](../getting-started/main-window.md#customizing-the-icon-toolbar).
- **Docked panels keep their width** — the AI agent panel, Coding Agents, Live Journal and local file browser retain their selected width beside wide terminals and shrink proportionally when the window has insufficient space.
- **More coding agents** — local shell tabs now also recognise MiniMax Code, Qwen Code, OpenCode, Cursor Agent, Aider, Goose, Crush, Continue, Superagent's Grok CLI, xAI's Grok Build, GitHub Copilot CLI, Jules, Amp and Kiro CLI. Amp and Kiro CLI rules are based on the programs' own texts and remain unverified against live sessions. See [What it detects](../features/coding-agents.md#what-it-detects).
- **Sidebar and quick answers** — the Coding Agents sidebar automatically appears on detection and hides when no agents remain; its selected side is remembered, automatic visibility can be disabled, and **Explain** details collapse after 60 seconds. **YES** and **NO** send the complete uppercase word followed by Enter, so one click submits the answer. See [Coding agents](../features/coding-agents.md).

### Notifications and AI skills

- **Messaging settings** — desktop notification choices now have a dedicated **Messaging** settings page, including a separate switch for coding-agent messages. Saving applies the choices to open sessions. See [Messaging settings](../reference/settings/messaging.md).
- **Notification clicks return to the pane** — clicking a desktop notification selects its window, tab and terminal pane. The Flatpak sandbox permits the desktop notification service, and macOS development runs build a native notification helper. The enterprise policy can disable desktop notifications for every feature. See [Clicking a notification](../features/terminal-notifications.md#clicking-a-notification).
- **Import and update external AI skills** — the AI Skills manager imports `SKILL.md` files from GitHub, SkillsMP and HTTP(S) providers. Provider tokens and passwords are encrypted with the master password, and source updates are previewed as a side-by-side diff. Imported skills start deactivated; only the skill text is imported, with a 256 KiB limit and HTTPS required except for loopback addresses. See [External skills](../reference/settings/ai-skills.md#external-skills).

### Fixes and maintenance

- **Log export controls stay visible** — the options dialog is resizable and scrollable, with an explicit **Export…** button that opens the save dialog for one log or a line selection, or a folder chooser for several logs. Export and Cancel stay visible even in a short window. See [Logfile Manager](../features/terminal.md#logfile-manager).
- **Snippet analysis progress stays usable** — the checklist remains visible in short panels and after a run finishes, and progress content no longer intercepts clicks on the dialog's **Close** button. See [Applying improvements](../features/snippets.md#applying-the-selected-improvements).
- **Complete log translations** — added the missing log context, badge and export labels in Spanish, French, Croatian, Italian, Dutch and Portuguese. The build checks each locale for missing keys and reports their names.

## v2.19.0

### Terminal

- **Session isolation, sandboxed local shells and incognito sessions** — a connection, a folder of the Connection Manager or *Settings → Security → Session isolation* can now choose how far a terminal session is kept apart from korTTY and the other tabs: **None**, **Own process** or **Own process + sandbox**. In the sandbox (`sandbox-exec` on macOS, bubblewrap on Linux, checked by a self-test before it counts) a local shell or the native `mosh-client` cannot read korTTY's configuration folder, your SSH and GnuPG keys or the keychains and writes only to its working folder and temporary files; An isolated SSH session runs in a **session worker**, a process of its own that holds the server connection while your private key stays in korTTY, which signs for it; SFTP, file drops, the AI agent and `-L`/`-D`/`-R` tunnels work as before, and *Tools → Session Processes...* lists the workers with their memory and CPU and can end one. The built-in Mosh client runs isolated in a session worker as well, its sandbox limited to the UDP port of the session. On Linux a sandboxed worker has no network of its own: korTTY connects it only to the server and jump server of its connection. The tab shows a shield: an outline for an own process, filled for a sandbox, with an exclamation mark when a sandbox was asked for but is not active. A **strict terminal mode**, automatic in a sandbox, drops clipboard access, non-web links, spoofing titles and device control strings a hostile server could send. An **incognito session** — per connection or with *File → New Incognito Session…*, with or without isolation — writes no log, journal or recording, leaves no Recently Closed entry and is not restored after a restart; its tab shows a spy. An administrator can demand a minimum with `[rule.isolation] minimum` and forbid incognito sessions with `incognito-sessions = "deny"`. A script can open a saved connection with `kortty-cli tab create --connection <name>`, with `--isolation` and `--incognito` if it likes, never below the organization's minimum. See [Session isolation](../features/session-isolation.md).
- **korTTY as an MCP server for AI assistants** — `kortty-cli mcp` lets an AI assistant that speaks the Model Context Protocol list your tabs, panes and coding agents, read a pane and wait for output in it. It runs as a child process of the assistant over stdio, opens no network port and reaches korTTY through the local Control API. It is **read-only and off by default**: switch it on with **MCP server** under *Settings → Terminal → Control API*, below the Control API checkbox. Everything an assistant reads has known secrets masked and is capped at 2,000 lines and 64,000 characters. A second switch, **Allow write tools**, also offers tools that type text, run a command or press keys in a pane, and korTTY asks you before every one of those writes; you can allow plain text for one pane for the rest of the session, but running a line always asks. Panes with a slow paste, a full-screen program, a nested login, broadcast or multi-exec, or a coding agent are refused. An administrator can deny the whole feature with the `mcp-server` policy key, and anonymous usage statistics, if you allowed them, report which tools are used and how the calls ended, never what they read or typed. See [Serving MCP clients](../reference/cli.md#serving-mcp-clients) and [MCP clients](../reference/control-api.md#mcp-clients).
- **Prompts and Control API pastes can no longer end their bracketed paste early** — a bracketed-paste end marker (`ESC[201~`, or its 8-bit form in a single-byte encoding) inside the text of a coding-agent prompt or a bracketed `pane.send_text` closed the paste korTTY had wrapped around it, so every following line reached the program as typed input and was submitted on its own. korTTY now removes the start and end markers from every prompt and from the text of a bracketed `pane.send_text`, including markers that only form once an inner one is removed and, in a Windows-1252 pane, the `›` that this encoding sends as the 8-bit introducer; an unbracketed `pane.send_text` or `pane.run` still keeps them. See [Typing into a pane](../reference/control-api.md#typing-into-a-pane).
- **Terminal pastes can no longer end their bracketed paste early** — korTTY passed pasted text to the terminal unchanged, so a bracketed-paste end marker (`ESC[201~`) inside it closed the paste the terminal wrapped around it, and every following line reached the shell as typed input and ran on its own. Every terminal paste (the paste shortcut, *Edit → Paste*, **Paste** in the right-click menu and a middle-click) now goes through korTTY, which removes the start and end markers from the text, including their 8-bit form in a single-byte character encoding, before it wraps the paste itself. A pane also no longer keeps bracketed paste switched on after a reconnect or a terminal reset (`reset`), which wrapped pastes in markers that the next program might not understand. See [Pasting text](../features/terminal.md#pasting-text).
- **Paste protection** — a terminal paste that could run commands or hide something now asks first. A paste with line breaks asks unless the program in the pane uses bracketed paste, a paste with control characters (such as Escape or Ctrl+C) or invisible direction-changing characters asks even then, and a paste larger than 5 KiB always asks. The dialog shows the pane, the number of lines, the size, the reasons and a preview in which hidden characters are visible; **Cancel** is the default button, so pressing ++enter++ by habit never pastes. Choose when it asks under *Settings → Terminal → Paste protection*: **Always** asks for every paste with a line break, **Off** only keeps the size check, and a size of 0 turns that off. See [Paste protection](../features/terminal.md#paste-protection).
- **Paste line by line into slow devices** — switches, routers and console servers behind SSH can lose input that arrives too fast, so a pasted configuration arrived with characters or lines missing. *Settings → Terminal → Paste protection → Pause after each pasted line* (0 to 1,000 ms, off by default) now sends a paste with several lines one line at a time with that pause. The pane shows how far the paste is, takes no keys meanwhile so nothing you type lands between two lines, and ++esc++ stops the rest; broadcast mode leaves the pane out until it is done. See [Pasting into slow devices](../features/terminal.md#pasting-into-slow-devices).
- **Drop text onto a terminal** — text dragged from a browser, an editor or another korTTY window and dropped onto a terminal was ignored; only files were taken, to be copied to the server. Dropped text is now pasted into the pane under the pointer, which becomes the focused pane, through paste protection like any other paste, and it is always copied, so the application you drag from keeps it. The setting is now called *Settings → Terminal → Allow drag and drop into the terminal* and covers files and text; with the enterprise policy's internal clipboard mode, text from other applications is refused. See [Dropping text](../features/terminal.md#dropping-text).
- **Files dropped onto a terminal land where you dropped them, and only there** — a file drop always went to the pane you had last clicked, even when you dropped it onto another pane of a split tab; it now goes to the pane under the pointer, which becomes the focused pane. After `su`, `sudo -i` or a nested `ssh` the files were still uploaded with the tab's own login into the directory the inner shell reported, which may belong to another user or host; korTTY now refuses such a drop with a message, and **Copy as file(s) to terminal directory** and **Copy folder to terminal directory** in the Snippet Manager do the same. A dropped folder containing a link to one of its parent folders no longer makes the copy run until it fails: links to folders are skipped and counted in the progress window, while links to files are still copied with their content. Each drop also kept one SFTP channel of the terminal's SSH session open until the tab closed, so after many drops the server could refuse new channels; the channel is now closed when the copy ends, and a drop onto a session that has just closed says so instead of failing with an internal error. See [Dropping text](../features/terminal.md#dropping-text).
- **A shell on another host is recognised from its directory reports** — shells that report their directory with OSC 7 also name their host. korTTY now remembers the host of the first report of your own session and, when a later report names another host, no longer moves the tracked terminal directory there and treats the pane as running elsewhere: file drops and snippet copies are refused as after `su` or a nested `ssh`, until the original host reports again or the tab reconnects. The full name of the host, `localhost` and reports without a host count as the same host. See [Dropping text](../features/terminal.md#dropping-text).
- **Busy sessions on slow links are no longer cut off as lost** — korTTY declared an SSH connection lost when two liveness probes in a row went unanswered, even when the server was still sending data and the reply was only queued behind it, for example a large output or a file transfer over a slow link. An unanswered probe now only counts while nothing arrives from the server at all, so such a session stays open, and a dead network is still noticed within about ten seconds. See [Connection loss and automatic reconnect](../features/terminal.md#connection-loss-and-automatic-reconnect).
- **Command timestamps stay on their command lines** — once the scrollback had reached its limit, the marks in the command timestamp sidebar drifted one row further from their command with every new line of output, and a new prompt on the bottom row got no mark of its own. Marks now move with their lines, disappear when their line leaves the scrollback, and are removed by **Clear Buffer**. The dates in the sidebar and its hover popup follow the UI language instead of a fixed German order, and **Duplicate** and **No Group** in the tab context menu are translated instead of always German. See [Terminal settings](../reference/settings/terminal.md#notes).
- **Anonymous usage statistics now cover the command palette, multi-exec and session restore** — if you allowed anonymous statistics, korTTY also reports which kind of command palette row you run, when you turn multi-exec on or off and how far it reaches, when the previous session is restored and how, and whether you changed the quick-select letters or patterns, the tab-title and tab-order switches or any shortcut. Only kinds, flags and rounded counts are sent — never search text, names, hosts, patterns or what you type. See [Anonymous data](anonymous-data.md).
- **Cmd/Ctrl+W and the Dashboard's Close ask before closing a busy terminal** — the tab's close button asks before it closes a tab with split panes or a command that is still running, but **Close Tab** (++cmd+w++ on macOS, *File → Close Tab*) and **Close** in the Dashboard closed such a tab straight away and ended the running command. All three now ask the same question; an idle terminal at its prompt still closes immediately, and a connection set to *Close tab without confirmation* never asks. A terminal closed with **Close Tab**, the Dashboard's **Close** or **Close All Tabs** is now also released like one closed with its close button, instead of staying in memory with its status-bar timer still running. See [Working with tabs](../features/terminal.md#working-with-tabs).
- **Tabs that close on their own are fully released** — when a split pane was left as the last pane and its shell exited, or ++ctrl+d++ closed a local cmd or PowerShell tab, the tab closed without the cleanup its close button runs: korTTY still counted that pane as connected, so with **Configuration > Prevent System Sleep** checked the computer was kept awake, and a shell closed with ++ctrl+d++ kept running in the background. Such tabs now close exactly like a tab closed with its close button.
- **Navigation keys reach programs the way they expect them** — korTTY used to send the arrow keys, Tab, Home/End, Page Up/Down, Insert/Delete and the F-keys as fixed sequences without their modifiers, so ++ctrl+left++ and ++shift+tab++ arrived as plain Left and Tab and ++shift+f1++ as F1. They are now encoded the xterm way and follow the program's cursor-key mode, so word movement (++ctrl+left++ / ++ctrl+right++, ++option+left++ / ++option+right++ on macOS) and back-tab work in the shell, `mc` and `vim`. ++shift+page-up++ / ++shift+page-down++ now scroll korTTY's scrollback, ++ctrl+tab++ switches tabs while the terminal has the focus, editing the find bar's search text no longer types into the shell, and broadcast mode mirrors these keys to every pane, encoded for each. See [Keyboard shortcuts](../reference/keyboard-shortcuts.md#terminal).
- **Broadcast mode no longer freezes the window when one server stalls** — the keys mirrored into the other panes were sent on the thread that draws the window, so a pane whose SSH connection had stopped responding froze korTTY on every keystroke. They are now sent in the background, still in the order you typed them for each pane, so only the stalled pane waits while the window and the other panes keep reacting. See [Broadcast mode](../features/terminal.md#broadcast-mode).
- **Broadcast mode keeps AI agents and passwords where they belong** — the keys typed in broadcast mode reached every pane of the tab, so `agent …` and ++enter++ started an AI agent run in each pane, a mirrored ++y++ could approve what a coding agent waiting for a decision asked in another pane, and a sudo password typed in one pane ran as a command in the panes at an ordinary prompt, where it stayed in their shell history and session journal. Now the agent shortcut starts a run only in the pane you type in, panes where an AI agent runs or a coding agent waits for your decision get no mirrored keys (the **Extras** submenu of a pane's right-click menu says how many are left out), and while you type at a password prompt your keys go only to the panes at a password prompt too. See [Broadcast mode](../features/terminal.md#broadcast-mode).
- **Copying and pasting in broadcast mode no longer reaches the other panes** — on Windows and Linux, ++ctrl+shift+c++ and ++ctrl+shift+v++ still produce the control character of ++ctrl+c++ or ++ctrl+v++, and broadcast mode sent it to the other panes of the tab: copying a selection interrupted the program running in each of them, and pasting made their shells insert the next key literally. A key now goes to the other panes only when the pane you type in sends it to its own program as well, which also keeps the keys of menu commands out of them. See [Broadcast mode](../features/terminal.md#broadcast-mode).
- **Ctrl+L and Ctrl+F reach the shell on Windows and Linux** — the terminal's own Clear Buffer and Find took these keys, so ++ctrl+l++ wiped the scrollback instead of redrawing the screen in bash, psql or a REPL, and ++ctrl+f++ never moved the cursor forward or paged forward in `less`. Both keys now go to the shell; Clear Buffer and Find stay in the terminal's right-click menu and Find in *Edit → Find…*, while ++cmd+k++ and ++cmd+f++ on macOS are unchanged. On Linux a selection copied automatically also becomes the X11 primary selection, so a middle-click pastes it in other applications. See [Keyboard shortcuts](../reference/keyboard-shortcuts.md#terminal).
- **Bold text in bright colors** — *Settings → Terminal → Bold text* now chooses how text that a program prints in bold is drawn: in a bold font (the default, as before), in the bright variant of its color the way xterm does, or both. Bright colors come from your palette on the Colors tab and apply to every open terminal and to terminal recordings as soon as you save. It replaces the **Bold as bright color** switch, which only ever affected recordings; with the terminal engine SithTermFX 1.2.4. See [Terminal](../reference/settings/terminal.md).
- **The terminal find bar speaks your language** — the find bar of a terminal pane (*Edit → Find...*) showed its texts in English whatever language korTTY used. Its search field, the **Ignore case** switch, the match count such as *3 of 12*, *No matches* and the tooltips of the next and previous buttons now follow the language set in korTTY, with the terminal engine SithTermFX 1.2.4. See [Terminal](../features/terminal.md).
- **The ANSI colors and the selection color on the Colors tab now take effect** — the 16 color pickers in *Settings → Colors* were never saved, and the terminal ignored the **Selection** color too. Both now apply to every open terminal as soon as you save, and terminal recordings use the same colors as the screen. Settings you never changed keep the built-in palette and inverse-video selection, so nothing looks different until you customize a color. See [Colors](../reference/settings/colors.md).
- **Menu commands follow the pane you type in** — in a split tab, *Edit → Copy*, *Edit → Paste*, *Edit → Find...*, the AI actions and a recording of the active split used the pane you had last clicked. When the keyboard focus reached another pane some other way, for example with a middle-click, or stayed in the original pane after a split that showed a connection dialog, they acted on a different pane than the one receiving your typing, and closing one pane moved them to the first pane even when you were typing in another. They now use the pane that has the keyboard focus. See [Split operations](../features/terminal.md#split-operations).
- **No pane close button on a tab with a single terminal** — the × in a pane's top-right corner, meant for closing one pane of a split tab, also showed when the tab had only one pane, and clicking it there ended that terminal's session at once, without the question the tab's own close button asks before it closes a busy terminal. The × now shows only while the tab has more than one pane. See [Split operations](../features/terminal.md#split-operations).

### Connections and security

The new **Configuration → Security → Known Hosts…** lists, searches and removes trusted keys. See [SSH host-key verification](../features/connections.md#ssh-host-key-verification).

See [Signing in](../features/connections.md#signing-in).

### SSH and security

- **SSH tunnels now really open** — tunnels configured on a connection were saved, imported and shared, but never opened. korTTY now opens the enabled ones once per terminal tab after login, closes them before a reconnect and opens them again afterwards, moves them to another pane of the same server when you close the pane they run on, and shows `Tunnels: 2/3 active` with the first error in the tab's status bar (hover for every tunnel). Because tunnels that never did anything would otherwise start listening silently after the update, korTTY asks once per connection before it opens them, and again when the tunnels or the server change. A remote tunnel listens on the SSH server's loopback address unless you name another one, shared (Teamwork) connections never open remote tunnels and may only listen on `localhost`, and administrators can forbid tunnels with the new `allow-port-forwarding` policy key. Remote tunnels that earlier versions imported from PuTTY Connection Manager carry the bind address `0.0.0.0`; the confirmation, the tunnel list and the status bar mark them as reachable from other computers, so set their **Remote bind address** to `localhost` if the forwarded port should stay private to the server. See [SSH Tunnels](../features/tunnels.md).
- **The tunnel editor says what listens where, and Enable SSH tunnels works** — the tunnel dialog now labels its fields after their role for each type (**Local bind address**, **Remote bind address**, **Local host** as a remote tunnel's target), lists the listener first and warns when other computers can reach it; the tunnel list shows remote tunnels listener first instead of reversed and no longer shows German text for SOCKS proxies. **Enable SSH tunnels**, which nothing ever read, now switches every tunnel of the connection on or off, and saving the connection applies tunnel changes to open tabs right away, so switching tunnels off closes them. **Cancel** now discards tunnels added, edited or removed in the connection editor, which were kept before. PuTTY Connection Manager imports bind remote tunnels to `localhost`. See [SSH Tunnels](../features/tunnels.md#the-tunnel-list).
- **The terminal encoding now takes effect** — *Settings → Terminal → Encoding* was never read, so every SSH session was decoded as UTF-8 and servers that write ISO-8859-1, ISO-8859-15 or Windows-1252 showed broken umlauts. The setting now applies to SSH connections, and each connection can choose its own **Character encoding** on the *Connection* tab of the connection editor. Local shells stay UTF-8 unless their connection sets an encoding, and Mosh is always UTF-8. A value you picked in an earlier version, when it had no effect, is not applied on its own: SSH sessions stay UTF-8 until you save the settings after opening the Terminal page, where a note points this out. Text that the [Control API](../reference/control-api.md#typing-into-a-pane) types into a pane follows the pane's encoding as well. See [Character encoding](../features/connections.md#character-encoding).
- **Temporary SSH keys are no longer left in the temp folder** — every connect, split and SFTP session with a temporary SSH key wrote the private key to a file in the system temp folder that was never deleted, so the key stayed on disk long after it had expired, and the debug log recorded the beginning and end of the key text. Temporary keys are now read in memory only and never logged, and key files that earlier versions left behind are deleted at the next start when they belong to you. See [Security](../reference/settings/security.md).
- **Scheduled jobs keep temporary keys off the disk too** — a JobScheduler job with a temporary SSH key now authenticates in memory like a terminal tab. Only an Rsync job still needs the key as a file for its external `ssh`; that file is created owner-only from the start and deleted when the job ends or its connection fails, instead of staying in the temp folder.
- **JMX monitoring shows the connections that are really open** — the `de.kortty:type=SSHClient` MBean always reported 0 active connections and no names, because it read a session list that nothing ever filled. `ActiveConnectionCount`, `ActiveConnectionNames` and `ConnectionStatistics` now list every live SSH and Mosh terminal connection (each split pane counts, local shells do not), and `BufferedTextSize`, which was never measured, stays at 0 for existing JMX clients. See [Logging and diagnostics](../reference/architecture.md#logging-and-diagnostics).

### AI agent and profiles

- **Desktop notifications for AI Agent and AI Swarm runs** — an agent or swarm run in a window behind another one waited for an approval without a word, so the run stood still until you happened to look. When a run in a tab you are not looking at waits for your approval or a password, finishes or stops without finishing, korTTY now shows a desktop notification titled with the tab's name, in one fixed sentence without the prompt, the command or any output, at most once per tab and kind every 10 seconds. It is on by default and can be switched off in *Settings → Terminal → Notifications*. See [AI agent and AI Swarm runs](../features/terminal-notifications.md#ai-agent-and-ai-swarm-runs).
- **Longer answers from Claude, and an output limit per profile** — the native Anthropic endpoint allowed every answer only 4,096 tokens, so a Mermaid diagram, a long chat answer or a snippet rewrite from Claude was cut off early. korTTY now sizes each request from the action's safety limit, the model's documented output limit and a ceiling of 16,000 tokens per request while answers are not streamed; unknown models keep 4,096 tokens, a thinking budget always fits below the limit, and a request the API rejects for a too-high `max_tokens` is retried once with the limit the error names. The new **Max output tokens** setting in both profile editors lowers the limit for a profile; it never raises an action's safety limit. See [Output limit per answer](../reference/settings/ai.md#output-limit-per-answer).
- **The AI Swarm's combined answer and scheduled AI jobs mask secrets too** — the request that merges the per-server answers of an AI Swarm into the comparison table still sent every server's answer and output excerpt to the AI as it was, and a scheduled AI Agent job sent its job prompt unchanged. Both are now masked like the agents' own prompts for profiles other than integrated models and trusted local endpoints: the servers' passwords, a stored sudo password, your organization's replacement rules and well-known token formats become `***`. The table shown when the AI cannot be reached stays unchanged because it never leaves your computer. Scheduled AI Swarm jobs also redact each server's password from their journals as soon as its session connects, not only after the run. See [Combined answer and row details](../features/ai-swarm.md#combined-answer-and-row-details).
- **The AI Agent masks secrets before it sends them to the AI** — the agent sent the environment probe and the full output of every command it ran to the model as they were, so a password, an access key or a token that a command printed reached a cloud AI provider unchanged, turn after turn. Every prompt of the agent, of its planning mode and of each AI Swarm agent is now masked like a terminal selection: the connection's password, a sudo password typed during the run, your organization's replacement rules and well-known token formats become `***`, while integrated models and a trusted local endpoint still get the original text. The terminal, the activity panel, the approval dialog and the journal keep the real output, a **Masked before sending** entry in the activity panel counts the masked values, and a planned command that contains the `***` placeholder is not run. See [Masking what the agent sends](../features/ai-tools.md#masking-what-the-agent-sends).
- **The AI agent asks before it runs in a switched session** — after `su`, `sudo -i` or a nested `ssh` in a terminal, the agent's commands would still run over the tab's original connection, as the user the tab was opened with, not as the user the prompt shows. AI Agent and AI Planning now warn first and name the `user@host` (or "on this computer" in a local-shell tab) the commands will really run as; **Cancel** is the default. The check also covers rerunning a command with the activity panel's reload button and the execution of an accepted plan. See [Safety and failure handling](../features/ai-assistant.md#safety-and-failure-handling).
- **No internet mode for native Anthropic profiles** — korTTY sends no web tools to the native Anthropic Messages API, so a mode such as KorTTY Tavily Tool had no effect there. For such profiles the **Internet access** dropdown is now locked to **Disabled** with a hint explaining why. See [AI internet access](../features/ai-assistant.md#ai-internet-access).
- **One switch for the shell's prompt marks** — *Settings → AI* had **Use OSC 133 prompt markers when the shell already provides them**, which changed nothing: the AI Agent's `agent` commands and the question before closing a busy SSH tab read the marks either way. The option is gone, and both now follow **Use the command marks of shells set up for shell integration (OSC 133)** in *Settings → Terminal*, like every other use of the marks; switched off, korTTY tells that an SSH session is at its prompt from the prompt's text alone. A short command whose output and next prompt arrive together no longer leaves the session looking busy, and a choice saved for the old option stays in the settings file without effect. See [Shell integration](../features/shell-integration.md#switching-it-off).
- **An invisible character in an AI skill can no longer reset all your settings** — a control character pasted into the Markdown of an AI skill, or U+FFFF in its name, was written into `global-settings.xml` as it was; korTTY then could not read the file at the next start and fell back to the default of every setting. The AI skill editor now names such a character below the field and refuses to save until you remove it, and importing a skill from a Markdown file removes these characters. See [AI Skills](../reference/settings/ai-skills.md#skill-editor-fields).

### JobScheduler

- **Scheduled AI jobs follow the organization's AI policy** — AI Agent and AI Swarm jobs ran even when an enterprise policy denied the AI agent or the AI Swarm or set the agent to read-only, and under `ai-agent-execution = "confirm"` a swarm job with **AI agent may change the server without runtime confirmation** approved the server-changing commands the policy wanted a person to approve. Such jobs now end as blocked before they connect to any server, with the policy reason in the journal; under `confirm`, an AI Agent job blocks a planned server-changing command and an AI Swarm job stops the agent that planned one, whatever the job's auto-approve says, while read-only commands still run.
- **Session journal per run** — a job can now record a full session journal for every run: one journal per target server with every command, its output, the job's summary and the outcome, which can be summarized by the AI, searched, exported and asked questions like an interactive journal. Per job you choose when the AI summarizes (every kept run, only failed runs, or never), whether successful runs are kept at all, when the journals are deleted automatically (after N days, on a date, or never), a maximum number of runs and disk space, whether a run identical to the previous one is discarded in favour of a reference, and which AI profile summarizes — a local profile keeps it free. Switching the journal or its AI summaries on first shows a warning with an estimate of the tokens and cost per run, day and month. The run history shows each run's journals with tokens and cost and opens them in the viewer; scheduled AI Swarm jobs record one journal per server as well. Administrators can forbid automation journals or cap their retention, disk space and number of runs. See [Session journal per run](../features/jobscheduler.md#session-journal-per-run).
- **Screenshots of jobs from an invisible virtual terminal** — COMMAND and snippet jobs with a session journal can run in a pseudo terminal that korTTY renders without any window: screenshots at an interval, when the screen changes and at the end land in the run's journal, and a runtime limit stops monitors such as `top` with Ctrl+C. Progress bars and AI coding tools in non-interactive mode become visible without disturbing the terminals you are working in. See [Virtual terminal and screenshots](../features/jobscheduler.md#virtual-terminal-and-screenshots).
- **Desktop and webhook notifications for job runs** — a JobScheduler run that fails or is blocked now shows a desktop notification titled *korTTY · Job* and the job's name, also while the JobScheduler window is closed. Its text only says how the run ended, its exit code and whether it was started manually or by its schedule, never the run's output or summary, and a job notifies at most once a minute. The new **Notifications** section of each job also notifies on recoveries or successes if you tick them, and sends runs to webhook targets you add with **Webhook targets...**: Slack, Microsoft Teams Workflows (Adaptive Card) or a generic JSON receiver, with **Send test** to check one. Webhook URLs are stored encrypted with the master password, must use `https://` (`http://` only for localhost) and never appear in the journal or the log; messages carry no output, the run's summary only if you opt in per target and then masked, and failed deliveries are retried up to 3 times and recorded in the journal. Administrators can forbid job webhooks with the policy feature `job-webhooks` and limit their hosts with `webhook-host-allowlist`. See [Run notifications](../features/jobscheduler.md#run-notifications).

### Security

- **Enterprise policy for the new terminal features** — administrators can now manage paste protection, OSC 52, multi-exec and session restore from `kortty-policy.toml`. `paste-warning` in `[rule.terminal]` sets the least a paste warning asks, on top of *Settings → Terminal*, a connection's own warning and teamwork connections; `allow-osc52-clipboard-write = false` in `[rule.security]` keeps programs from putting text on the clipboard; `multi-exec = "deny"` in `[rule.features]` locks every way into multi-exec and broadcast mode while **Stop Multi-exec** keeps working; `session-restore` in `[rule.terminal]` sets and locks what korTTY does at startup with the previous session; and `session-restore-output` in `[rule.terminal]` sets and locks whether the output of each terminal pane is restored with it. Managed settings carry the "Managed by your organization" hint (the paste warning still offers stricter choices), and the fail-safe lockdown of a broken policy file now asks before every multi-line paste, forbids OSC 52 and multi-exec, reopens nothing at startup and saves no terminal output for it. See [Policy configuration](../reference/enterprise-policy.md).
- **Links in terminal output can no longer start local programs** — a program or server could print an OSC 8 link (the kind `ls --hyperlink` prints) with a `file:` target, and a single click opened that file with its associated application, which runs scripts and programs, on Windows even from a network share. korTTY now opens only `http`, `https`, `ftp`, `ftps` and `mailto` links, in your browser or mail program. `file:`, `news:` and every other link stays plain text, and so does a link with control characters, invisible bidi characters or more than 8 KB. A mail link may only fill in recipients, subject, body and in-reply-to, because some mail programs attach the local file an `attach` field names. See [Links in terminal output](../features/terminal.md#links-in-terminal-output).
- **Server output can no longer start an AI agent run** — korTTY reacted to an escape sequence (`ESC ] 777 ; korTTY-agent`) anywhere in the output of an SSH session, such as a file shown with `cat`, a login banner or anything a compromised server sends. It opened the AI agent run dialog filled in with a prompt and inline options such as `root=true` chosen by the server, or started the run right away when the per-run setup dialog was turned off, and the same sequence moved the working directory korTTY tracks for the session. korTTY now ignores these sequences, so an agent command in the terminal starts a run only when you type or paste it. Prompt detection through OSC 133 markers and directory tracking through the shell's OSC 7 reports are unchanged. See [Terminal agent shortcut commands](../features/ai-assistant.md#terminal-agent-shortcut-commands).
- **An overlong escape sequence in terminal output can no longer close the tab** — an escape sequence padded with more than about a thousand characters that the terminal cannot place in it, or with one such character and hundreds of parameters, crashed the terminal emulator, which ended the session and closed its pane or tab. A malicious server, a file shown with `cat` or a line in a log was enough. korTTY now drops what does not fit, as xterm does with too many parameters, and goes on showing the output that follows; escape sequences of normal length are read exactly as before.
- **Unlock the vault after startup** — with *Require master password on startup* turned off, korTTY started with the vault locked and offered no way to enter the master password later. *Configuration → Security → Unlock Vault…* now opens the vault mid-session, and the "vault locked" messages for saving keys and passwords, AI Swarm, guide questions and workflow scripts have an **Unlock Vault…** button that continues the action once the vault is open. Temporary SSH keys that a locked start could not decrypt are restored on unlock instead of being lost on the next save. See [Unlocking the vault later](../features/security.md#unlocking-the-vault-later).
- **Renamed and deleted folders no longer leave host-key verification switched off** — turning off host-key verification for a folder in the Connection Manager stored the folder's name, and renaming or deleting the folder left that entry behind, so a new folder that later reused the name, or a folder renamed to it, silently connected without verifying host keys. Renaming a folder now moves the setting, and that of its subfolders, to the new name, deleting a folder removes it, and when a rename merges two folders verification stays off only if it was off in both. See [Relaxing host-key verification](../features/security.md#relaxing-host-key-verification).

### Connections

- **A connection's own terminal settings take effect** — the font, colors and other values on the connection editor's *Terminal Settings* tab were stored but never used, because saving them did not switch the connection away from the global settings, so its tabs always looked like every other tab; changing the look in Quick Connect had the same problem. The tab now starts with a clear choice between **Use the global terminal settings** and **Own settings for this connection**; own settings apply to the connection's open, new and reconnected tabs when you save, and start from the values that applied until then. In Quick Connect, changing the terminal appearance now takes effect for that session. Existing connections, imports and teamwork connections from earlier versions keep using the global settings until you choose own settings for them, so values stored back then do not suddenly change how they look. See [Own terminal settings](../features/connections.md#own-terminal-settings).
- **Password targets behind a password jump server now connect** — the terminal handed the master password only to targets that log in with an SSH key, and the SFTP tab not even to a temporary key, so a password or keyboard-interactive target failed on the jump server's stored password with "vault is locked" although the vault was open — and korTTY kept repeating that failed attempt through the whole retry count. The jump password now works whatever the target's authentication. Failures that another attempt cannot fix — a jump password that is missing, locked in the vault or cannot be decrypted, an incomplete jump setup, a rejected jump-server host key, an SSH key file that is missing or cannot be read — are reported once and no longer retried or reconnected automatically, and with a locked vault korTTY no longer contacts the jump server at all. See [When the jump server cannot be used](../features/jump-server.md#when-the-jump-server-cannot-be-used).
- **Saved local shells keep their shell in Quick Connect and through export and import** — picking a saved Local Shell connection in Quick Connect left its shell, custom command and start directory out of the form and started the platform's default shell instead, for example zsh instead of the saved fish, and importing a korTTY export turned Local Shell and Mosh connections into SSH connections and dropped the shell. Quick Connect now shows the saved shell and start directory and starts that shell, including a command the shell list cannot show, such as `wsl.exe -d Ubuntu`, unless you pick another one; an import keeps the protocol, the shell command and the start directory. See [Local Shell](../features/connections.md#local-shell).
- **Tool windows open large enough to read their labels** — right after a fresh install, and after a change of the UI font scale, no window size is remembered yet, so the Connection Manager, the AI Manager and the *Tools* windows opened at a fixed size that cut longer labels short, especially in German ("Profilna…", "Zeitlimi…"). A window without a remembered size now grows before it appears until every label, button and check box shows its full text, up to almost the whole screen; the Connection Manager's buttons take the width of the longest label, and the AI Manager keeps its field labels at full width on small screens. A dialog designed taller than the screen, such as the connection editor on a laptop, is held to the screen height with its tabs scrolling, so its Save and Cancel buttons stay reachable; a remembered window that would reach below the screen edge is moved up and shortened to fit. A remembered window that is narrower than its labels need, such as a connection editor stored at an earlier release's width, is widened once when it opens. The check covers every tab of a window, not only the one that opens first; the button rows on the AI Manager's *Local Models*, *Knowledge Stores* and *AI Skills* tabs wrap onto a second line in a narrow window, and the explanations on those tabs keep all their lines. A size you chose yourself is otherwise restored unchanged.
- **Arrow buttons step through the connection editor's tabs** — the connection editor has grown to eight tabs, more than fit in one row of a narrow window. Besides the menu at the end of the tab bar, a row above the tabs now has arrow buttons for the previous and the next tab and a counter such as *3 / 8*; ++ctrl+tab++, ++ctrl+shift+tab++, ++ctrl+page-down++ and ++ctrl+page-up++ switch tabs from anywhere in the dialog, also from a field. See [Creating / editing a connection](../features/connections.md#creating-editing-a-connection).
- **No more error beep when the connection editor closes** — on macOS, closing the connection editor with **Save** or **Cancel** made the system's error sound. The Connection Manager opened the editor, and its other dialogs, as children of the main window, which the manager itself still blocks while it is open; closing the editor handed the focus to that blocked window. They now belong to the Connection Manager. Saving was never affected: the connection was stored either way.

### SFTP file manager

- **Edit server files in your own editor** — **Edit in External Editor** in the SFTP Manager downloads a server file into a private temporary folder, opens it in your text editor (set one under *Settings → SFTP Manager → External editor*, such as `code --wait {file}`, or use the system's text editor) and uploads every save automatically, keeping the file's permissions and owner. A **Remote edits** list shows each file with its last upload, **Upload now** and **Stop**; when the file was changed on the server meanwhile, korTTY asks before overwriting it. The editor is never started through a shell, file names are cleaned up, and the local copy is deleted when you stop, close the tab or quit. See [Editing in your own editor](../features/sftp.md#editing-in-your-own-editor).
- **Edit server files as root** — **Open With → Edit as Root (sudo)...** in the SFTP Manager opens a root-only file such as one under `/etc` in your own editor and writes every save back through sudo. Saves go to a staging folder owned by root, are checked by size and SHA-256 and only then written into the file in place, so it keeps its owner, permissions and labels and is never left half written. korTTY tries sudo without a password first, then asks in a masked dialog (or uses the JobScheduler's saved sudo password once you allow that for the server); the password is wiped when you stop and never reaches a command line or a log. Symbolic links are shown and confirmed first, the row in **Remote edits** carries a **sudo** badge, and the new policy key `sftp-sudo-edit` can switch it off. See [Editing as root](../features/sftp.md#editing-as-root).
- **The SFTP Manager follows the snippet editor policy** — the enterprise policy's `load-into-snippet-editor` key restricted only files opened from the terminal; the SFTP Manager's **Edit in Snippet Editor** ignored it and could write back to the server. Now `read-only` opens server files without **Overwrite file** and **Save as...**, and `deny` disables **Edit in Snippet Editor** and **Open image** for server files; local files are not affected. See [Editing files with Snippet Editor](../features/sftp.md#editing-files-with-snippet-editor).
- **Extract archives on the server** — **Extract Here...** in the SFTP Manager's remote context menu unpacks a ZIP, tar (also `.tar.gz`, `.tar.bz2`, `.tar.xz`) or 7z archive on the server into a new folder next to it, without downloading it; a taken folder name gets ` (1)`, ` (2)` and so on, so nothing is ever overwritten. The archive is checked before anything is written and refused when an entry would land outside the new folder; it is unpacked into a private staging folder, every symbolic link is checked again, and a failure or **Cancel** removes the partial result. Password-protected archives are refused, and a missing `unzip`, `tar` or `7z` is named in the error. See [Extracting archives on the server](../features/sftp.md#extracting-archives-on-the-server).
- **Search subfolders on the server** — the SFTP Manager's search only filtered the folder shown. With **Include subfolders** checked, ++enter++ in the remote search field now searches that folder and everything below it on the server, with the same wildcards, up to 10 levels, 5000 results and 60 seconds. The results list each hit with its path below the folder and say when a limit stopped the search; double-clicking a hit opens its folder with the hit selected, **Back to folder** returns, and ++esc++ stops the search. korTTY uses `find` on the server when it can, with symbolic links never followed and, by default, without crossing into other mounted file systems, and otherwise walks the folders over SFTP. See [Searching subfolders on the server](../features/sftp.md#searching-subfolders-on-the-server).
- **Server archives no longer expose their password** — a password for a ZIP or 7z archive created on the server was passed to `zip` or `7z` on the command line, where every other user of that server could read it in the process list. These tools only take a password that way or from a terminal, so the archive dialog for server files no longer offers a password and explains why; archives created on your computer can still have one, and server archive commands now quote every path and treat a path starting with `-` as a file, never as an option.
- **Open SFTP Here on the terminal's own session** — the SFTP Manager always logged in again, with a second password or MFA prompt, a second jump-server hop and the CyberArk access reason asked again, and it started in the login folder for the tab's connection even when a split pane ran another one. *Connections → Open SFTP Here*, **Open SFTP here** in a terminal tab's and a pane's right-click menu, the command palette and *Connections → SFTP-Client...* with a terminal in front now open SFTP on the focused pane's own SSH session, as that pane's user, in the folder its shell is in. After `su` or a nested `ssh`, or with a shell startup command, it starts in the login folder and says why. Each pane gets its own tab, closing it never closes the terminal, Reconnect uses the pane's session again or offers a separate login, and a server that refuses SFTP on the terminal's session gets a tab with its own login as before. See [Opening from a terminal tab](../features/sftp.md#opening-from-a-terminal-tab).
- **A remote files sidebar that follows the shell** — seeing the files of the folder you had just `cd`'d into meant opening the SFTP Manager and browsing there by hand. *View → Remote Files Sidebar* now docks a file list beside the panes of every terminal tab (off by default, right or left, width remembered) that lists the folder the focused SSH pane's shell is in, over that pane's own session. It follows folders the shell reports at once and a typed `cd` only after the next prompt shows the session's own user, pauses with a banner while another user or host is active, can be pinned, and only browses — it never types into the terminal. Uploads, downloads and drops go through the transfer list after a confirmation that names the server folder, and are greyed out up front when your organization switches file transfer off. See [Remote files sidebar](../features/terminal.md#remote-files-sidebar).
- **Uploads and downloads ask before they replace a file** — the SFTP Manager replaced a file of the same name on the server or on your computer without a word. It now shows **File already exists** with the size and time of both files and offers **Replace**, **Skip**, **Keep both** (a numbered name such as `report (1).txt`) and **Cancel transfer**, with one answer for all remaining conflicts of the same kind; a symbolic link is never replaced, and a folder still merges into a folder of the same name.
- **A transfer list with progress, Cancel, Retry and resume** — uploads and downloads in the SFTP Manager ran one file after another without progress, could not be stopped, and opened one error dialog per failed file. They now run up to three at a time in a **Transfers** list at the bottom of the tab with progress, speed and time left per file or folder, **Cancel**, **Retry**, **Cancel all** and **Clear finished**; failures become red rows plus one summary at the end. Files are written as `name.kortty-part` and renamed when complete, and **Retry** after a failure or a lost connection continues an interrupted file where it stopped. See [Transfer list](../features/sftp.md#transfer-list).
- **SFTP tabs ask before they close under running transfers** — closing an SFTP Manager tab, its window or korTTY while files were still transferring stopped them without a word, and an idle tab with auto-close could close itself during a long transfer. Every close path now asks **Cancel *n* running transfers and close?** with **Keep tab open** as the default, and auto-close waits until the transfers are done. A drag to the desktop whose download runs out of time now stops in the middle of the file instead of finishing it in the background. See [Transfer list](../features/sftp.md#transfer-list).
- **Transfer settings for the SFTP Manager** — *Settings → SFTP Manager → Transfers* now sets how many files are copied at once (1 to 8, default 3), whether an existing target is asked about, skipped or overwritten, whether interrupted transfers resume from their partial file (on by default) and whether a cancelled transfer keeps its partial file for later. See [SFTP Manager settings](../reference/settings/sftp.md#transfers).
- **Organizations can switch file transfer off** — the new `file-transfer` policy key refuses uploads, downloads, drops and dragging files out of the SFTP Manager, rejects files dragged onto a terminal pane while you drag, greys out the Snippet Manager's copy-to-terminal items for SSH tabs, and fails the JobScheduler's SFTP upload, download and sync jobs and its rsync jobs before they connect, while browsing and remote-only operations keep working; `[rule.sftp]` caps the parallel transfers and sets and locks the answer to existing files. See [Policy configuration](../reference/enterprise-policy.md#rulesftp).
- **Downloads cannot write outside the target folder on Windows** — a server file named after a Windows device such as `CON`, `NUL` or `COM1` (also with an extension, as in `nul.txt`), or a name ending in a dot or a space or containing `:`, was handed to Windows as is, which writes such names to a device or to a different file. - **Flow diagrams of long scripts are less generic and generate much faster** — the diagram request never told the model the node limit that the validator enforced, so for a script of several thousand lines the model transcribed the whole script into hundreds of nodes, spent minutes doing it, and was rejected. The limit is now part of the request and grows with the script — 12 action/decision nodes for snippets up to 200 lines, up to 24 at 1,000 lines or more — and the built-in flowchart skill asks for the main phases of a long script rather than every branch. A script longer than 400 lines is also sent as a condensed structural outline — its definitions and top-level flow, with elided runs marked and the original line numbers kept — instead of every single line, which cuts the request size several-fold and lets the model describe phases instead of statements. See [Mermaid diagrams](../features/snippets.md#mermaid-diagrams).
- **Flow diagrams now accept the Mermaid that models actually write** — tested live against MiniMax-M3, korTTY's diagram grammar rejected one answer in three for shorthand the contract never allowed but every model uses: nodes declared inline in an edge, chained edges, `-- yes -->` labels, the `:::class` shorthand, unquoted labels, other node shapes, and the model's own slips (a label pipe typed as a bracket, a shape closed early, a decision drawn as a diamond with one exit, a mistyped id left dangling, `File::Glob` in a label tripping the URL screen). The grammar now reads all of these and rewrites an accepted diagram into its strict dialect before rendering or saving, the validator tolerates a modest overshoot of the stated node limit instead of discarding a summarized diagram, the contract shows the edge-label syntax instead of describing it, and only what cannot be drawn faithfully — parallel branches from one action — is still rejected, with the reason named. A `start_1` the model declared but never connected is wired to the flow's real entry, statements written with a stray `class ` prefix are still read, and a repaired diagram that kept fewer than half of the drawn nodes is refused rather than shown as a stub.
- **A rejected AI flow diagram now says so** — when korTTY discarded an AI-generated flowchart, the [Full code analysis](../features/snippets.md#ai-code-actions) window silently showed the generic local fallback diagram instead, so a long script always seemed to produce a trivial five-node chart. The fallback now carries a notice naming the rejection reason, the same reason appears in the editor's status line and in the log together with the diagram's node and edge counts, and a diagram whose nodes lack a valid source mapping is kept (those nodes merely lose their hover reference) instead of being replaced by the fallback. Acceptance is logged only after the last gate, so a diagram the strict-dialect repairs then hollow out no longer appears as accepted and rejected one millisecond apart, and the rejected answer itself is kept under `ai-answers/` for diagnosis.
- **Sequence, state, class and ER diagrams now scale with the window** — Mermaid puts an inline `max-width` on the root SVG of every family whose `useMaxWidth` option is on, which is all of them except the flowchart korTTY configures explicitly, and that cap outranked the viewer's own sizing: those four stayed at their natural size however large the window grew, while the zoom label climbed to 311%. The inline size declarations are now stripped before the width and height are written from the viewBox, so how large a diagram is drawn is the container's business alone — for the families korTTY may render later as well.
- **A zoom slider for the diagram** — the diagram toolbar's **−** / **+** / **Fit** buttons now have a slider between them that sets the scale directly. Its track runs in powers of two, so the fitted size sits in the middle and one step to either side halves or doubles it, instead of a linear track that would leave the fitted size at a fifth of the way. The buttons and the slider drive one value, so each follows the other, and **Fit** returns both to the middle. Because every zoom step redraws the whole diagram, a dragged slider redraws a few times a second and once more on the value it is released on, so a 4,000-line script's flowchart follows the drag smoothly. The zoom controls stay together as one group when the toolbar wraps.
- **The docked change preview keeps its size and place** — the preview docked beside a [Full code analysis](../features/snippets.md#ai-code-actions) opened at 1040×700 instead of its docked size, drifted to the screen edge when all three windows had to be tiled, and could show a blank band with its content covering only half the window. A freshly docked window now ignores the platform's late size reports for a second and re-asserts its placement, opens at its docked size, and checks that its content still covers it whenever the window, the scene or the content changes size.

### AI assistant

- **AI chat answers now display formatted Markdown** — headings, emphasis, lists, quotations, and inline code appear as a readable preview alongside the existing tables and code blocks. Long text wraps without a fixed-height inner scrollbar. The conversation follows new messages and delayed layout changes, pauses when you scroll up, and resumes when you return to the bottom.

## v2.12.0

### Session journal: complete under load, smaller on disk

- **A server flood can no longer punch holes into the journal** — when output arrived faster than the capture log could persist it, up to 10,000 queued lines were silently dropped with nothing in the journal to show for it. The capture now applies backpressure instead: the terminal may briefly slow down under an extreme flood, but every line lands in the log. The log writer also batches its disk writes, so it keeps up with far more output in the first place.
- **Repeated output lines are coalesced** — progress loops, `tail -f` repeats and similar floods are stored syslog-style: the first occurrence immediately, follow-ups as one entry with a repeat count. The [journal page](../features/session-journal.md#storage-and-formats) shows such a run compactly as `line ×12`; copying the log reproduces the original lines in full, and the AI summarizer sees the count instead of thousands of identical lines.
- **Rotated log parts are now zstd-compressed** — finished capture-log parts compress to `.zst` instead of `.gz`, which is both faster and noticeably smaller on repetitive terminal output. Journals recorded by earlier versions keep their `.gz` parts and open, export and redact exactly as before — even mixed within one journal.
- **Log rotation is configurable per connection** — the Journal tab gained **Maximum size per log part (MB)** (default 25) and **Maximum rotated log parts** (default 20). Previously both were fixed, and a long noisy session simply stopped recording output after 20 parts. An enterprise policy can cap the part count with the new `max-log-parts` key.

### Session journal: AI search and Q&A

- **Ask the AI about a recorded session** — the viewer's new [AI Q&A panel](../features/session-journal.md#asking-the-ai-about-a-journal) answers questions like *"Were screenshots taken that show errors from this script?"* from what the journal already collected (summaries, screenshot analyses, notes) — the raw capture log is never sent to a model. When a question needs hard evidence, the model names literal search strings, korTTY's own streaming search scans the log, and only match counts plus a few sample lines go back for the final answer. Answers cite their sources: clicking a source scrolls the timeline to the entry, clicking a log-evidence line opens the log panel scrolled to the very line. Follow-up questions continue the conversation, and **Save as note** appends a Q&A pair to the timeline.
- **One question across all journals** — the manager's new [AI search](../features/session-journal.md#ai-search-across-all-journals) answers questions like *"In which journals did result_complex.pl exit with an error?"*: a fast local ranking over the journals' collected entries picks the candidates, one AI request writes the summary and selects the relevant journals, and the exact hits are materialized by the internal search. The hit tree jumps straight to the entry or log line, already-opened hits stay marked across searches and restarts, the table shows a sorted **Hits** column with a row highlight instead of filtering, and **Selection only** restricts the scope. Without a reachable model the search degrades to the pure text search with a notice. Optional **Semantic journal search** adds embedding-based ranking when a local embedding model is configured in the knowledge stores.
- **Journals now carry AI keywords** — the closing session summary extracts up to twelve verbatim search terms (hostnames, script and file names, error classes) into the journal metadata; the manager's filter matches them and shows them as clickable **keyword chips** under the filter field.
- **Catch up summaries** — the journal options can now run the summarizer over closed journals that were never summarized, one by one behind a cancellable progress dialog.
- **The manager's content search reads logs streaming** — **Search contents** no longer decompresses whole capture logs into memory; parts are scanned line by line, so searching across many large journals stays lightweight.
- **New policy key `ai-ask`** — an organization can forbid the on-demand AI over journal content (Q&A panel and cross-journal AI search) while keeping AI summaries.

### Security

- **Removed `net.i2p.crypto:eddsa`, an abandoned dependency with an unpatched signature-malleability flaw** (CVE-2020-36843) — Ed25519 SSH host keys and key-based authentication are now served by BouncyCastle, already part of korTTY, with no user-visible change in behavior.
- **A failed connection to a host on your local network now explains itself** — since macOS 15, a missing Local Network permission makes any local connection fail exactly like a powered-off host (`No route to host`), with nothing pointing at the actual cause. korTTY now adds a hint naming the permission when the failure and the network shape match, without ruling out a genuine outage.

Two parts stay fixed at every setting: the macOS application menu, which the operating system draws, and the AI swarm status strip, whose labels are painted onto a canvas alongside hand-computed positions.

Clicking the percentage resets it to 100 %. The shortcuts ++cmd+plus++, ++cmd+minus++ and ++cmd+0++ do the same. The setting scales the whole page between 70 % and 250 %, applies to the AI search answers beside it, and survives both navigation and a restart. It is separate from the interface setting above, because the manual is a document you read at length, and the size that suits a dialog rarely suits a page of prose. See [Manual text size](../reference/settings/appearance.md#manual-text-size).
