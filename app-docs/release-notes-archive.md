# Release notes archive

Curated release notes for earlier versions, moved out of the guide.

The guide page `app-docs/site/docs/en/about/release-notes.md` deliberately carries only the
current release: it is translated into every language the guide ships in, so a growing
changelog there costs translation time and buries the notes that matter. When a release is
cut, the outgoing version's section moves here.

This file is not part of the documentation site — it is neither published nor translated.
Releases older than the ones below are recorded in `RELEASE_NOTES.adoc` next to this file, and
every version is also listed on the [GitHub releases page](https://github.com/chardonnay/korTTY/releases).

## v2.13.1

### AI assistant

- **[Full code analysis](../features/snippets.md#ai-code-actions) no longer fails on some local reasoning models** — when korTTY requests a strictly structured result from a local server, certain reasoning models return their complete answer in the reasoning channel and leave the actual reply empty. korTTY treated this as an empty reply and discarded a finished analysis after minutes of work. korTTY now detects such a reply and uses the analysis it already contains. Only if that text is unusable does it ask a second time, without the strict format. This was observed with the newer Qwen reasoning models in LM Studio, and it affected **Full code analysis** and **Apply selected** in the snippet editor. Models that return a normal reply are unaffected.

### Terminal

- **A split no longer asks again for the reason of the connection** — when a server wants a reason for the operation, as a CyberArk-style jump host does, every split of a tab opened that dialog again although the reason had been given when the tab was opened. korTTY now sends the answer already given in that tab. It is still sent rather than skipped, because a server that asks for a reason closes a session that answers with nothing. A split to a different server, or a server asking something else, is asked once as well, and a new tab always starts by asking. If the server refuses the reason, because a ticket number has expired in the meantime for example, korTTY drops it and asks again. See [Split-screen with broadcast](../features/terminal.md#split-operations).

## v2.13.0

### Connection loss and reconnect

- **A lost connection no longer closes the tab** — when an established SSH connection drops (network outage, VPN cut, server gone), the tab now stays open in a red `(DISCONNECT)` state with a red status bar showing when the connection was lost, instead of silently closing as if you had typed `exit`. Reconnect in place with a double-click on the bar or tab, or via **Reconnect** in the context menus; a normal remote logout still closes the tab as before.
- **Connection loss is detected within about ten seconds** — korTTY actively probes the server over the SSH connection (the same technique as OpenSSH's `ServerAliveInterval`) and treats two consecutive unanswered probes as a lost connection, instead of waiting minutes for a TCP timeout. The terminal cursor also stops blinking in a disconnected tab, so a dead session no longer looks alive.
- **Automatic reconnect** — a new **Settings → Terminal → Automatically reconnect lost connections** option (on by default) reconnects a lost tab on its own, with delays growing from 3 seconds up to one attempt per minute and a countdown in the red status bar. Permanent failures such as a wrong password, a changed host key, or a configuration refusal are never retried automatically, and while a session journal is deciding how to continue, the journal's own reconnect choice takes precedence. See [Terminal sessions → Connection loss](../features/terminal.md#connection-loss-and-automatic-reconnect).

### Privacy

- **Anonymous usage statistics are now pre-selected during first-run setup** — the checkbox next to the master-password setup ([Anonymous data for application optimization](../about/anonymous-data.md)) starts ticked, so sharing is the default and clearing it before you confirm is the opt-out. An organization policy that forbids telemetry locks the checkbox to the enforced state instead. What is collected is unchanged: voluntary, anonymous, EU servers, and changeable any time in **Settings → Privacy**.

### Appearance

- **A first installation now starts with [Match display resolution](../reference/settings/appearance.md#ui-font-size) on** — korTTY scales its UI font size to the screen from the very first launch instead of only after someone finds the setting. Updating an existing installation never changes it: whatever it had stays.

### Translation

- **Yandex Translate works again** — it still spoke the retired Translate API v1.5, whose credentials Yandex stopped accepting, so the provider was dead for anyone who selected it. It now calls Cloud Translate v2 with the current `Api-Key`/IAM-token authentication, batches requests to the API's limits, and no longer sends a leftover v1.5 API URL to a host that is gone. A rejected key's fragments, which Yandex echoes back inside its own error message, are now redacted before anything reaches a log file.
- **Microsoft Translator now reaches regional and custom-domain resources** — a new optional **Azure region** setting, shown only while Microsoft Translator is selected, is required by any Azure resource that is not global; such a resource previously could not be reached at all.
- **DeepL now recovers from a wrong Free/Pro host guess** — the key suffix korTTY uses to pick a host is only reliable for older Free keys; a 403 response now retries once against the other host instead of failing outright.

### Enterprise policy

- **Administrators can forbid AI web access** — a new [`[rule.ai-profiles] allow-internet`](../reference/enterprise-policy.md) key switches off every internet-access mode an AI profile can select (Tavily, Bright Data, Brave, SearXNG, LM Studio Toolpack). It is enforced at three levels rather than one: stored profile modes are reset whenever settings are loaded or saved, the dropdown is locked in the AI Manager and in **Settings → AI**, and korTTY refuses to build a service for a profile whose mode is still enabled — so neither a hand-edited `global-settings.xml` nor the window between two clamps re-opens web access. Cloud profiles still reach their own provider; deny the `ai` feature for that.

## v2.12.0

### Session journal: complete under load, smaller on disk

- **A server flood can no longer punch holes into the journal** — when output arrived faster than the capture log could persist it, up to 10,000 queued lines were silently dropped with nothing in the journal to show for it. The capture now applies backpressure instead: the terminal may briefly slow down under an extreme flood, but every line lands in the log. The log writer also batches its disk writes, so it keeps up with far more output in the first place.
- **Repeated output lines are coalesced** — progress loops, `tail -f` repeats and similar floods are stored syslog-style: the first occurrence immediately, follow-ups as one entry with a repeat count. The [journal page](../features/session-journal.md#storage-and-formats) shows such a run compactly as `line ×12`; copying the log reproduces the original lines in full, and the AI summarizer sees the count instead of thousands of identical lines.
- **Rotated log parts are now zstd-compressed** — finished capture-log parts compress to `.zst` instead of `.gz`, which is both faster and noticeably smaller on repetitive terminal output. Journals recorded by earlier versions keep their `.gz` parts and open, export and redact exactly as before — even mixed within one journal.
- **Log rotation is configurable per connection** — the Journal tab gained **Maximum size per log part (MB)** (default 25) and **Maximum rotated log parts** (default 20). Previously both were fixed, and a long noisy session simply stopped recording output after 20 parts. An enterprise policy can cap the part count with the new `max-log-parts` key.

### Session journal: AI search and Q&A

- **Ask the AI about a recorded session** — the viewer's new [AI Q&A panel](../features/session-journal.md#asking-the-ai-about-a-journal) answers questions like *"Were screenshots taken that show errors from this script?"* from what the journal already collected (summaries, screenshot analyses, notes) — the raw capture log is never sent to a model. When a question needs hard evidence, the model names literal search strings, korTTY's own streaming search scans the log, and only match counts plus a few sample lines go back for the final answer. Answers cite their sources: clicking a source scrolls the timeline to the entry, clicking a log-evidence line opens the log panel scrolled to the very line. Follow-up questions continue the conversation, and **Save as note** appends a Q&A pair to the timeline.
- **One question across all journals** — the manager's new [AI search](../features/session-journal.md#ai-search-across-all-journals) answers questions like *"In which journals did result_complex.pl exit with an error?"*: a fast local ranking over the journals' collected entries picks the candidates, one AI request writes the summary and selects the relevant journals, and the exact hits are materialized by the internal search. The hit tree jumps straight to the entry or log line, already-opened hits stay marked across searches and restarts, the table shows a sorted **Hits** column with a row highlight instead of filtering, and **Selection only** restricts the scope. Without a reachable model the search degrades to the pure text search with a notice. Optional **Semantic journal search** adds embedding-based ranking when a local embedding model is configured in the knowledge stores.
- **Journals now carry AI keywords** — the closing session summary extracts up to twelve verbatim search terms (hostnames, script and file names, error classes) into the journal metadata; the manager's filter matches them and shows them as clickable **keyword chips** under the filter field.
- **Catch up summaries** — the journal options can now run the summarizer over closed journals that were never summarized, one by one behind a cancellable progress dialog.
- **The manager's content search reads logs streaming** — **Search contents** no longer decompresses whole capture logs into memory; parts are scanned line by line, so searching across many large journals stays lightweight.
- **New policy key `ai-ask`** — an organization can forbid the on-demand AI over journal content (Q&A panel and cross-journal AI search) while keeping AI summaries.

### Security

- **Removed `net.i2p.crypto:eddsa`, an abandoned dependency with an unpatched signature-malleability flaw** (CVE-2020-36843) — Ed25519 SSH host keys and key-based authentication are now served by BouncyCastle, already part of korTTY, with no user-visible change in behavior.
- **A failed connection to a host on your local network now explains itself** — since macOS 15, a missing Local Network permission makes any local connection fail exactly like a powered-off host (`No route to host`), with nothing pointing at the actual cause. korTTY now adds a hint naming the permission when the failure and the network shape match, without ruling out a genuine outage.

## v2.11.0

### Terminal logging

- **Connection logging was rebuilt to actually be reliable** — [terminal logging](../features/terminal.md#terminal-logging) previously wrote every connection to one fixed path (so two connections open at once interleaved into the same file), had no compression, and rotated by *deleting* the file at the size limit. Files are now named `<date>-<time>-<server>_<number>`, a fresh one starts every day (optional) and whenever the size limit is hit, nothing is ever overwritten or deleted by rotation, and each closed file is gzip-compressed. Old archives are swept by the date encoded in their name once the retention period (default 30 days, `0` keeps everything) expires, and only korTTY's own log files are ever touched, so it is safe to point the setting at a folder used for other things too.
- **The terminal log is now redacted** — captured lines pass through the same redaction as the session journal before anything is written: the connection's own stored password and any replacement rules an organization's policy defines. Log files, and a log folder korTTY created itself, are set to owner-only permissions where the filesystem supports it.
- **Quick Connect gained a Terminal log section** — configuring logging in the Connection Manager and then connecting from Quick Connect with a different authentication method previously dropped the setting silently; Quick Connect now carries its own folder, format and compression controls and applies them to the session it opens.
- **Fixed: XML and JSON logs had two document roots and never parsed**, rotation wrote the closing footer twice, up to 10,000 queued lines from just before a disconnect could be silently dropped, and output was split on line endings in a way that destroyed indentation and turned every progress-bar frame into its own log entry. All four are fixed.

### Session journal: filtered export, named markers, page appearance and screenshot editing

- **Exports can now be narrowed down** — [Exporting only part of a journal](../features/session-journal.md#exporting-only-part-of-a-journal) accepts any number of time windows (an entry only needs to fall into one of them), a topic filter as literal text, a regular expression, or handed to the AI to select by meaning, and a marker filter (all entries, only marked ones, or specific markers). Times are parsed leniently (`8`, `0800`, `8.30` all work) and widened by an adjustable tolerance (± 5 minutes by default), so an approximate window still catches the entry that actually straddles it. A filtered HTML bundle is rebuilt rather than copied — trimmed capture log, only the referenced screenshots — so a shared export cannot leak the rest of the session; every filtered PDF, Markdown file and bundle carries a banner naming the range so nobody mistakes it for the complete journal.
- **Markers are no longer a fixed four-value list** — beyond the built-ins (None, Info, Important, Error) you can now define [custom markers](../features/session-journal.md#markers), give each one a name and colour, and map it to one of the built-ins for older journals and for the error/important counts. Optional rules apply a marker automatically as entries are captured, matching a literal term or a regular expression against the entry's title, summary, note and excerpts, with precedence **your own choice > a rule > the AI's suggestion** — a rule never overwrites a marker you set by hand.
- **The journal page has adjustable [appearance](../features/session-journal.md#appearance)** — a colour scheme (six fixed palettes, the page's automatic light/dark pair, or a scheme derived live from your terminal's own colours), a text font and a monospace font, chosen from a toolbar popover and remembered for every journal korTTY renders afterwards.
- **Screenshots can be [annotated](../features/session-journal.md#screenshot-notes-and-annotations)** — pen, box, an "Unreadable" tool that coarsens a region into blocks, and text labels, plus a note field, reachable by right-clicking a screenshot. Marks are stored as data and stay re-editable; the untouched capture is kept locally as `.orig.png` and is never included in an export. This obscures a value in the rendered page, it does not redact it — use Search & replace or a policy redaction rule to remove something from a journal for good.
- **Selecting a time range got easier** — inside korTTY the viewer's timeline can be switched into range-selection mode: click a first and a last entry to highlight the span between them and hand it straight to the export dialog, or collect several windows before exporting. The same selection is available from the edit-mode entry table via right-click.
- **You can edit a journal title directly on its page**, and a header button jumps from one marked entry to the next.
- **A lost connection no longer ends the journal** — when the connection drops or the server ends it (a `reboot`!) while a journal is running, the tab now [stays open](../features/session-journal.md#when-the-connection-ends) and a decision bar offers **Reconnect** — the journal continues in place, with a reconnect marker — or **End journal**, which writes the closing summary exactly like the stop button. Previously a cleanly ended connection closed the tab silently and took the running journal with it, without the closing summary.
- **Notes got a real editor** — the quick note was a one-line input; [writing a note](../features/session-journal.md#writing-notes) now happens in a resizable field of at least six lines, the same one the viewer's entry form and the screenshot editor use. Web addresses typed into a note become **clickable links** on the journal page and open in your system browser (only `http`/`https`, and only in text you wrote — AI summaries and terminal excerpts stay literal). A **Translate** button with a language drop-down hands the note to the model assigned to *Text and translation profile* in the AI manager and replaces it with the translation, with the original one undo away.

### AI screenshot analysis in journals

- **Journal screenshots are now searchable by their content** — when the journal's AI profile accepts images, every captured screenshot gets an [AI-written description and tags](../features/session-journal.md#ai-screenshot-analysis), shown to the right of the picture on the journal page. The tags are clickable chips that start a journal search, and description and tags are covered by the manager's content search, by Search & replace and the policy redaction rules, and by the Markdown and PDF exports. Right-clicking a screenshot offers **Analyze screenshot with AI** for journals recorded earlier, for retries, and for re-running the analysis after annotating — the analysis always reads the annotated picture, never the untouched `.orig.png`. The automatic run on capture can be switched off in the journal options, and an organization can force the analysis on or off via the `ai-screenshot-analysis` policy key (off also disables the manual run).
- **AI profiles know whether their model accepts images** — a new [Image input (vision)](../reference/settings/ai.md#image-input-vision) setting per profile defaults to automatic detection: LM Studio model metadata is authoritative (read during the reasoning refresh), the Anthropic endpoint always qualifies, and other endpoints are recognized by well-known vision model names, with an Enabled/Disabled override for models the detection misjudges. LM Studio vision models (`vlm`) now also appear in the model dropdown, which previously hid them.

### Live journal side panel

- **A running journal can now be watched — and worked with — in real time** — **View → Live Journal** (++ctrl+alt+l++) docks the [live journal panel](../features/session-journal.md#the-live-journal-panel) to the left or right of the terminal. It shows the journal's **full page**, the same one the viewer renders: the timeline with AI summaries, notes and screenshots, plus an on-demand **Live Log** view streaming the capture log as it is written — output lines, your typed commands, notes and screenshot markers. New timeline cards and edits appear moments after they happen without losing your scroll position; the live log starts hidden, a header button shows or hides it, its height is drag-adjustable and remembered, scrolling it up pauses following and scrolling back down resumes it, and a header menu switches the page between light and dark. Terminal AI-agent replies are captured into the journal's log, and every agent run writes its own **AI agent** timeline card — prompt as title, final answer as body, plus model, duration and token count — the moment it completes; long answers collapse to a click-to-expand preview. The timeline cards adapt to the panel width instead of clipping their text, the panel can be dragged considerably wider than before, and the page header's **◷** button jumps the timeline to a typed time (`19:00`, `1900` or `13.08. 19:00` all work).

- **Fixed: the window size was not always remembered** — the geometry was only written when the window closed through its own handler, so quitting by a route that bypasses it lost the size and position you had just set. korTTY now records them shortly after you stop resizing or moving the window (never while minimized or in fullscreen, so the normal geometry survives those states). Because it is the real page, its actions work right in the panel: right-click a screenshot to annotate it (the edited picture appears on save), pick markers, search, and open entry log excerpts; the header adds **Note**, **Screenshot** and **Open Viewer**. The panel shows the journal of the current tab and only switches on a tab change when the new tab also has a running journal — otherwise it keeps the journal it shows, and a stopped journal or closed tab leaves the page in place with a badge. Side and width are remembered across restarts. Everything shown has already passed the journal's password protection, so suppressed input and redacted secrets never appear.

- **The interface font size can now be set, and optionally follows the display** — a high-resolution monitor left korTTY's own text, the menu bar most of all, uncomfortably small, because every size in the interface was fixed in pixels. [UI font size](../reference/settings/appearance.md#ui-font-size) on the Appearance tab now scales the whole interface between 80 % and 160 %: the menu bar and its dropdowns, dialogs, labels, buttons, tab titles, the dashboard, the file browser and the status bar. It applies the moment you save, to windows that are already open as well as new ones, and the main window's first-launch size and any remembered dialog sizes are re-measured to match. **Match display resolution** derives the value from the primary display's logical resolution instead, which leaves a Retina panel at 100 % — macOS has already scaled it — and raises a 4K display running at 100 % operating-system scaling to 125 %. Surfaces that already have their own size control are deliberately left alone, so nothing gains two competing settings: terminal sessions keep the Font tab and the zoom shortcuts, the editor keeps the Editor tab, and the AI chat, plan and activity panels keep their `A-` / `A+` buttons. Two parts stay fixed at every setting: the macOS application menu, which the operating system draws, and the AI swarm status strip, whose labels are painted onto a canvas alongside hand-computed positions.

- **The manual has its own text size** — the manual window (**Help → Manual**, ++f1++) now has three buttons at its top left: `A-`, the current percentage, and `A+`. Clicking the percentage resets it to 100 %. The shortcuts ++cmd+plus++, ++cmd+minus++ and ++cmd+0++ do the same. The setting scales the whole page between 70 % and 250 %, applies to the AI search answers beside it, and survives both navigation and a restart. It is separate from the interface setting above, because the manual is a document you read at length, and the size that suits a dialog rarely suits a page of prose. See [Manual text size](../reference/settings/appearance.md#manual-text-size).

### Snippet editor

- **The change preview can be read one finding at a time** — a **Highlight** picker below the diff narrows the review to a single improvement or hardening id (`SEC-1`, `HARDENING-05`, …): only that finding's places keep their marker and get a coloured line background, every other changed block is muted to a neutral tint, the window scrolls to the first place, and the explanation cards below shrink to match. **◀** / **▶** beside the picker walk the list one finding at a time, wrapping at the ends, so a report can be worked through without opening the dropdown for every step. *All changes* restores the full colouring. Muted blocks stay visible and keep their change markers, so this approval step never makes a real change invisible. The summary at the top now scrolls in its own pane above a draggable divider, so a staged apply's paragraph-per-stage summary no longer pushes the code out of view. The window also remembers the size and position you gave it, and the divider once you move it yourself.

- **Fixed incomplete Full code analysis replacements** — every **Apply selected** stage asks for one full rewritten script, explicitly requires every unchanged section to be copied, and refuses omission markers such as `rest unchanged` before another stage or the review window can use the result.
- **Fixed the snippet Text language scope** — every AI action that returns code now requires all existing and new comments, every displayed message, every log message, and every help message in that returned scope to use the selected language. A Full code analysis replacement applies the rule to the entire script while its report and diagram labels continue to follow the interface language.
- **Reduced Full code analysis prompt and skill bloat** — analysis and diagram requests now send one line-numbered script copy instead of repeating the same source as raw and numbered text. An explicit snippet-skill selection is used as an allowlist instead of being combined with another automatic relevance pass, and ordinary automatic matching keeps only its strongest candidates.
- **Optimized and hardened Mermaid diagram generation** — diagram-only requests no longer carry configurable coding Skills, knowledge-store excerpts, a linear example that could anchor the model, or repeated copies of the Mermaid contract. A compact immutable Mermaid action skill is now always included instead: it asks for grouped runtime behavior, localized **yes**/**no** branches and loop exits, connected start-to-stop paths and exact source ranges. Fresh AI results with disconnected nodes, backward terminal paths, incomplete decisions, more than 12 action/decision nodes or incomplete source mappings are rejected and use the local fallback without an AI retry, while safe stored diagrams remain backward-compatible; built-in interface languages also get a local edge-label check. When the `none` **Reasoning** value is available and the profile has a fixed model selection, korTTY automatically uses it for the diagram request without changing the saved profile. An Auto profile is not overridden from previously discovered capabilities because its loaded model can change; an explicitly configured `none` value still applies. OpenAI-compatible HTTP, LM Studio native, and embedded llama.cpp/MLX transports cap the response at 8,192 tokens, while Anthropic retains its separate provider cap. For embedded llama.cpp/MLX, korTTY does not repeat a response that is empty or contains only the model's reasoning; replacing or closing a pending diagram also cancels the superseded client request.
- **Added output limits for code replacements** — A finite output limit now applies to Full code analysis, security-fix, hardening and assistant replacements over OpenAI-compatible HTTP, LM Studio native, and embedded llama.cpp/MLX. It scales from 32,768 to 65,536 tokens with the source size; Anthropic retains its separate provider cap. When korTTY applies selected Full code analysis improvements or security fixes, it automatically requests `none` Reasoning only if that value is available and the profile has a fixed model selection. An Auto profile keeps its configured or provider-default Reasoning behavior unless `none` was explicitly configured. This prevents binary on/off reasoning models from spending the complete replacement budget before emitting the script. A provider-reported or malformed truncated response — including a reasoning-only answer with empty visible content — is recorded and rejected with the localized output-limit status and cannot change the editor or trigger an AI retry. Very large full-script replacements can therefore be refused rather than partially applied.
- **LM Studio reasoning-option detection was fixed** — **Refresh reasoning options** now prefers the model's exact native `allowed_options` metadata. A binary `off`/`on` model no longer shows the Minimal, Low, Medium, High, or Extra high levels as supported merely because LM Studio silently converts an unsupported value to `on`; an explicit `none` request switches this feature off, while omitting the parameter uses the published provider default. A model that publishes no reasoning capability at all — a coder model, or a virtual model whose configuration overrides reasoning metadata to false — now offers only **Disabled** instead of every level: LM Studio skips an unsupported request-time reasoning value with a log warning instead of rejecting the request, so the active probe mistook every level for supported and korTTY kept sending an explicit `off`. Levels detected by an earlier version are no longer trusted, since they may have come from that probe: HTTP and CLI profiles fall back to the conservative defaults for their model name until **Refresh reasoning options** is pressed once more, so an affected profile stops sending the parameter without anyone having to know about the button. Nothing is deleted from the settings file, and profiles using an integrated model keep their detected levels.
- **Fixed the Input hardening file-size guard** — generated scripts now use `MAX_FILE_SIZE`, check file metadata before reading any content, reject oversized files without reading them, and treat `0` as an unlimited size. The size field now accepts `0` accordingly.
- **Audited every Hardening and Input hardening option** — leaving a classic option unselected no longer lets the same behaviour return through unconditional language-specific defaults, and each input sub-option now names only its own checks, helpers and exit-code cases. Global hardening selected in **Improve robustness** or **Custom improvement** now rewrites the complete snippet so prologue and epilogue rules can actually be applied.
- **Stopped partial hardening in Full code analysis** — **Apply selected** assigns every selected classic and input-hardening rule a stable mandatory identifier, batches analysis items and dependencies into apply stages of at most three, processes the two hardening categories separately in batches of at most three mandatory requirements, and verifies the cumulative completed-identifier list without demanding one verbose change record per rule. Missing requirements reject the whole staged result, while explicit selected flags and guard literals such as `--dry-run`, `--yes`, `--help`, `--verbose`, `MAX_FILE_SIZE`, `FORCE`, `--force`, and `SECURITY:` must be present in the final script.
- **Made staged Apply selected requests survive a dropped connection** — a stage whose response stream is cut off mid-answer by the connection is now retried once automatically and reported as an interrupted connection, instead of aborting the whole apply and misreporting it as the output-token limit. Long-running chat requests (Full code analysis, security fixes, hardening, the assistant) now stream over OpenAI-compatible HTTP so a slow generation keeps bytes flowing and survives gateway idle timeouts; a MiniMax profile with reasoning turned off now also disables MiniMax's own "thinking" budget instead of silently spending it anyway.
- **Fixed empty Full code analysis apply results from malformed local-model JSON** — each stage now returns the complete script as a structured array with one source line per entry instead of one escape-sensitive JSON string. OpenAI-compatible requests enforce that shape and a conservative minimum line count through a strict JSON response schema, dropping the schema only when the endpoint explicitly rejects structured output. The compatibility parser still preserves source escapes such as `\s` where possible.
- **Made Full code analysis apply progress visible and atomic** — the analysis report now stays open while a narrow AI-processing companion window docks beside it. Separate progress bars for improvements and code hardening, elapsed time and provider-reported cumulative token usage sit above a complete checklist. Improvement and dependency rows show their colour-coded category icon directly after the item ID rather than reserving a narrow right-hand column for category and severity text; hardening requirements rely on the **Code hardening** section heading. Checklist descriptions are capped at three lines with an ellipsis while the complete text remains visible in the adjacent analysis report. The active batch is visible, every completed item receives a green checkmark and a failed or retried step remains identifiable. Each stage builds on the previous full script, but intermediate results remain hidden and are never applied on their own. A stage gets at most one visible repair attempt after either a short non-truncated fragment or a complete response that omits a mandatory identifier or required literal. Requirement repair starts from the complete returned script and names the unresolved identifiers; a second failure reports those identifiers and discards the sequence. Exactly one final review preview opens only after cumulative validation succeeds.
- **A stage that undoes an earlier stage's hardening is now caught immediately** — every **Apply selected** stage rewrites the whole script, so a later stage could silently drop work an earlier one had already delivered (for example the `--help` handling of a selected rule). Only the final validation noticed, after every stage had run and with no way to resume. Each stage is now also checked against the literals of the rules earlier stages delivered, so the offending stage fails right away, gets its one repair attempt naming exactly what to restore, and the run stays resumable if that attempt does not fix it.
- **An interrupted Apply selected can now be resumed or partially applied** — when the staged run stops after at least one completed stage (an AI or connection failure, or the editor's cancel button), an **Apply interrupted** prompt offers three ways out: continue the remaining stages from the point of interruption while keeping the completed work, review the completed stages' combined rewrite in the usual before/after preview and apply it from there, or discard everything as before. Closing the analysis window or the snippet editor mid-run still discards silently, and a run that aborts before its first completed stage keeps the previous behavior.
- **Made unavailable input guards explicit** — Input hardening is now disabled, and yields no effective saved configuration, for YAML/YML/Ansible targets in workflow, swarm, improvement and Full code analysis dialogs instead of accepting a selection that would later be ignored.
- **Fixed an Auto AI Complete popup during Full code analysis** — starting the analysis now discards a pending completion timer and closes any visible ghost suggestion instead of allowing a stale completion popup to appear over the analysis flow.
- **Hardened the initial Full code analysis response** — OpenAI-compatible HTTP now constrains the report to a strict JSON schema with the fields `summary`, `dependencies` and `improvements`. korTTY retries once without the schema only when the endpoint explicitly rejects structured output. Malformed model output is rejected without a retry loop.
- **Moved the Full code analysis selection checkbox** — **Select all improvements** is now the first control at the far left of the analysis toolbar instead of being pushed to its right-hand control group, with extra spacing before the following **Profile:** indicator so the two groups remain visually distinct.

### Connections

- **Connections can now be tagged** — every saved connection takes one optional free-text [tag](../features/connections.md#tags) (`prod`, `staging`, a customer name…), set on the connection editor's *Connection* tab or in bulk via the Connection Manager's new **Assign Tag** / **Remove Tag** context-menu entries, which work on a multi-selection and on whole folders including their subfolders. ## v2.3.3

### Fixes

- **macOS: "Quit korTTY" actually quits the app** — on the packaged macOS app, a native quit (Cmd+Q, the app menu's **Quit korTTY**, the Dock's **Quit**, or logout) left korTTY running in the background, so the process had to be killed. - **Closing a local shell no longer freezes korTTY** — the PTY process is now destroyed before its streams are closed, releasing a terminal reader thread blocked in a pty `read()` instead of deadlocking the close on the JavaFX thread.
- **Correct wording for local shells when closing** — the close-confirmation no longer says "End SSH connection?" for a local shell, and the window-close prompt is now transport-neutral ("Active sessions").
- **No password prompt for local shells** — opening a local shell no longer shows an irrelevant password dialog (local shells use no authentication).
- **"Load as text file" works in local shells** — right-clicking a selected file name in a local-shell tab and choosing **Load as text file** no longer fails with "No active SSH connection is available". The file is read from the local filesystem — resolved against the working directory shown in the shell prompt when available, otherwise the directory the shell was started in — and opens in the snippet editor with **Overwrite local file** and **Save as...** just like the SSH/SFTP variant. The not-connected error message is now transport-neutral.
- **Local file overwrites are now atomic** — both "Overwrite local file" flows (local-shell **Load as text file** and the SFTP-manager local-file editor) used to truncate the target file in place, so a mid-write failure (disk full, process killed, power loss) could leave it truncated with no recovery. Overwrites now write to a sibling temp file and move it into place, preserve the original file's POSIX permissions, and write through symlinks to their real target instead of replacing the link itself.
- **Fixed the Monaco-based editors (snippet, file, AI, diff) opening to an empty pane in the packaged/notarized macOS app** — no caret, no typing, no paste. In the packaged app the WebView loaded its page from a `jar:` URL, and the page's Content-Security-Policy (`script-src 'self'`) then blocked the editor's own `monaco-host.js`/`.css`, because a `jar:`-origin document does not authorize its `jar:` siblings. The Monaco resources are now extracted to a temp directory and loaded from a `file:` URL, which the CSP allows. A failed editor load now also surfaces an error instead of a silently empty pane, and the editor bundle is additionally minified with a more generous boot budget.
