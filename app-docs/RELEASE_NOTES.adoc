= Release Notes

== v2.3.0

=== AI Swarm

* *AI Swarm tab* (*AI → AI Swarm...*, Ctrl+Alt+S / Cmd on macOS): Broadcast one AI-agent task to many servers at once; each server runs its own agent and the answers are combined into a single comparison table with one row per server and a literal *"Fehler"* column for deviations and errors.
* *Animated status strip*: One orb per agent above the conversation shows queued/running/awaiting-input/paused/done/failed/cancelled at a glance, flags _unusually long_ runs via an adaptive threshold (`max(60 s, 2 × median of finished agents)`), and clicking an orb jumps to the agent's row. The strip scales from 1 to 50+ servers.
* *Per-agent and swarm-wide run control*: Pause, resume, restart, and stop either a single agent (right-click its row) or the whole swarm (toolbar). Pausing is cooperative and stops the elapsed timers; restarts replace only that agent's answer.
* *Expandable live transcripts*: Left-click an agent row to watch its live command/output transcript inline while it runs.
* *Conversation copy & export*: Copy the whole swarm conversation to the clipboard or export it as plain text, Markdown, or PDF; saved swarm chats get their own *Swarm Chats* section in the AI Manager.
* *Readable result rows*: Clicking a row of the combined answer table opens it in a separate *Row details* window with A−/A+ font sizing and copy-to-clipboard.
* *Targets without open terminals*: Swarm runs (AI and script) now work on saved servers with no open terminal via background SSH sessions; no terminal tab is opened. Requires an unlocked master-password vault.
* *Run scripts without AI*: Execute a Snippet Manager script with parameters on all swarm targets in parallel (Base64-transferred, single confirmation), with live output per server and a per-server exit-code/output result table.
* *Schedule swarm runs*: A new JobScheduler action type *AI_SWARM* with *Swarm parallelism* (1–16) and *Swarm read-only* fields; the swarm tab's *Schedule…* button prefills a job from the current targets and prompt. Results go to the journal _and_ a saved swarm chat.
* *Visible composer and tab status dot*: The swarm input is a clearly framed three-line field, and the tab shows a colored activity dot (running / waiting for input / paused / finished — the green dot stays until the next run).
* *Multi-server workflow dialog reworked*: Syntax-highlighted script view, a visible working animation with live elapsed time and total duration, an additional-instructions field with a de-duplicated 10-entry history, and *Save to Snippets* with a fitting pre-filled script name.

The existing designs are unchanged.

* *Design preview moved below the controls*: The preview now lives in a fixed-size area, so switching designs (or back to `Default`, which has no preview) no longer draws the preview over the dropdown.

=== Local Shell Connections

* *Open the local machine's shell in a terminal tab (no network)*: A new *Local Shell* protocol spawns a local pseudo-terminal (PTY) via pty4j instead of connecting to a remote host. On Windows you can choose *PowerShell* (default) or *cmd.exe*; on macOS/Linux it defaults to your `$SHELL` (falling back to `/bin/zsh` or `/bin/bash`). A free-form *Custom command* field supports any executable with arguments (e.g. `pwsh.exe`, `wsl.exe -d Ubuntu`, Git Bash), and an optional start directory can be set. Local Shell is selectable in both Quick Connect and the Connection Manager; for these connections host/port/username/authentication are not required and are disabled in the dialogs.
* *Shared connector hooks*: The terminal recording/logging and AI input-interceptor/data-listener hooks were lifted from the SSH connector onto a shared `ObservableTtyConnector` interface, so terminal logging and recording also work for local shells.
* *Git Bash / Cygwin / WSL shell options*: On Windows, *Git Bash*, *Cygwin*, and *WSL* are offered as local-shell presets (in Quick Connect and the Connection Manager) — but each only when actually installed: Git Bash and Cygwin are detected via their usual install locations / `PATH`, and WSL is listed only when `wsl.exe` is present and at least one distribution is installed (checked once, with a short timeout). The local-shell command parser is now quote-aware, so shell paths containing spaces (like `"C:\Program Files\Git\bin\bash.exe"`) launch correctly.
* *AI Agent & Planning in local shells*: The agent's command-execution engine was decoupled from SSH behind an `AgentCommandRunner` abstraction with two backends — SSH (exec channel) and local (a fresh local process). The *AI Agent* and *AI Planning* now run in local shells on Windows, macOS, and Linux: commands execute in the connection's shell (PowerShell via `-EncodedCommand`, `cmd.exe`, or `$SHELL`), the environment probe and system prompt are platform-aware so the model generates native commands, and the existing approval flow applies. Limitations on local shells: no `sudo`/administrator elevation on Windows, and no live working-directory tracking (the agent uses the connection's start directory). The JobScheduler's headless AI-agent action stays SSH-only.

=== Terminal Usability

* *Ctrl + mouse wheel zoom*: Holding *Ctrl* (or *Cmd* on macOS) and scrolling the mouse wheel over the terminal now changes the font size — wheel up enlarges, wheel down shrinks — instead of scrolling the buffer. This complements the existing Alt+Plus / Alt+Minus / Alt+0 shortcuts.
* *Ctrl+D closes a local cmd.exe/PowerShell tab*: Those Windows shells do not exit on EOF, so Ctrl+D had no effect there. Ctrl+D now closes the tab for local cmd.exe/PowerShell sessions. For bash-family shells (Git Bash/Cygwin/WSL, macOS/Linux) and SSH, Ctrl+D keeps its normal EOF meaning (the shell exits on EOF and the local tab then auto-closes).

=== AI Chat & Agent

* *Images, diagrams, and math render in AI chats*: AI answers containing an SVG document, a base64 raster image (`data:image/png;base64,...` — PNG, JPEG, GIF, BMP), a `plantuml` code block, a `mermaid` code block, or LaTeX math (`latex`/`tex`/`math` code blocks and `$$...$$` in prose) are shown as images instead of raw markup, each with a *Show code / Show image* toggle and copy button. Mermaid and MathJax are bundled (no network); PlantUML uses the local toolchain (`java` + Graphviz `dot`); SVG output is sanitized and shown with JavaScript disabled.
* *Full model reasoning in agent thinking rows*: Expanding a 💭 row in the agent activity panel now shows the model's actual reasoning when the provider exposes it (Anthropic extended thinking per the profile's Reasoning effort, OpenAI-compatible `reasoning_content`, LM Studio reasoning output, `<think>` blocks from local CLI models), falling back to the decision summary otherwise.
* *Run log records the AI profile*: Every agent run starts with an `AI profile: <name> (<model>)` activity row.
* *Reload uses the currently active profile*: The activity panel's reload button re-runs the command with the profile that is active now, not the one the original run was started with.
* *Agent Ask includes the terminal selection*: Starting *AI → Ask AI Agent* from the right-click menu with text selected sends the selection as context, so the question is answered about the selected output or script.
* *Concrete models for cloud profiles*: The model selector is pre-filled with common model names for known cloud providers (offline, no API key needed), the refresh button merges the endpoint's live model list, clicking a model in the dropdown now reliably applies it, and the unusable *Auto* option is no longer offered for cloud endpoints (with a clearer error when no model is selected).

=== Guide AI Docs Search

* *Ask the manual in natural language*: The built-in guide (*Help → Manual*, F1) gets an *AI search* side panel — type a question in your language and get an answer generated exclusively from the bundled documentation, with clickable citations that jump the guide directly to the referenced page.
* *Uses your default AI profile; retrieval is fully offline*: No server, no extra API keys, no new dependencies. Retrieval runs locally over the bundled search index (with bilingual synonyms, German compound splitting and umlaut folding); off-topic questions are answered locally without contacting the AI endpoint at all.
* *Grounded answers*: The model is restricted to the retrieved excerpts, invented links are repaired or removed, and a native *Sources* list always shows the cited pages regardless of the model's answer.

=== Workflow Script Generator

* *Two new target languages*: The agent run → *Workflow* script generator can now produce *Windows-CMD* (`.cmd` batch, `@echo off` lead line, `REM` header comments, `errorlevel` checks) and *AppleScript* (`.applescript`, `osascript` shebang, `--` comments, `try/on error` handling) in addition to Bash, Python, Perl, Ruby, PowerShell, and Ansible.
* *Adjustable script font size*: Each generated-script editor now has *A-* / *A+* buttons and supports *Ctrl + mouse wheel* (Cmd on macOS) to change the font size; the chosen size is remembered across sessions.
* *Visible progress while a diagram is generated*: Generating a PlantUML diagram from a script now shows the working spinner (in addition to the "diagram is being generated" status), so it is clear the AI connection is actively working.
* *Clearer AI backend errors*: When the AI server runs out of memory / hits a resource limit (e.g. LM Studio/MLX "Resource limit exceeded", "metal::malloc"), the dialog shows a short, actionable hint instead of dumping the raw multi-line backend stack trace; all other AI errors are collapsed to a single line.

=== Fixes

* *Closing a local shell no longer freezes korTTY*: Closing a local-shell tab (or the window with a local shell open) could hang the whole app. `LocalShellTtyConnector.close()` now destroys the shell process before closing its streams, so a terminal reader thread blocked in a pty `read()` is released instead of deadlocking the close on the JavaFX thread.
* *Correct wording for local shells when closing*: The close-confirmation no longer says "End SSH connection?" for a local shell — it uses local-shell wording — and the window-close prompt is now transport-neutral ("Active sessions") since a window can mix SSH, Mosh and local-shell tabs.
* *No password prompt for local shells*: Opening a local shell no longer shows a password dialog. Local shells use no authentication, but the connection's default `PASSWORD` auth method previously triggered an irrelevant (and ignored) prompt in Quick Connect and the Connection Manager.

== v2.2.3

=== Critical Fix: Monaco Editors Failed to Load in the Packaged App

The Monaco-based editors (snippet, file, AI, diff) opened to an empty pane in the packaged/notarized macOS app — no caret, no typing, no paste. In the packaged app the WebView loaded its page from a `jar:` URL, and the page's Content-Security-Policy (`script-src 'self'`) then blocked the editor's own `monaco-host.js`/`.css` because a `jar:`-origin document does not authorize its `jar:` siblings. The Monaco resources are now extracted to a temp directory and loaded from a `file:` URL, which the CSP allows. A failed editor load now also surfaces an error instead of a silent empty pane, and the editor bundle is additionally minified (~27 MB → ~13 MB) with a more generous boot budget.

== v2.2.2

=== Critical Fix: Crash Opening Monaco Editors

* *Fixed a hard crash (no on-screen error) when opening the Snippet Manager, the Snippet editor, or the Settings AI-skill editor in the packaged builds*: the bundled runtime was missing the `jdk.jsobject` module, so `netscape.javascript.JSObject` was unavailable at runtime. When the embedded Monaco editor's WebView marshalled a JavaScript object back to Java, JavaFX WebKit's native class lookup returned `NULL` and the JVM crashed in JNI `get_method_id` (`SIGSEGV`). `jdk.jsobject` is now bundled in the packaged runtime, so the Monaco-based editors open correctly. This release supersedes v2.2.0 and v2.2.1, whose binaries are affected by this crash.

== v2.2.1

=== Stability Fixes

* *Settings / Snippet Manager crash fixed*: Opening *Global Settings* or the *Snippet Manager* could abort the app with no on-screen error. The embedded Monaco editor binds a JavaScript→Java bridge through `JSObject.setMember`, which JavaFX keeps only via a weak reference; under the bundled runtime's garbage collector the bridge could be collected while still in use, so the next JavaScript→Java callback dereferenced a freed object and the process crashed natively. The bridge is now held by a strong reference for the editor's lifetime (and made static with a weak back-reference so a closed dialog no longer pins the whole window graph).
* *WebView lifecycle hardening*: Monaco editors are now disposed when their dialog closes (Settings, Snippet editor) — the boot-retry timer is cancelled, the JavaScript bridge is detached, and the page is dropped — instead of leaking a WebView on every open, and late timer/load callbacks after close are ignored. The Settings *AI Skills* editor now loads lazily on first use instead of on every Settings open.

=== Master-Password Login Window

* *Cleaner branding*: Removed a stray watermark from the animated login logo.

== v2.2.0

=== Terminal Engine and Hyperlinks

* *SithTermFX 1.2.0*: Upgraded the embedded terminal engine to SithTermFX 1.2.0 (built from source, no GitHub token required).
* *OSC 8 clickable hyperlinks*: The terminal now supports OSC 8 explicit hyperlinks — clickable links emitted by programs such as `ls --hyperlink` or `eza`. === Mosh (mosh4j) 2.0.2 Upgrade and Security Hardening

* *mosh4j 2.0.0 → 2.0.2*: The dynamically loaded Mosh backend was upgraded to mosh4j `2.0.2`. The release JARs are bundled in native builds (no first-run download) and otherwise fetched on demand via the GitHub CLI (`gh`) or `KORTTY_MOSH4J_RELEASE_DIR`. No reconnect or protocol migration is required — the Mosh wire protocol is unchanged (still version `2`), so existing Mosh connections behave exactly as before.
* *Inherited security hardening*: mosh4j `2.0.2` adds per-direction replay/freshness protection, decompression-bomb limits on reassembled/zlib data, and a server-side protocol-version check. These harden the Mosh datagram path against malformed or replayed traffic.
* *Bouncy Castle `1.78.1 → 1.84`*: The Bouncy Castle provider was upgraded to `1.84` (fixes CVE-2026-5598, HIGH, and CVE-2026-0636, MODERATE). The bump was applied both to the mosh4j runtime classpath and to korTTY's own SSH crypto dependencies (`bcprov-jdk18on`, `bcpkix-jdk18on`), so no known-vulnerable provider remains on either path. SSH key compatibility and connector behavior were re-verified after the upgrade.
* *protobuf-java `4.28.2 → 4.35.1`*: mosh4j `2.0.2` compiles its generated Protobuf DTOs against protobuf-java `4.35.1` (they reference `com.google.protobuf.GeneratedFile`, which does not exist in `4.28.2`). The bundled/auto-downloaded protobuf dependency on the dynamically loaded Mosh classpath was bumped accordingly, fixing a `NoClassDefFoundError` that would otherwise occur on the first Mosh connect.
* *Release tag vs. artifact version*: Since mosh4j `2.0.1` the GitHub release tag carries a leading `v` (`v2.0.2`) while the artifact file names stay versioned `2.0.2`. korTTY now tracks the tag and the artifact version separately so release downloads, cache directories, and bundled layouts all resolve correctly.
* *Integration test*: A new self-skipping integration test verifies that the pinned mosh4j `2.0.2` artifacts still expose every constructor and method korTTY loads reflectively (`MoshKey.fromBase64`, `MoshClientSession`, `MoshTerminalFrontend`), guarding future mosh4j upgrades against silent API drift.

=== AI Agent Panel Placement and Status Indicators

* *Choose where the agent panel lives*: *View → AI Agent Panel* now offers *At Bottom* (default, unchanged), *Dock Left*, or *Dock Right*. Docked mode shows the activity panel as a resizable side panel attached to the main window, exactly like the local file browser. The chosen placement and side width are remembered across restarts.
* *One tab per terminal, runs stacked*: In side mode the dock shows one outer tab per terminal widget of the active terminal tab (e.g. a base terminal plus two splits = three tabs); within each tab the individual agent runs are listed stacked vertically.
* *Spotlight on the active tab*: Switching to another terminal tab swaps the dock to show only that tab's terminals; panels of other tabs are hidden until you switch back. Runs keep executing across the switch. Splitting/closing terminals updates the dock's tabs live.
* *Dashboard status badge*: Each connection in the Dashboard shows an AI-agent status icon — ✋ awaiting input, ⚡ working, ⏸ paused, ✓ finished — aggregated across that terminal's runs and refreshed about once a second.
* *Terminal tab status badge*: The same ✋/⚡/⏸/✓ indicator is prefixed to the terminal's tab title, so an agent's state is visible even without the Dashboard.

=== Terminal AI Agent Activity Panel and Concurrency

* *Multiple concurrent runs per split*: Terminal AI Agent activity panels now support multiple concurrent runs shown as closable tabs (one tab per run), with a per-widget concurrency cap of 5 runs. Finished runs remain as tabs until explicitly closed.
* *Typing unlocked during runs*: Normal terminal input is no longer locked while a run is active. You can continue typing and launch new `agent` commands concurrently; only run-control keys (*Esc*, *Ctrl+C*) and the toggle-thinking shortcut (*Ctrl+R*) are intercepted by the active run's tab.
* *Per-run pause and resume*: Each run tab can be paused (⏸) to park the agent at a safe point between steps, allowing already-running commands to finish first. Resume (▶) restarts the paused run. Paused time is excluded from the run's work-time accounting.
* *Activity row emoji indicators*: Activity rows now show static colored emoji icons chosen by the command action, replacing the old `↑` / `↓` / `?` / `!` / `x` / `i` markers. Icon set includes 💾 write/create file, 📖 read, ▶️ run/execute, 📁 directory, 📦 package, ⚙️ service, 🌐 network, 🔍 inspect, 💭 thinking, 💬 message, ✋ awaiting user input (sudo/approval), ❌ error/failed, 🚫 cancelled.
* *Collapsed status bar and input-required signaling*: When collapsed, the activity panel shows a compact status bar (run prompt + state + pause/cancel buttons + expand button). With multiple runs it surfaces the most relevant one (awaiting input first, otherwise an actively-working run) and shows a run breakdown such as "1 running · 2 done" instead of a bare total run count, plus a spinner while the agent is actively working. User-input requirements (sudo password or command approval) are clearly signaled with a bold ✋ "input required" indicator. The panel auto-expands and selects the requesting run when input is needed, and the tab displays a ✋ badge. The collapsed pause/cancel controls act on exactly the run shown in the bar.
* *Keep-collapsed preference*: A panel-level preference controls whether new runs start minimized to the status bar. This setting is remembered across sessions.
* *Run cancellation on tab/split close*: Closing a terminal tab or split discards and cancels all agent runs associated with that widget.
* *Agent final message in terminal*: The agent's final user-facing message now contains the actual answer or result (not just a meta summary) and is displayed in the terminal transcript.

=== Terminal Tab Completion and Agent Prompt History

* *Tab completion for agent commands*: At the shell prompt, typing the agent command name then pressing TAB offers completions for configured agent command variants (`agent` / `agent-ask` / `agent-plan`).
* *Recent prompt history on TAB*: After typing an agent command and a space, pressing TAB offers a history of recent agent prompts. Each row shows the prompt on the left and the date/time it was last run on the right, deduplicated by prompt text, newest first. The popup is user-resizable (drag the bottom-right grip), remembers its size across restarts, and scrolls when the history is long. Entries can be pruned in place — a per-row ✕ button (or *Del* on keyboards with a forward-delete key) removes one prompt, and *Clear all* (two-step confirm) wipes the whole history; deletions persist immediately.
* *Cleaner history capture*: Recorded prompts now come exclusively from the exact characters typed, so the history is never reconstructed from the wrapped terminal screen. This fixes long prompts being stored with stray mid-word spaces at line-wrap points (e.g. "nur" → "nu r", "ansible" → "ansibl e") and keeps shell tab-completion listings and "command not found" output out of the history; any such pre-existing junk entries are also filtered from the popup and can be removed with the per-row ✕ or *Clear all*.
* *Configurable history size*: *Settings → AI* now includes a setting for terminal-agent input-history size (default 20, range 5–100).

=== Automated Security Pipeline

* *Dependabot*: Weekly automated pull requests for outdated Gradle graph dependencies and GitHub Actions; SSH/crypto dependencies are grouped for joint review.
* *CodeQL static analysis*: Java source is scanned on every push to `main`, on every pull request, and weekly. Results appear under *Security → Code scanning* in the repository. Uses `build-mode: none` to avoid the heavy SithTermFX/mosh4j build during scans.
* *CodeRabbit AI review*: Every pull request — including Dependabot security updates — is reviewed by CodeRabbit with Gitleaks (committed-secret detection), Semgrep (SAST), and OSV Scanner (dependency vulnerability scan). Security-specific review instructions are applied to SSH/crypto code paths, `build.gradle.kts`, and workflow files.
* *Pinned-artifact freshness monitoring*: A weekly job compares URL-pinned artifacts that Dependabot cannot track (mosh4j, bundled BouncyCastle/protobuf, Node.js formatter runtime, Monaco Editor, SithTermFX) against their upstream latest versions and opens a tracking issue when any artifact is behind.
* *Automated security patch releases*: When a pull request labeled `security` is merged to `main`, the release pipeline automatically computes the next patch version and creates a GitHub Release, which triggers the existing multi-platform build and signing workflow.

=== Terminal Recording

* *Lightweight replay recording*: Terminal recording can be enabled for the current app session in the Video Manager or permanently in *Settings > Video*. SSH terminal tabs can then start/stop recording from the terminal bar, *Tools > Start/Stop Terminal Recording*, or *Ctrl/Cmd+Shift+E*. Recording stores screen-state replay events instead of continuous pixel capture.
* *One file per tab session*: Multiple start/stop segments in the same terminal tab append to one JDK/GZIP streaming-compressed `.korttyrec.jsonl.gz` file until the tab closes; existing `.korttyrec.jsonl` replay files remain readable.
* *Split-aware scope*: When a tab has split terminals, recording can target the active split or the whole tab.
* *Auto-pause*: Recording automatically pauses after the configured idle threshold when neither visible terminal output nor user input activity changes the terminal, and resumes on the next activity.
* *Video Manager*: *Tools > Video Manager...* enables terminal recording for the current app session, configures storage path, default format, default scope, optional color capture, auto-pause threshold, optional `ffmpeg` path, replay listing, in-app replay viewing, rename/delete actions, and video export.
* *Replay viewer controls*: In-app replay viewing includes a timeline slider, a time-jump field accepting minute and `MM:SS` input up to the replay duration, and playback speed from 1x to 20x.
* *Color and geometry metadata*: New replay screen events can store terminal geometry and optional per-cell color/style runs. Color capture is off by default to keep replay files small.
* *Export options and progress*: Video export shows an options dialog for full/custom time ranges, color inclusion, and open export format selection. The progress dialog shows the current export phase and an estimated remaining time while frames are rendered and `ffmpeg` encodes the video.
* *Optional WebM/MKV export*: Replay files can be exported to WebM/VP9 or MKV/FFV1 when `ffmpeg` is found on `PATH` or configured explicitly. The export uses replay timestamps instead of a fixed frame rate, uses recorded terminal geometry or a computed legacy fallback to avoid cropping, and renders frames with bounded CPU parallelism. If `ffmpeg` is missing, replay recording remains available and export is disabled.
* *No streaming*: Live/network streaming is intentionally not implemented.

=== SFTP, Local Files, and Terminal Emulation

* *Temporary SSH keys for SFTP*: SFTP openings that use a valid temporary SSH key now create an authentication-only connection copy, preserving the exact temporary key content without mutating the saved connection's configured authentication.
* *SFTP subsystem failure diagnostics*: SFTP startup now reports when the server or SSH proxy rejects/closes the SFTP subsystem after SSH authentication, including EOF, channel-closing, and `subsystem request failed` cases, and keeps generic SFTP startup causes visible.
* *SFTP file editing through Snippet Editor*: Local and remote SFTP panels now provide an *Edit* pulldown and an *Edit with Snippet Editor* context-menu action for exactly one selected file. File mode can overwrite the source file, save under another name, or save the current content as a Snippet Manager snippet while keeping the Snippet Editor toolbar available.
* *Dockable local file browser*: *View > File Browser* can show a local file browser on the left or right side of the main window with open, copy, cut, paste, delete, new file/folder, archive, details, hidden-file toggle, and owner/permission actions.
* *Per-connection terminal emulation*: Quick Connect and Connection Edit can store the selected SithTermFX terminal emulation, and SSH/native Mosh sessions use the selected `TERM` value instead of a fixed default.
* *Terminal drag-and-drop target handling*: Drag-and-drop uploads resolve `~` and `~/...` targets through the SFTP start directory, show the selected remote target, elapsed time, and current file during upload, and improve prompt-directory extraction for wrapped or decorated prompts.
* *Terminal-only fullscreen*: *F12* and *View > Terminal-only Fullscreen* hide menu/status chrome, dashboard, and the local file browser while keeping only the terminal visible, then restore the previous fullscreen and UI state when toggled off. *View > Hide terminal scrollbars in fullscreen* can also hide terminal scrollbars only while fullscreen mode is active.
* *Terminal color sequence control*: *Settings > Colors*, Quick Connect, and Connection Edit can disable ANSI/TrueColor terminal colors globally or per connection. When disabled, KorTTY ignores color SGR sequences from the remote process and uses the configured foreground/background colors.
* *Tab bar cleanup*: The tab bar no longer shows the separate `+` affordance; new tabs continue through *File > New Tab* or the existing keyboard shortcut.
* *AI profile model selection*: AI profile editors now use an editable model selector. Local LM Studio profiles can choose *Auto* or a loaded local LLM discovered through `GET /api/v1/models`; Auto resolves again immediately before connection tests, chat/follow-up requests, terminal AI actions, and agent runs. === JobScheduler Actions and Security

* *Command, snippet, and AI-agent jobs*: `COMMAND` jobs run non-interactive remote commands. `SNIPPET_SCRIPT` jobs run selected SnippetManager scripts with additional per-job parameters. `AI_AGENT` jobs use the shared AI-agent safety logic and require explicit job-level auto-approval before unattended command execution.
* *SFTP jobs*: Scheduler actions cover upload, download, sync, delete, rename, mkdir, chmod, chown, remote copy, and remote archive creation.
* *Archive jobs*: Scheduler archives support ZIP, password-protected ZIP, TAR, and TAR.BZ2, with optional download after successful creation.
* *Sudo handling*: Server-specific sudo passwords are used before group sudo passwords. Stored sudo secrets are encrypted with the master password.
* *SFTP sudo staging*: SFTP paths that need elevated rights can use temporary staging plus sudo-assisted `mv`, `cp`, `tar`, `chmod`, and `chown`, with cleanup failures journaled.
* *Host-key safety*: Host-key pinning is required by default for unattended SSH/SFTP/Rsync execution. A job can explicitly disable host-key verification, and that unsafe mode remains scoped to that job.
* *Journal modes*: `LIMITED_REDACTED` stores bounded stdout/stderr excerpts with redaction. `FULL` stores full output/transcripts while still redacting KorTTY-managed secrets before persistence.
* *Locked master-password behavior*: Jobs that need encrypted SSH, sudo, API, or archive secrets are blocked and journaled when the master password is locked.
* *Action-specific fields*: The *Action* tab now shows only fields used by the selected scheduler action, and `SNIPPET_SCRIPT` jobs include a search box for filtering large SnippetManager script lists.

=== JobScheduler Rsync Integration

* *New `RSYNC_SYNC` action*: Schedule upload or download directory synchronization between the local filesystem and saved SSH TCP connections.
* *Multiple sources*: One job can synchronize multiple source directories under the configured target root.
* *Safe defaults*: Rsync uses `-a --itemize-changes`; `--delete` is optional and disabled by default.
* *Group downloads*: Downloads from multiple targets write into separate per-target subdirectories below the local target root to avoid overwrites.
* *External tools*: KorTTY uses `rsync` from `PATH` or the optional *Settings > SFTP > JobScheduler Rsync* binary path. The local `ssh` command must be available in `PATH`.
* *Pinned known_hosts*: Rsync jobs create a temporary owner-only `known_hosts` file from the pinned host key. Existing pins without OpenSSH public-key material must be confirmed again before Rsync can run.
* *Askpass support*: Password and key-passphrase authentication use temporary owner-only `SSH_ASKPASS` helper files. Passwords, passphrases, helper paths, and secret-file paths are redacted before journaling.
* *Rsync sudo scope*: `Use sudo` for Rsync maps to passwordless remote `sudo -n rsync`; stored sudo passwords are not used by the current Rsync integration.
